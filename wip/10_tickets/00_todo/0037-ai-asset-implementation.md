# 0037 ヒアドキュメント本文を実行位置として数えない（0028 で踏んだ過剰拒否の是正）

## 目的

0036 の判定軸が cmdpos のプレースホルダ _ を「難読化」と一律に読むため、実行位置ですらないヒアドキュメント本文で拒否側に倒れる。0028 の実測で登録から 3 回目に踏んだ。0029 / 0030 で拒否側 4 本を足す前に塞ぐ

## DoD

- [ ] cmdpos が「潰れたクォート由来の _」と「ヒアドキュメント本文・コメント由来の _」を呼び手から区別できる。既存の CP_* の意味を変えず、新しい出力変数か既存の段の属性として足す（CP_DEGRADED / CP_OPAQUE の意味は変えない）（根拠: ）
- [ ] block-chmod の _bc_exe_unknown が、ヒアドキュメント本文・コメント由来の段を実行体の判定から外す。bash はヒアドキュメント本文を決して実行しないので、そこは実行位置ではない（根拠: ）
- [ ] 0028 で再現した 4 形（<<'PY' / <<PY / <<-PY / << PY）が、本文に禁止語を含んでいても ALLOW になる。直す前は 4 形とも DENY であることを先に確かめる（根拠: ）
- [ ] 取りこぼしを増やしていない。ヒアドキュメントの本文ではなく実行位置に禁止語がある形（cat <<PY 直後の行ではなく、ヒアドキュメントの後ろの段に chmod がある形）は DENY のまま。少なくとも 3 形の対照を BC-T01 に置く（根拠: ）
- [ ] 0028 の対照 5 形（禁止語 + クォート + 変数展開でヒアドキュメント無し）が ALLOW のままであることを BC-T02 で固定する（根拠: ）
- [ ] 拒否理由の文面が、過剰拒否を踏んだ読み手に何が起きたかを伝える。実行体を特定できないために倒したときは、何が判定を妨げたか（変数展開・バッククォート等）を添え、権限変更の案内だけを出さない（根拠: ）
- [ ] cmdpos のテスト（HK-T05 / HK-T12）に、ヒアドキュメントの 4 形が本文由来の印を持つことを固定するケースを足す（根拠: ）
- [ ] 足したテストが直す前は落ちることを 1 件ずつ確かめ、変異テストで検出力があることを確かめた。変異が 0 件だった行は「要らない」と即断せず、重ならない条件を探した（根拠: ）
- [ ] 全件テストが既定ロケールと LC_ALL=C.UTF-8 の両方で FAIL 0（根拠: ）
- [ ] 登録済みのフックとして実際に走らせ、0028 で踏んだのと同じ形（ヒアドキュメントで .py を書く操作）が通ることを実測した（根拠: ）

## 作業内容

- 先にテストを足して落ちることを確かめてから実装する（0036 と同じ順序）
- 過剰拒否と取りこぼしはトレードオフなので、両側のケースを同じ数だけ用意してから直す
- cmdpos は中核なので、CP_* の既存の意味を変えない。呼び手（block-chmod 以外の 10 本はまだ無い）に影響しない形で足す
- .claude/docs/** には書かない（実装フェーズの deny）。仕様の書き戻しは 0032 へ送る
