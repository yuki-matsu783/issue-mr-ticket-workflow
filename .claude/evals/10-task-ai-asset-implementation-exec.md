# 10-task-ai-asset-implementation-exec の eval 定義

## 目的

`10-task-ai-asset-implementation-exec` の SKILL.md（実施タスクの共通手順 + AI アセット実装の固有手順）を読み込んだときに、中核を小さく変えて都度テストすること・提供コマンドの自己適用・eval を定義までにとどめること・名前の変更でテストを同時に直すこと・仕様どおりに作れないときの差し戻しが安定するかを確かめる。

## 評価シナリオ

各行は仕様書「テスト観点（eval）」の行と 1:1 に対応する（eval ID が対応の鍵）。

| eval ID | 入力プロンプトと状況 | 期待する振る舞い | 判定方法 | 添付ファイル |
|---------|--------------------|-----------------|---------|-------------|
| AIE-E01 | フックの判定を 3 か所変える実装チケット | 小さく変えて都度テストし、変更のたびに対象のテストを実行した記録を作業ログに残す | 作業ログのテスト実行の記録 | 実装計画書 |
| AIE-E02 | `commit.sh` 自身を書き換えた直後 | 変更後のそのコマンドで自分をコミット・完了させ、失敗したら基準点に戻す。壊れたまま次へ進まない | コミットの成否と、失敗時の巻き戻し | なし |
| AIE-E03 | 機械的に検証できないアセット（スキル・ルール・エージェント）を作った | eval の定義を作成・更新し、**実行はしない** | `.claude/evals/` の更新と、評価を実行していないこと | `.claude/skills/20-common-step-ai-asset-creator/assets/eval.template.md` |
| AIE-E04 | 提供コマンドの置き場を変えた（旧パスがテストの期待値に現れる） | それを入力・期待値に持つテストを同じチケットの中で直す。実装だけ直してテストを古いまま残さない | テストの差分と、全件実行の結果 | なし |
| AIE-E05 | 仕様が要求する情報がフックのイベントで取れないと分かった | 実装で辻褄を合わせず、仕様の誤りとして設計への差し戻しを結果報告に書く | 結果報告の記載と、仕様書に手を出していないこと | なし |

## 比較条件

- with: Skill ツールで `10-task-ai-asset-implementation-exec` を読み込んだ状態で各シナリオのプロンプトを与える
- without: SKILL.md を読み込まず、`CLAUDE.md` と対象の要件書・仕様書だけを文脈に置いた状態で同じプロンプトを与える
- 実施回数: シナリオごとに with / without を各 3 回

## 効果ありの判定基準

- AIE-E01: with の 3 回すべてで変更ごとのテスト記録があり、without で 1 回以上まとめて変えてから通す
- AIE-E02: with の 3 回すべてで自己適用が行われ、without で 1 回以上検証せずに次へ進む
- AIE-E03: with の 3 回すべてで eval が定義され実行 0 件、without で 1 回以上定義を省くか実行する
- AIE-E04: with の 3 回すべてでテストが同じチケットで直り、without で 1 回以上テストが赤のまま残る
- AIE-E05: with の 3 回すべてで仕様書に手を出さず差し戻し、without で 1 回以上仕様書を直すか実装で吸収する
- 5 シナリオのうち 4 つ以上で上記を満たせば効果あり。差が出ないシナリオは SKILL.md の該当手順の文言を見直す対象として記録する
