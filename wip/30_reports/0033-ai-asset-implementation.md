## 実施した内容と結果

### 1. 読み込み行の `|| true` を戻し、抜けていた経路を SS-T04 に足す ✕問題

0027 が入れた回帰。仕様 `20-common-step-shell-script.md:116` は「`git rev-parse` だけに頼らないのは …… git 不在・リポジトリ外で `set -e` により即死することを避けるため」と明記している。

**SS-T04 がこれを拾えなかった理由**も分かった。既存の `nogit` ヘルパが `make_restricted_path` で PATH から git を外すので、`command -v git` が偽になり 3 段目に入らない。仕様が挙げる 3 条件のうち「リポジトリ外（git はある）」だけが未カバーだった。`withgit` を足し、前提が満たせない環境は `pass` で流さず `fail` にした（検査できなかったことが緑で隠れるのは同じ型の穴）。

### 2. worktree 偽装を塞ぐ ✕問題

判定を「`gitdir:` が `worktrees/` を指す」から、**指す先の実在と相互参照**まで要求する形に変えた。あわせて「本流の配下は worktree ではない」を先に弾く（`参考ディレクトリ/*/.claude` の経路）。`__hc_winpath` を切り出して `HOOK_ROOT` と候補の両方に掛けたので、`/c/…` と `C:/…` の混在で判定が外れる経路も閉じた。

**「穴を塞ぐ決定が別の穴を開ける」型は通算 6 回目**。今回は 0027 の対策が不十分だったという形。

### 3. `curl` の分類の 2 つの穴 ✕問題

- **リダイレクト先を落としていた**。`CP_REDIRECTS` に宛先が入っているのに web 分岐が先にあり、`SC_TARGETS` が空だった。`curl <url> > .claude/hooks/lib/hook-common.sh` が `web` に落ち、WF205 の判定が一切当たらない
- **束ねた短オプションを見ていなかった**。`-d` は捕捉するのに `-sd` は素通り。`web` を宣言しただけのチケットからローカルファイルを送出でき（`-sd @secret`）、作業ツリーへ任意のファイルを落とせた（`-sO`）

値を取る短オプションの表を持ち、`-` で始まる語を 1 文字ずつ走査する形にした（curl の「値を取る文字が末尾なら次の語、途中なら残りが値」の規則）。長オプションは前方一致に変えた。

### 4. `redact` の退行 ◎良

0027 は病的ケース（1 語 4000 字・58 秒）を直したが、区切りの多い現実の入力で超線形になっていた。原因は `${s:pos:1}` の位置指定と、`out+=` の繰り返し（毎回 realloc して O(n²)）。

40 字以上の候補が無ければ規則 5 を丸ごと飛ばす短絡を入れ、連結を配列 + `printf -v` の 1 回にした。**結果として 0027 前より全ケースで速い**。

### 5. `hc_append_jsonl` の切り詰めが不正な JSON を書く △注意

レビューの指摘は「末尾のバックスラッシュ」だったが、実際にはもっと広い。**切断点が JSON の構造の途中（`{"k":"a","` の後ろ）に落ちると `…"}` を足しても閉じない**。つまり入力次第で壊れるかどうかが変わる。

内容を 1 つの文字列フィールドに入れ直し、**エスケープを「切ってから」掛ける**形にした。どこで切っても妥当になる。バイト長は `local LC_ALL=C` の helper で測るので、ロケールに依らず上限を守る。

### 6. `block-chmod` のクォート回避と過剰拒否 △注意

前置判定を生の文字列と「`\` `"` `'` を落とした複製」の両方に当て、`$` 始まりの実行体を opaque にし、制御方式 5（取り除いた文字列を別に解析して実行位置だけ照合）を足した。制御方式 4 は (a) opaque な段の引数 /(b) 中身が見えない形だけコマンド全体 に分けた。

あわせて `. cmdpos.sh` を前置判定の**後ろ**へ動かし、仕様 BC-T05 の「一覧の語を含まなければ `cmdpos.sh` を呼ばずに通る」が実際に成立する形にした。

### 7. テストの検出力 ◎良

**BC-T05 の空振りは、テストの補助関数 `judge` が終了コードを見ていないことが原因でもあった**。無出力 + exit 2（PreToolUse では拒否）を `allow` と読むので、前置判定を消しても落ちない。`judge` を直して初めて検出力が出た。

存在しなかった **HK-T16**（読み込み系 3 関数の戻り値 0/1/2 の区別、`FM_AVAILABLE=0` での無出力、述語・判定関数が 3 状態の規約に巻き込まれないこと）を実装した。`scope_load_ticket` の戻り値 2 の経路は、これまで 1 件もテストされていなかった。

**SS-T05** は `__ss_load` を含むのに行頭一致しないファイルを「対象外」で静かに落としていたので、それも不一致として数えるようにした。
