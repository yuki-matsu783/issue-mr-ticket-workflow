# 全体計画 — 要件定義書の型の改訂

- 対象 issue: #17 https://github.com/yuki-matsu783/issue-mr-ticket-workflow/issues/17
- PR: #18 https://github.com/yuki-matsu783/issue-mr-ticket-workflow/pull/18
- ブランチ: `feature-17-requirements-flow-notation`

## 背景と狙い

要件定義書の受け入れ基準は「EARS で メインフロー → 代替フロー → 例外フロー → 整合 の順に置く」としか
決まっておらず、どの記述をどの節に入れるかの判定基準がない。メインフローは箇条書きだけで分岐と順序が
読み取れず、長い要件書ではレビュアーが全体像を掴めない。自由記述の章（概要・背景・目的）は粒度の基準が
なく重複が起きる。この 3 点を型として決め直し、見本 1〜2 件で成立を示す。

## フェーズ列とチケット構成

| 連番 | type | 内容 | 主な成果物 |
|---|---|---|---|
| 0001 | overall-plan | 本計画書と後続チケットの起票 | `wip/00_overall_plan/0001-overall-plan.md` |
| 0002 | investigation | 既存 45 件の要件書でフロー節の振り分けの揺れ・メインフローの規模分布・自由記述章の粒度を棚卸し。mermaid を GitHub のレビューで使うときの制約を確認。見本候補を選定 | `wip/30_reports/0002-investigation.md` + `.html` |
| 0003 | ai-asset-design | `20-common-step-requirement` の要件書・仕様書の改訂、DDR、見本 1〜2 件の書き直し | `.claude/docs/**` |
| 0004 | ai-asset-implementation | テンプレート・SKILL.md・`ai-asset-design-docs` ルールの改訂、eval 定義 | `.claude/skills/**`, `.claude/rules/**`, `.claude/evals/**` |
| 0005 | overall-summary | PR 本文の最終整形・issue へのコメント・片付け | PR #18 / issue #17 |

チケットは `predecessors` で直列につなぐ。各チケットの完了時が 1 ワークの境界で、push → PR 本文更新 →
レビュー依頼 → レビュー完了の連絡、を挟んでから次に進む。レビュー境界は 5 回。

### 見本の書き直しを ai-asset-design に置く理由

見本の対象は `.claude/docs/00_requirement/` 配下の要件定義書で、`scope-limits.json` では
`ai-asset-design` の許可範囲（`.claude/docs/**`）に入り、`ai-asset-implementation` では拒否される。
型を決める作業と同じチケットで書き直すことで、決めた型が実際に書けるかをその場で検証できる。

## 方針（work-defaults の基準との差分）

| type | 基準 | 本 issue での扱い | 理由 |
|---|---|---|---|
| overall-plan | メイン / 人間レビュー要 / 敵対的不要 | 基準どおり | — |

| ai-asset-implementation | サブエージェント（opus）/ 人間レビュー要 / 敵対的レビュー要 | 実行者を**メインエージェント**に、敵対的レビューを**省略** | 中核を含まず対象がテンプレート・SKILL.md・ルールに閉じる。敵対的レビューはユーザーとの合意で省略 |

### 機構の未整備による運用上の差分

`10-task-*` スキル 15 本（issue #10）と `.claude/hooks/` の各フック（issue #9）、`work-boundary.sh` /
`merge-prep.sh` が未実装。したがって次を手動で代替する。この差分自体は本 issue の成果物ではない。

- ワーク境界の判定・レビュー状態の管理: `work-boundary.sh` の代わりに、チケットの完了と PR コメントで運用する
- 完了処理（wip リセット・衝突確認・issue コメント・draft 解除）: `merge-prep.sh` の代わりに 0005 で手順を手動実行する
- `gh` CLI が環境に無いため、GitHub 操作は GitHub MCP ツールで行う（CLAUDE.md「環境と制約」に従う）

- `10-task-*` スキル・フックの実装（issue #9 / #10 が担う）
