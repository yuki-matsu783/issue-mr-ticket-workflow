# ワークフロー用語

### ワーク

issue の作業を分割する単位で、計画と実施を対にして進める。15 種があり、1 つのワークは 1 枚以上のチケットで実現される。ワークの完了地点が[ワークの切れ目](#ワークの切れ目)になる。

- 正典: [00-workflow-issue-mr-driven.md](../00_requirements/skills/00-workflow-issue-mr-driven.md)「ワークの構成」

### ワークの切れ目

ワークが完了し、次のワークへ進む前の境界。人間レビューの実施や push など、ワークの中では行わない境界処理をここで行う。

- 正典: [00-workflow-issue-mr-driven.md](../00_requirements/skills/00-workflow-issue-mr-driven.md)

### フェーズ列

1 つの issue で実施するワークの並び。issue 種別ごとのテンプレートがあり、全体計画でユーザーと合意して確定する。

- 正典: [00-workflow-issue-mr-driven.md](../00_requirements/skills/00-workflow-issue-mr-driven.md)

### 全体計画

開発作業の最初に行うワーク。issue の確定、フェーズ列の選択、各チケットの実行者と人間レビュー要否の合意までを担う。メインエージェントが行う。

- 正典: [10-work-overall-plan.md](../00_requirements/skills/10-work-overall-plan.md)

### チケット

作業の最小単位。ワークの種類・やってよいこと・実行者・人間レビュー要否・DoD を宣言したファイルで、`wip/10_tickets/` を未着手 → 作業中 → 完了と移動して進む。

- 正典: [自己改善ワークフロー機構.md](../00_requirements/自己改善ワークフロー機構.md) C 節
- 別名・禁止表記: 状態のディレクトリ名は `00_todo` / `10_doing` / `20_done`（文中では未着手 / 作業中 / 完了と書く）

### やってよいこと

チケットが宣言する、書き込んでよい範囲と実行してよい操作の分類。機構が書き込み・操作を許可するか拒否するかの判定基準になる。

- 正典: [自己改善ワークフロー機構.md](../00_requirements/自己改善ワークフロー機構.md) C・D 節

### 実行者

チケットを担当する LLM モデル。チケットに明記され、全体計画で合意する。既定値はワークの種類ごとに `work-defaults` ルールが持つ。

- 正典: [自己改善ワークフロー機構.md](../00_requirements/自己改善ワークフロー機構.md) C 節、[work-defaults.md](../00_requirements/rules/work-defaults.md)

### 人間レビュー要否

そのチケットの成果をワークの切れ目で人間がレビューするかどうかの宣言。理由とセットでチケットに明記される。既定値は `work-defaults` ルールが持つ。

- 正典: [自己改善ワークフロー機構.md](../00_requirements/自己改善ワークフロー機構.md) C 節、[work-defaults.md](../00_requirements/rules/work-defaults.md)

### DoD

チケットの完了条件。何をもって完了とするかの項目群で、チケット完了時の検査対象になる。

- 正典: [自己改善ワークフロー機構.md](../00_requirements/自己改善ワークフロー機構.md) C 節
- 別名・禁止表記: 完了条件

### 作業ログ

チケットに書き込む固定見出しの作業記録。現在地・判断と根拠・逸脱・AI アセットへの反映事項などを持ち、フィードバック計画と再開の入力になる。

- 正典: [自己改善ワークフロー機構.md](../00_requirements/自己改善ワークフロー機構.md) C 節

### 提供コマンド

機構が用意する、状態の変更を担うスクリプト群。チケットの状態遷移・commit / push・レビュー依頼・マージ前の片付けはこれを通して行う。

- 正典: [自己改善ワークフロー機構.md](../00_requirements/自己改善ワークフロー機構.md) C・E 節

### 敵対的レビュー

経緯を知らされない読み取り専用のレビュアー（サブエージェント）が、成果物ルールの観点章に沿って欠陥を探すレビュー。人間レビューの前段として使う。

- 正典: [自己改善ワークフロー機構.md](../00_requirements/自己改善ワークフロー機構.md) I 節

### 軽作業

issue と MR を作らずに範囲を宣言して進める作業。`00-workflow-issue-mr-driven` の基準に当たらない質問・調査・振る舞いを変えない小さな修正が該当する。

- 正典: [00-workflow-quick-request.md](../00_requirements/skills/00-workflow-quick-request.md)

### 単独実行モード

issue と MR を作らず、チケット駆動だけを使う実行形態。ワーク境界の承認は MR ではなくチャット上の確認で取る。

- 正典: [自己改善ワークフロー機構.md](../00_requirements/自己改善ワークフロー機構.md) 代替フロー

### MR

マージリクエスト。機構の文書は GitLab の用語で書き、GitHub では MR → PR、`glab` → `gh` と読み替える。

- 正典: [自己改善ワークフロー機構.md](../00_requirements/自己改善ワークフロー機構.md) 概要
- 別名・禁止表記: PR（GitHub での読み替え）

### wip/tmp

一時ファイル（issue / MR に投稿する本文、その場限りのスクリプト、中間結果）の置き場。コミット対象外で、ワークスペース外のパスの代わりに使う。

- 正典: [自己改善ワークフロー機構.md](../00_requirements/自己改善ワークフロー機構.md) C 節
