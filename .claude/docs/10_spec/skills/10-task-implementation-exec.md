# 10-task-implementation-exec スキル 仕様

## 概要・禁止事項

実装・テスト実施タスクの内部仕様。対応する要件は [00_requirement/skills/10-task-implementation-exec.md](../../00_requirement/skills/10-task-implementation-exec.md)。処理フローの共通手順は `10_spec/skills/10-task-investigation-exec.md`「実施タスクの共通手順（正）」に従い、ここでは固有部分だけを書く。

禁止事項（共通手順の禁止事項に加えて）:

- 設計文書・実装計画書の書き換え（食い違いは「仕様からの逸脱」に記録し、書き戻しは設計反映フェーズ）
- テストを通すためにテストの期待値を仕様と違う値に変えること（変える場合は逸脱として記録し、見てほしい点へ）
- 許可範囲外のファイルへの変更を残すこと（作業ログに理由を残して基準点の状態に戻す）
- テストを書かずに実装すること、失敗を確認せずに実装に進むこと
- ステップの先取り（担当チケットのステップだけ）

## 呼出条件

- `next` が実装チケットを示したとき、全体計画で合意した実行者（サブエージェント）で読み込まれる

## IN / OUT

| IN | OUT |
|----|----|
| 実装計画書（変更対象・許可範囲・テスト方針・ステップ）、設計書（仕様書のテストシナリオ）、実装チケット群 | ソースコードとテストコードの変更（コミット済み）、実装結果レポート（md + HTML）、完了済みの実装チケット群、結果報告 |

## IN / OUT サンプル

- 作業ログ「仕様からの逸脱」: 「AUTH-T03 の期待メッセージは仕様書 §4 と UI 文言集で食い違う。UI 文言集に合わせた。設計反映で仕様書を直す必要あり」
- 結果報告の見てほしい点: 「テスト結果（失敗 → 成功の記録・失敗ケースの網羅）/ 逸脱一覧の妥当性 / 計画外の変更（該当時）/ 許可範囲外の差分が無いこと」

## 処理フロー

共通手順に加えて（3 の実施）:

- ステップごとに **テストを先に書く → 実行して失敗を確認する → 実装する → 通す** の順。失敗の確認結果（コマンドと要約）を作業ログに残す
- テスト側を直した場合（期待値・前提の変更）は理由を「仕様からの逸脱」に記録する。仕様書とコードの実態が食い違って実装できない場合も同様に記録し、仕様書は直さない
- ステップの完了ごとに `git diff --stat <基準点>` で差分が許可範囲内にあることを確認する。範囲外の変更があれば理由を作業ログに書いて `git checkout <基準点> -- <path>` で戻し、必要なら別チケット・別 issue 候補として結果報告に載せる
- 計画に無い変更が要ると分かったら、その理由と最小の変更を作業ログに記録して進め、見てほしい点に「計画外の変更」として挙げる（計画書は直さない）
- 既存テストが通らなくなったら原因を切り分け、自分の変更が原因なら直し、既存の不具合なら「想定と異なった点」に記録して見てほしい点へ
- 完了前に、チケットのテスト ID がすべて通ること・既存テストが通ることを実行して確認し、コマンドと結果を作業ログに残す
- 見てほしい点の固定項目: テスト結果（失敗 → 成功・失敗ケースの網羅）/ 逸脱一覧の妥当性 / 計画外の変更 / 許可範囲外の差分が無いこと

## OUT ひな形

実装結果レポート（report-view のレポートテンプレート）に次を含める: 変更したファイルの一覧（ステップ・仕様書の節との対応）/ テスト結果（テスト ID × 結果・実行コマンド・失敗ケースの有無）/ 仕様からの逸脱の一覧（設計反映で書き戻すべき点）/ 想定と異なった点（計画外の変更・既存の不具合）/ 残課題。
