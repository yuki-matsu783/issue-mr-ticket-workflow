# i0009-41. `web` は `curl` / `wget` を分類として強制し、`WebFetch` / `WebSearch` は緩和のまま残す

## 背景

`i0009-12` は「`web` は機構が強制せず意図の記録に留める」と決め、その理由の 1 つに「issue #9 の調査ワークでは `curl` による取得も併用しており、`WebFetch` だけを止めても**抜け道が残る**（`Bash` の `curl` まで止めるのは過剰）」を挙げていた。

ワーク境界のレビューで、この前提が事実と食い違うことが分かった。

- `scope.sh` の `_SC_READ_ONLY_CMDS` に `curl` / `wget` は**無い**
- `workflow-guard` の制御方式 6 に `web` の分岐は無く、最後は「上記のいずれにも該当しない → **deny WF204**（既定拒否）」

つまり `curl` は「抜け道」どころか**既定で拒否されている**。しかも `curl` は `decisions.jsonl` にコマンド列が残るのに対し、`WebFetch` は matcher 外で記録すら残らない。**記録が残る側だけが塞がれ、記録が残らない側が素通りする**倒錯した状態だった。加えて共通仕様 §8 の「`web` を宣言したときだけ通る」も要件の制約条件も、この事実と食い違っていた。

## 決定

- **`curl` / `wget` を `scope_classify` の `web` に分類する**。`allow.ops` と `types[t].ops` の両方に `web` があれば許可、無ければ **deny WF204**。`SC_CLASS` の値に `web` を加える
- **出力先を持つ形は書き込みとして先に判定する**。`curl` の `-o` / `-O` / `--output` / `--remote-name`、`wget` の既定動作と `-O <file>` は、出力先パスに §8 の判定を当て、`wip/tmp/**` / `logs/**` 以外なら **deny WF205**。宣言があっても書き込みの判定は免除しない
- 出力先を持たない `curl <url>`（既定は標準出力）と `wget -O -` は書き込みに当たらない
- **`WebFetch` / `WebSearch` は引き続き強制しない**（`i0009-12` の決定はこの 2 つに限って有効）。§13 の意図的な緩和はツール側 2 つの行として残す
- `i0009-12` の理由と却下した案から偽の「抜け道が残る」を除き、タイトルを `WebFetch` / `WebSearch` に限定する

## 理由

- **宣言が効かないなら宣言の意味が無い**。`allow.ops` の `web` は「宣言だけあって効いていない項目」だった。コマンド側を分類として通せば、**計画で宣言したチケットだけが外部を取得できる**という当初の意図がそのまま成立する
- **倒錯を正す方向が 1 つしかない**。もう一方（`WebFetch` も止める）は `i0009-12` の理由（判定モデルが合わない・守る対象に当たらない）がそのまま残るので採れない。記録が残る側を通すのが筋
- **調査タスクが回る**。公式ドキュメントを `curl` で落として `grep` で読むのは調査の本体で、`i0009-12` が心配した「止めた場合の害」はここで現実になっていた。宣言があれば通るなら害は無い
- **書き込みの穴を新たに開けない**。`curl -o .claude/settings.json <url>` は上限設定の自己改変そのものなので、`web` の宣言で通してはならない。既存の WF205（コマンドによるファイル書き込み）の規則をそのまま当てれば足り、新しい規則を作らずに済む
- **実装が小さい**。`cmdpos.sh` は既に引数を返しており、`cmdpos_operands`（`i0009-39`）とオプションの照合で出力先を取れる。ホットパスの fork 上限（`i0009-22`）に影響しない

## 却下した案

- **`allow.ops` から `web` を落とす**: 倒錯（記録が残る `curl` だけ塞がれる）が残り、調査タスクが `curl` を使えなくなる。`i0009-12` が「消すと考える契機まで失われる」として既に退けている
- **`curl` / `wget` を `_SC_READ_ONLY_CMDS` に足して常に通す**: 宣言が効かないままで、しかも `-o` による書き込みが読み取り扱いで素通りする。最悪の選択
- **出力先の有無を見ず `web` の宣言だけで通す**: `curl -o` が WF201 / WF205 を迂回する経路になる。宣言は「外部を見てよい」の許可であって「どこにでも書いてよい」の許可ではない
- **`WebFetch` / `WebSearch` も matcher に足して強制する**: `i0009-12` の 2 つの理由（`scope_classify` はコマンド列を前提にする / 副作用が読み取りに閉じる）が今も有効。1 つのフックに 2 つの判定モデルを持たせない
- **オプションの厳密な解析（`--output=<file>` の等号形まで）を行う**: 等号形も含めて前方一致で拾えば足り、`getopt` 相当の解析は要らない（`i0009-39` と同じ線引き）
