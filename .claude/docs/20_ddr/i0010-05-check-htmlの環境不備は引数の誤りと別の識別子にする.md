# check-html.sh の環境不備は引数の誤りと別の識別子にする

## 背景

`20-common-step-report-view` 仕様は `check-html.sh` の `RV008` を 2 か所で使っていた。1 つは「引数が 1 つでない・ファイルが無い・読めない・`.html` でない」、もう 1 つは「`awk` が無い環境で検査を縮退させずに止める」。どちらも終了コード 2 だが、原因が違う。

`10-task-ai-asset-design-plan` の要件は「番号で引く一覧（識別子の台帳）を確定するチケットの完了条件に『1 つの番号が 1 つの原因だけを指すこと』の確認を含める」と定めている（申し送り 0029）。この issue で `check-html.sh` の仕様を触っている以上、自分の定めた基準を自分が破っている状態を残せない。

## 決定

- `RV008` は**引数・ファイル不正だけ**を指す（引数が 1 つでない・ファイルが無い・読めない・`.html` でない）
- **`RV009` を新設**し、環境の不備（`awk` が使えない）を指す。判定は `RV008` の後、検査に入る前
- どちらも終了コードは 2（使い方・環境の誤りで、検査の不合格ではない）
- 台帳（`フック共通仕様` §6）の `RV` の範囲を `RV001–009` に広げる
- テスト `RV-T08`（`PATH` から `awk` を外した状態で、正しい引数・正しい HTML を渡しても `RV009`・終了 2 になる）を追加する

## 理由

- **受け取った側の対処が違う**。`RV008` は呼び出し方を直せば解決するが、`RV009` は実行環境に `awk` を入れるまで解決しない。同じ番号だと、AI も人間もメッセージの本文を読み解いてから分岐することになる
- **縮退しないことの担保にテストが要る**。「黙って通さない」は振る舞いの規定なので、テスト ID を持たないと実装が守ったか確かめられない。番号を分けると「`RV009` が返る」という形でテストが書ける
- **DDR `i0006-12` と矛盾しない**。あちらは「提供コマンドごとに引数・環境の誤りの識別子を新設し、既存番号を転用しない」という決定で、1 コマンドが 1 つしか持てないとは定めていない。`RV008` を 2 原因のまま残すほうが `i0006-12` の趣旨（原因ごとに番号を持つ）から外れる

## 却下した案

- **`RV008` のまま、メッセージの本文で区別する**: 識別子は分岐の材料として使うものなので、本文を読ませる設計は識別子を持つ意味を失わせる。`10-task-ai-asset-design-plan` が定めた「1 番号 1 原因」にも反する
- **`awk` が無ければ検査を縮退させて `grep` / `sed` で代替する**: 「検査した」という記録だけが残り、検査の強度が環境によって変わる。issue #6 の逸脱 D2-4 がこの形で見逃しを生んだ
- **`RV009` ではなく `RV000` 台の別レンジを使う**: 台帳の `RV` は `001` からの連番で、レンジを分ける規約は無い。1 コマンドの識別子を 2 レンジに割るほうが読み手の負担が大きい
- **`check-html.sh` の前提コマンドから `awk` を外す**: 属性値と `id` の抽出は `awk` で書くと素直で、`grep` / `sed` の組み合わせに置き換えると読めなくなる。前提を減らす価値より可読性を採った

## 影響

- `20-common-step-report-view` 仕様の「前提コマンド」「終了コード」「検査項目の表」「テスト観点」の 4 か所を更新する
- `フック共通仕様` §6 の `RV` の行を `RV001–009` に更新する
- テスト ID の総数が 1 増える（`RV-T08`）
- 実装フェーズは `check-html.sh` に `awk` の存在確認を入れ、`RV009` で終了 2 を返す
