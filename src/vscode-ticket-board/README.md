# チケットボード（VS Code 拡張）

`wip/10_tickets/` 配下のチケット Markdown を読み、状態ディレクトリを列としたカンバンボードを Webview に表示する。**読み取り専用**で、チケットの状態を変えたりファイルを書き換えたりはしない。

- 要件: `docs/00_requirement/vscode-ticket-board.md`
- 仕様: `docs/10_spec/vscode-ticket-board.md`

## できること

| コマンド（コマンドパレット） | 動き |
|---|---|
| `チケットボード: ボードを開く` | ボードを開く。既に開いていれば増やさず前面に出す |
| `チケットボード: ボードを更新` | 走査からやり直して内容を差し替える |

- 列は `00_todo` / `10_doing` / `20_done` / `30_cancelled` の 4 つ。チケットが 0 件の列も件数 0 で出す
- カードにはチケットの番号・タイトル・種類・実行者・人間レビュー要否・敵対的レビュー要否を出す
- カードを選ぶ（クリック / Enter）とそのチケットのファイルをエディタで開く
- `wip/10_tickets/**/*.md` の作成・変更・削除を監視し、自動で読み直す
- 読み取れない項目は `TB001`〜`TB007` の不備としてカードに出し、他のチケットの表示は止めない

## 必要なもの

| ツール | 版 |
|---|---|
| VS Code | 1.90 以上 |
| Node.js | 22 以上（`npm test` の `node --test` に使う） |

## ビルドとテスト

このディレクトリ（`src/vscode-ticket-board/`）で実行する。

```sh
npm install     # 開発依存（typescript / @types/node / @types/vscode）を入れる
npm run compile # tsc -p . で out/ に出力する
npm test        # tsc -p . のあと node --test out/test/*.test.js を走らせる
```

`npm test` は中核層（`src/core/`）の単体テスト TB-T01〜TB-T17 を実行する。`out/` と `node_modules/` はこのディレクトリの `.gitignore` で除外してある。

> `node --test` にはディレクトリではなくグロブ（`out/test/*.test.js`）を渡す。ディレクトリを渡すと `MODULE_NOT_FOUND` になる。

## デバッグ実行（拡張ホストで動かす）

1. `npm install && npm run compile`
2. VS Code でこのディレクトリを開く
3. `F5`（実行とデバッグ → 拡張機能）で拡張開発ホストのウィンドウを起動する
4. そのウィンドウで、チケットのあるリポジトリ（`wip/10_tickets/` を含むフォルダ）を開く
5. コマンドパレットから `チケットボード: ボードを開く` を実行する

`.vscode/launch.json` は置いていない。`F5` で「拡張機能」の構成を選べば、`main`（`./out/src/extension.js`）から起動する。

## 手動確認の手順

`extension.ts` と `board-panel.ts` は VS Code の API に触れるため単体テストの対象外で、次の受け入れ条件は拡張開発ホストで確認する。上の「デバッグ実行」の 1〜4 を済ませた状態から始める。

| # | 確認すること | 手順 | 期待 |
|---|---|---|---|
| 1 | ボードが開く | `チケットボード: ボードを開く` を実行する | 4 列のボードが出て、上部に残り件数・全件数・不備件数が出る |
| 2 | カードの選択でファイルを開く | 任意のカードをクリックする。続けて別のカードを `Tab` で選び `Enter` を押す | どちらもそのチケットの Markdown がエディタで開く |
| 3 | 更新コマンドで読み直す | チケットを 1 枚追加してから `チケットボード: ボードを更新` を実行する | 追加したチケットがボードに現れる |
| 4 | ファイルの変化で自動更新する | ボードを開いたまま、エディタや別のターミナルからチケットを `00_todo` から `10_doing` へ移す | コマンドを実行しなくても、そのカードが作業中の列へ移る |
| 5 | 増やさず前面に出す | ボードを開いたまま、もう一度 `チケットボード: ボードを開く` を実行する | タブは 1 つのままで、既存のボードが前面に出る |
| 6 | 再表示で読み直す | ボードのタブを裏に回し、その間にチケットを 1 枚足してからタブに戻る | 戻った時点で足したチケットが出ている |
| 7 | ワークスペースが無い場合 | 「ファイル → ウィンドウを閉じる」等でフォルダを開いていないウィンドウを作り、そこで `チケットボード: ボードを開く` を実行する | 「ワークスペースが開かれていないため、チケットボードを表示できない」と通知が出て、ボードは開かない |
| 8 | 対象が無い場合 | `wip/10_tickets/` を持たないフォルダを開いて `チケットボード: ボードを開く` を実行する | 「wip/10_tickets が見つからないため、チケットボードを表示できない」と通知が出る |
| 9 | 表示中に対象が失われた場合 | ボードを開いたまま `wip/10_tickets/` の名前を変える（確認後に戻す） | 「wip/10_tickets が失われたため、チケットボードを閉じる」と通知が出て、ボードのタブが閉じる |
| 10 | 未表示で更新した場合 | ボードのタブを閉じた状態で `チケットボード: ボードを更新` を実行する | 「チケットボードが開かれていない」と通知が出る |
| 11 | 選んだファイルが無い場合 | ボードを開いたまま、ターミナルからチケットを 1 枚削除し、**自動更新が走る前に**（120 ミリ秒以内）そのカードをクリックする。難しければ削除の直後に連打してもよい | 「チケットのファイルを開けなかった」と通知が出たあと、ボードが読み直されてそのカードが消える |
| 12 | 1 枚の失敗で他を止めない | frontmatter を壊したチケット（例: 先頭の `---` を消す）を置いて更新する | そのカードに `TB001` が出て、他のカードは今までどおり出る |

11 は競合状態を突く確認のため、再現しなければ「削除したチケットのカードをクリックしても何も起きない」（自動更新後は `isKnownTicketPath` が弾く）ことを確認すれば足りる。

## 構成

```
src/
  extension.ts        コマンド登録（vscode に依存する）
  board-panel.ts      Webview パネルの生成・更新・破棄、ファイル監視（vscode に依存する）
  core/               vscode に依存しない中核層。単体テストの対象
    frontmatter.ts    frontmatter のサブセットパーサ
    ticket.ts         チケットの内部表現と検証
    scan.ts           状態ディレクトリの走査
    board.ts          ボードの組み立て
    render.ts         HTML の生成
test/                 core/ の単体テスト
```

`core/` は `vscode` を import しない。拡張ホストの外では `vscode` が解決できないため、この分割によって `node --test` だけで中核の振る舞いを確かめられる。
