# i0009-16. `frontmatter.sh` のスタブは戻り値 2 で「読めない」と「無い」を区別する

## 背景

0014（DDR `i0009-14`）で `scope.sh` の読み込みポリシーを `deny` から **`nop`** に変えた。読めなければ `fm_*` が空を返すスタブになり、失敗をどう扱うかは呼び手のフックが決める。

ここで問題になるのが**回復の案内**である。`workflow-guard` は 2 つの別々の識別子を持つ。

| 識別子 | 意味 | 回復の案内 |
|---|---|---|
| `WF209` | 判定不能（機構の破損） | `.claude/` の状態を確認してユーザーに報告する |
| `WF211` | チケットの記載不正・種類が設定に無い | チケットの記載を直す / `ticket.sh cancel` |

`frontmatter.sh` が読み込めていない（機構の破損）のと、frontmatter は読めたがキーが無い（チケットの記載不正）のは、**どちらも `fm_get` が空を返す**。空だけを見ていると取り違えが起き、AI がチケットを直そうとして直らない（あるいは機構の破損だと誤報告する）。0014 はこの区別の設計を 0015 に送った。

## 決定

- `nop` ポリシーで `frontmatter` を読み込めなかったとき、`fm_extract` / `fm_get` / `fm_list` / `fm_has` を**出力なし・戻り値 2** のスタブとして定義し、`FM_AVAILABLE=0` を設定する（読めたときは `FM_AVAILABLE=1`）
- 戻り値で 3 状態を区別する: **0** = 値を読めた / **1** = frontmatter は読めたがキーが無い・対象外の形（→ `WF211`）/ **2** = ライブラリを読み込めていない（→ `WFx09`）
- `scope.sh` は `fm_*` の戻り値 2 を自分の戻り値 2 としてそのまま呼び手へ返す（1 と 2 を潰さない）
- 案内側のフックは 1 と 2 のどちらでも何も出さずに通すが、`decisions.jsonl` の `note` に原因を書き分けられるよう区別自体は保つ
- テストは `SS-T04`（読み込み行の `nop` でスタブと `FM_AVAILABLE=0` が定義される）と **`HK-T16`**（`scope.sh` の戻り値 0 / 1 / 2 の区別と、`frontmatter.sh` を隠した環境で `scope.sh` 自身が無出力であること）で固定する

## 理由

- **既にある終了コードの規約と揃う**。提供コマンドの終了コードは「0 成功 / 1 検査・前提未充足 / 2 引数や環境の誤り」で、`2 = 環境の誤り` はライブラリ不在と同じ性格。読み手が新しい約束を覚えなくてよい
- `FM_AVAILABLE` だけで済ませる案もあるが、呼び手が毎回グローバル変数を確認する形になり、確認を忘れると 1 と 2 を取り違える。**関数の戻り値なら `if ! fm_get ...; then case $? in ...` の形で自然に分岐できる**
- 空文字列に特別な値（`__UNAVAILABLE__` など）を入れる案は、値としてそのまま使われると壊れる。戻り値なら値の空間を汚さない

## 却下した案

- **`FM_AVAILABLE` だけを見る**: 呼び手が確認を忘れると取り違える。戻り値と併用すれば忘れても安全側（2 が返る）に倒れる
- **`scope.sh` の側で `WF209` / `WF211` まで決めて返す**: `scope.sh` は共有ライブラリで、`workflow-guard`（WF2xx）と `workflow-state-guard`（WF3xx）で識別子の番号が違う。ライブラリが呼び手の識別子を知る設計は避ける（DDR `i0009-17` の「分類まで / 照合は呼び手」と同じ理由）
- **区別せず常に `WF209` に倒す**: チケットの記載不正は実際に起きるほうの故障で、そのたびに「機構が壊れた」と報告されると回復の案内が役に立たない

## 影響

- `10_spec/skills/20-common-step-shell-script.md`「読み込み行」（`scope.sh` の行・スタブの戻り値の表）・`SS-T04`
- `10_spec/フック共通仕様.md` §8（`scope.sh` の関数の戻り値）・§11（`HK-T16` を追加）
- `10_spec/hooks/20-PreToolUse/workflow-guard.md` / `workflow-state-guard.md`（判定順 4 の `WF211` と `WFx09` の分岐は戻り値で行う）
- **実装フェーズへ**: `scope.sh` の各関数は `fm_*` の戻り値を握りつぶさない
