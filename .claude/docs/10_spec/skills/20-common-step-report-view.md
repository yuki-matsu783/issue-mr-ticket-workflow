# 20-common-step-report-view スキル 仕様

## 概要・禁止事項

HTML ビュー作成の共通ステップの内部仕様。対応する要件は [00_requirement/skills/20-common-step-report-view.md](../../00_requirement/skills/20-common-step-report-view.md)。

Markdown を正文とし、HTML はテンプレートのコピーを Edit で埋めて作る。出力後に検査スクリプト `check-html.sh` に通す。

禁止事項:

- スクリプトや白紙からの HTML の組み立て（必ずテンプレートのコピーから）
- テンプレートの DOM 構造の改変（構造の変更はテンプレート自体の改訂として AI アセットフェーズへ）
- HTML にだけある情報を作ること（正文は Markdown）
- 片方（md / html）だけを更新して作業を終えること
- 検査を飛ばした提出、独自の色・記号の持ち込み
- 全体計画書への HTML ビューの作成

## 呼出条件

- 各実施タスク（結果レポート）・各計画タスク（フェーズ計画書）・`10-task-overall-summary`（統括レポート）が、md を書き終えて HTML を作るとき、および md を更新したとき

## IN / OUT

| IN | OUT |
|----|----|
| 正文の Markdown（`wip/30_reports/` または `wip/20_plans/`）、用途（レポート / 計画書） | 同じベース名の `.html`（検査通過済み）、検査結果（作業ログに残す） |

## IN / OUT サンプル

```bash
cp .claude/skills/20-common-step-report-view/assets/report.template.html wip/30_reports/0002-investigation.html
# （Edit で節を埋める）
bash .claude/skills/20-common-step-report-view/scripts/check-html.sh wip/30_reports/0002-investigation.html
# => OK: 検査 6 項目すべて通過（id 42 件 / リンク 17 件を確認）
# => RV001: プレースホルダが残っている: {{summary}}（1 件）
```

## 処理フロー

1. 対象を判定する: `wip/30_reports/` の結果レポート・統括レポートと `wip/20_plans/` の計画書は必須。全体計画書（`wip/00_overall_plan/`）には作らない
2. 用途に対応するテンプレート（レポート用 / 計画書用）を**同じベース名**で `cp` する
3. Edit で節を埋める。内容は md と同一（視覚化のみ）。テンプレートの節に対応しない内容は最も近い節へ、空になる任意の節は削除する（DOM の構造変更はしない）
4. `check-html.sh` を実行し、失敗したら原因を直して再実行する（飛ばさない）
5. 検査結果（通過項目・確認件数）を作業ログに残す
6. 以後 md を更新したら、同じ変更を HTML に反映して 4〜5 を繰り返す

## OUT ひな形

- `assets/report.template.html`（レポート用）と `assets/plan.template.html`（計画書用）。共通の規約:
  - 自己完結: 外部リソース参照なし・`<style>` は 1 つ・スクリプトなしで表示可能
  - ライト / ダーク両対応（`prefers-color-scheme`）
  - 視覚語彙: 結論の性質は 3 色 + 記号 + 文字（良 / 注意 / 問題）、レビューの重みは色相を使わず ◆（特に見てほしい）/ ◇（承認が欲しい）/ ・（細かいレビュー不要）
  - プレースホルダは `{{名前}}` 形式。必須節には `data-required` 属性を付け、検査の対象にする
  - 節構成はレポートが「サマリ → 確かめられなかったこと → 実施した内容と結果 → 設計への反映 → 想定と異なった点 → 残課題」、計画書は計画タスクの要件に従う
- 初版は参考実装のレポートテンプレートを土台に、参考実装固有の記述を除いて作る（`i0001-05`）

## 参照ナレッジ

- HTML ビューの対象と md 正文の原則: 要件書と `i0001-05`
- md / html の対の存在検査: push 前チェック（`10_spec/skills/20-common-step-commit-push.md` 項目 3）
- 検査結果の記録先: `20-common-step-ticket`（作業ログ）

## Script 処理

### check-html.sh <file.html>

検査は**全項目を実行して**未充足を全件列挙する。終了コードは成功 0 / 検査不合格 1 / 引数・ファイル不正 2。ログ: すべてのサブコマンドは共通 logger（`10_spec/lib/logger.md`）を source し、受け付けた操作・判定結果・拒否理由を INFO で、判定材料の詳細を DEBUG で `logs/sh/` に記録する。標準出力には出さない。

| # | 検査 | 不合格の識別子 |
|---|------|---------------|
| 1 | プレースホルダ（`{{名前}}`）の残存が 0 件 | RV001 |
| 2 | 外部リソース参照（`http(s)://` の href / src / url()。ページ内アンカーと `data:` は除く）が 0 件 | RV002 |
| 3 | id の重複が無い | RV003 |
| 4 | ページ内リンク（`#id`）の参照先がすべて存在する | RV004 |
| 5 | `<style>` 要素がちょうど 1 つ | RV005 |
| 6 | テンプレートの必須節（`data-required` 付きの節）がすべて存在する | RV006 |
| 7 | 負のコントロール: 抽出した id・リンクが 0 件のとき「異常なし」とせず、抽出自体の故障を疑って不合格にする | RV007 |

- 出力は `OK:`（確認した件数を添える。件数の明示が負のコントロールを兼ねる）または `RVxxx:` の列挙
- 検査 6 の必須節一覧はテンプレート自身から導出する（テンプレートを読み `data-required` を集める）。テンプレートと検査の二重管理をしない

### テスト観点

| テスト ID | 種別 | 固定する振る舞い |
|-----------|------|----------------|
| RV-T01 | 正常系 | テンプレートを正しく埋めた HTML が OK（件数付き） |
| RV-T02 | 異常系 | プレースホルダ残存・外部参照・重複 id・破断リンク・style 2 つがそれぞれの RV で全件列挙 |
| RV-T03 | 異常系 | 必須節を丸ごと削った HTML が RV006 |
| RV-T04 | 異常系 | 空に近い HTML（id/リンク 0 件）が RV007（出力なし＝合格にしない） |
| RV-T05 | 境界 | ページ内アンカー・data: URI は外部参照と数えない |

## 要件との対応

| 要件（受け入れ基準） | 実現箇所 |
|--------------------|---------|
| メイン: 必須対象に同ベース名の HTML・全体計画書には作らない | 処理フロー 1・2、禁止事項 |
| メイン: テンプレートのコピーと Edit（スクリプト生成・白紙禁止） | 処理フロー 2・3、禁止事項 |
| メイン: md 正文・HTML は視覚化 | 処理フロー 3、禁止事項 |
| メイン: 更新の同期 | 処理フロー 6 |
| メイン: 機械的検査と作業ログへの記録 | check-html.sh、処理フロー 4・5 |
| 代替: 対応しない内容は近い節へ・DOM 改変禁止 | 処理フロー 3 |
| 例外: 検査失敗は直して再検査 | 処理フロー 4 |
| 例外: テンプレートが無ければフリーハンドで書かない | 禁止事項（不在は呼び出し元へ返す） |
| 規約: 視覚語彙・自己完結・ライト / ダーク | OUT ひな形 |
| 整合: 対の同期は push 前チェックの対象 | 参照ナレッジ |
| 整合: 手順の再掲禁止 | 参照ナレッジ（呼び出し元はこの仕様を参照） |
