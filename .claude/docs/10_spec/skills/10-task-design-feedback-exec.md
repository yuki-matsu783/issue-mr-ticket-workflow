# 10-task-design-feedback-exec スキル 仕様

## 概要・禁止事項

設計反映実施タスクの内部仕様。対応する要件は [00_requirement/skills/10-task-design-feedback-exec.md](../../00_requirement/skills/10-task-design-feedback-exec.md)。処理フローの共通手順は `10_spec/skills/10-task-investigation-exec.md`「実施タスクの共通手順（正）」に従い、ここでは固有部分だけを書く。

禁止事項（共通手順の禁止事項に加えて）:

- ソースコード・テストの書き換え（実装の誤りを見つけてもコードは直さず「実装漏れ」として報告）
- 設計書の本文への変更履歴・経緯の記載（経緯は DDR）、実装漏れを設計書側で吸収すること
- 設計反映計画書の差分一覧の行の削除（消込は「一致」への更新。新差分は行の追加）
- 実装に根拠の無い設計書の変更（差分一覧・コードのどちらにも無い変更）

## 呼出条件

- `next` が設計反映チケットを示したとき、全体計画で合意した実行者（サブエージェント）で読み込まれる

## IN / OUT

| IN | OUT |
|----|----|
| 設計反映計画書（差分一覧・書き戻し方針）、設計書、実装結果レポート、ソースコードとテスト（読むだけ） | 更新された設計書と DDR、消込済みの差分一覧（計画書の更新）、設計反映結果レポート（md + HTML）、完了済みの設計反映チケット群、結果報告 |

## IN / OUT サンプル

- 書き戻し: 仕様書 §4 の期待メッセージを実装（`auth/messages.ts:12`）どおりに書き換え、DDR「エラーメッセージを UI 文言集に統一」を追加、差分一覧の該当行を「一致」に更新
- 結果報告の見てほしい点: 「書き戻しが実装の実態と一致しているか（根拠の行）/ 差分一覧の消込漏れ / 新たに見つかった差分・実装漏れ / DDR に経緯が残っているか」

## 処理フロー

共通手順に加えて（3 の実施）:

- 差分一覧の担当行ごとに、**実装（ファイル・行・テスト）を根拠に**設計書の該当節をその時点の正史へ書き換える。分類「設計に無い決定」は追記、「設計書が古い」は置き換え。いずれも採らなかった案・理由を DDR に残す
- 仕様書のテスト ID を実装のテストと突き合わせ、名称・番号のずれを設計書側で合わせる（実装のテストは触らない）
- 反映した行は計画書の差分一覧を「一致」に更新する（消込）。作業中に新しい差分を見つけたら行を追加して分類し、担当範囲なら反映、そうでなければ残課題に書く
- 実装の誤り（設計書が正しく実装が違う）を見つけたら、コードは直さず差分一覧の分類を「実装漏れ」に改め、レポートの実装漏れ一覧に載せる
- 書き終えたら設計書のプレースホルダ 0 件と、用語・インターフェースの整合を確認する
- 見てほしい点の固定項目: 書き戻しと実装の実態の一致（根拠）/ 差分一覧の消込漏れ / 新差分・実装漏れ / DDR の経緯

## OUT ひな形

設計反映結果レポート（report-view のレポートテンプレート）に次を含める: 更新した設計書・節・DDR の一覧（根拠とした実装の箇所）/ 差分一覧の消込結果（残った行とその理由）/ 実装漏れ一覧（実装の追加が要る点）/ 想定と異なった点（新差分）/ 残課題。
