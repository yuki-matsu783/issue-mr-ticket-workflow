# i0009-58. 横断で決めた規則は個別の要件と仕様まで降ろす

## 背景

`i0009-41` は「`curl` / `wget` は `web` の分類として機構が強制する」と決め、共通仕様 §8 と `workflow-guard` を更新した。しかし、その決定と矛盾する記述が別の文書に残っていた。

| 文書 | 残っていた記述 |
|---|---|
| `00_requirement/skills/10-task-investigation-exec.md:97` | 「リポジトリ外への問い合わせを行わない（**この禁止は機構では強制されず** — 読み取り操作は種類を問わず許可される — スキルの自制による）」 |
| `10_spec/skills/10-task-investigation-exec.md:19` | 同じ禁止の記述（強制の有無に触れない） |
| `10_spec/skills/20-common-step-shell-script.md:126` | `scope_classify` の分類一覧に **`web` が無い**（`read` / `build-test` / `hook-test` / `remote-read` / `remote-write:*` / `merge-base` / `provided` のまま） |

ワーク境界の 2 巡目レビューは、1 巡目 38 件のうち閉じきれなかった 7 件が**すべて同じ型**（横断仕様では閉じたが、実装される側の個別仕様・要件で閉じていない）だったと報告した。`i0009-41` はその 7 件を直すためのチケットで作られた決定なのに、**同じ型を新たに作っていた**。

## 決定

- `i0009-41` の反映を個別文書まで降ろす（上の 3 文書を是正）
- **規約として**: 横断文書（`10_spec/フック共通仕様.md` 等）で決めた規則は、DDR の「影響」に**降ろす先を列挙し切る**。列挙の対象は次の 4 種類
  1. その規則が現れる**個別のフック・スキルの仕様書**
  2. その規則に対応する**要件書**（外から見える振る舞いが変わる場合）
  3. 同じ事実を**再掲している表・一覧**（分類表・語彙表・採番台帳）
  4. その規則を根拠にしている**既存の DDR**
- **再掲する表には「正は横断文書の §X」と書く**。`20-common-step-shell-script` の分類表のように、責務の境界を示すための要約は残してよいが、正がどこかを明示する（「正は 1 箇所」の原則）

## 理由

- **同じ型の取りこぼしが 2 巡続けて起きた**。1 巡目の 7 件も、2 巡目の B3・B5・B6・B7・B8 も同じ形をしている。個別の是正だけを続けても再発する
- **「影響」は既にある節なので、新しい仕組みを足さない**。DDR の節構成（背景 / 決定 / 理由 / 却下した案 / 影響）を変えず、影響に書く内容の粒度を決めるだけ
- **列挙し切れば `grep` で確かめられる**。「この決定に関係する語」で検索して、影響に挙がっていない文書が出たら取りこぼしである。チケット完了時の自己点検に使える
- **要約の再掲を禁じるのは行き過ぎ**。`20-common-step-shell-script` の分類表は「どのライブラリが何を返すか」の責務の境界を示すもので、読み手にとって有用。正の所在を書けば矛盾の危険は下がる

## 却下した案

- **再掲を全面的に禁じ、すべて横断文書への参照にする**: 個別の仕様書が読み物として成立しなくなる。責務の境界のような文脈依存の要約は、その場にある方が読みやすい
- **機械的な検査（同じ語が複数文書にあれば警告）を作る**: 正当な再掲と取りこぼしを区別できない。設計文書検査（`ai-asset-design-docs` の「テスト・機械的検査」）に載せるには基準が曖昧すぎる
- **横断文書を廃止して個別仕様だけにする**: 共通の規則が 11 本のフック仕様に散らばり、変更のたびに 11 か所を直すことになる。`i0009-13`（横断は 1 か所）の逆行
- **チェックリスト文書を作る**: `ai-asset-design-docs` が「別のチェックリスト文書を作らない」と定めている

## 影響

- `00_requirement/skills/10-task-investigation-exec.md`（外部への問い合わせの強制の有無を事実に合わせる）
- `10_spec/skills/10-task-investigation-exec.md`（同上）
- `10_spec/skills/20-common-step-shell-script.md`（分類表に `web` を追加し、正が §8 であることを明記）
- `00_requirement/自己改善ワークフロー機構.md` 制約条件（自制の列挙から調査タスクの問い合わせ禁止を外す）
- `20_ddr/i0009-41`（影響に上記 3 文書を追記）
- **今後の設計チケットへ**: DDR の「影響」に降ろす先を列挙し切る。列挙は 4 種類（個別仕様 / 要件 / 再掲している表 / 根拠にしている DDR）
- 関連: `i0009-13`（横断は 1 か所に集める）・`i0009-41`（`web` の強制）
