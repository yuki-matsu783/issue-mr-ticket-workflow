# i0001-28. 機構の記録はリポジトリ直下の logs/ に置き、コミットと片付けの対象外にする

## 背景

`i0001-22` の決着（片付けが作業領域を文字どおり空にする）に伴い、片付け後の push・draft 解除・継続判定を支える記録（MR の記録・マージ前作業の証跡・前回 push 時点）は「ブランチ外の消えない場所」に置くとしたが、具体的な場所が未定だった。フックの判定記録やセッション内の承認記憶も、置き場が決まっていなかった。一時ファイルには「ワークスペース外のパスを使わない」（`i0001-13`）という既定の原則がある。

## 決定

- 機構が自身のために持つ記録 — MR とマージ前作業の進行状態、前回 push 時点、フックの判定記録、セッション内の承認の記憶 — は**リポジトリ直下の `logs/` ディレクトリ**に置く
- `logs/` は**コミットの対象外**（`.gitignore` で保証）かつ**全体まとめの片付けの対象外**とする。機構が必要時に自動作成する
- 記録はローカル限りのため、失われた場合（別の clone・誤削除）は **MR とリモートの実態からの再導出、または提供コマンドの再実行で復元できる**ことを要件とする（`logs/` が唯一の正であってはならない）
- 証跡の正はあくまで MR への実操作（コメント投稿・添付・draft 解除・push されたコミット）であり、`logs/` はその導出結果と判定材料を置くローカルの記録である
- 進行状態ファイルの直接書き換えの拒否（D 節）は置き場によらず適用される
- タスクの証跡として MR の差分に残すもの（チケット・レビュー状態など作業領域の内容）は従来どおり `wip/` に置き、`logs/` に移さない

## 理由

- リポジトリ内にあることで、可視でデバッグ・振り返りに使え、`i0001-13` の「ワークスペース外のパスを使わない」原則とも一貫する
- gitignore により、片付け・squash merge の設計（wip の履歴は main に残らない）と独立して記録が残る。状態変化のたびのコミットも要らない
- worktree ごとに独立する（gitignore されたファイルは worktree 単位）ため、「並行作業は worktree または別 clone」の前提とも整合する

## 却下した案

- **wip/ 内に置いて片付けの除外リストで残す（参考実装 merge-prep.json 方式）**: 「片付け = 作業領域を空にする」の単純さが崩れ、コミット対象のため状態変化のたびに履歴が増える
- **`.git/` 配下や OS の一時ディレクトリ・セッションディレクトリ**: `i0001-13` の原則に反し、可視性が低く、振り返りで参照しにくい
- **`logs/` をコミット対象にする**: 記録の耐久性は上がるが、squash してもローカル状態の変遷が MR の差分を汚し、別ブランチとの衝突源になる

## 影響

- `.gitignore`（`logs/` を追加済み）
- `10-task-overall-summary.md`・自己改善ワークフロー機構.md J 節（置き場の明記と logs/ の一般規定）
- `hooks/22-PostToolUse/post-push-compact-prompt.md`（前回 push 時点の置き場）
- `i0001-22` の「消えない場所」の具体化
- 各フック・提供コマンドの仕様（`logs/` 配下のファイル構成・再導出の手順は仕様で定める）
