# i0001-26. チャットで受けた承認と判断はタスクの切れ目ごとに MR コメントへ書き写す

## 背景

敵対的レビューで、承認①〜③やフィードバック計画の合意はチャットで取られ、記録先の全体計画書・フィードバック計画書は片付けで消え、squash merge で履歴にも残らないため、「誰が・いつ・何に合意したか」がマージ後に残る保証が弱いと指摘された。参考実装は同型の事故（AI が仰いだ 3 点の回答がすべてチャットに来て、記録がどこにも残らなかった）を経て「チャットで受けた判断はレビュー往復ごとに MR 通常コメントへ投稿する。wip に書くだけでは代わりにならない」を義務化していた。本機構は「レビュアーがチャットでレビュー判断を伝えた場合」だけを覆っており、タスク中の承認・保留点への回答は覆っていなかった。

## 決定

- タスクの切れ目に達したとき、そのタスクの間にチャットで受けた承認・判断・保留点への回答を MR のコメントとして投稿する（push・MR 本文の要約追記とあわせて切れ目の処理に含める）
- 作業領域（wip/）と全体計画書への記録は行うが、それだけでは記録にならない（片付けと squash merge で消える）
- あわせて、MR 本文・MR コメント・issue には `wip/` 配下のパスを恒久的な参照として書かない（片付けと squash merge で参照先が消える）。恒久的な参照は issue 番号・MR・正史のファイルに限り、レビュー依頼でレビュー対象を指す一時的な参照だけを例外とする
- 全体計画書の「合意の記録」の正は、マージ後は切れ目ごとの MR コメントと統括レポートの要約に引き継がれる

## 理由

- チャットは squash merge 後に残る唯一の場所ではない。MR コメントは MR と同じ寿命で残り、レビュアーが往復の文脈ごと追える
- 切れ目は push と MR 本文更新が必ず起きる場所であり、書き写しの実施タイミングとして機械的に定まる（「合意のたび」だと漏れる）
- 参考実装が実際の事故から獲得した規則であり、本機構の全体計画書が片付けで消える設計では必要性がより高い

## 却下した案

- **全体計画書への記録だけ（従来）**: 片付けと squash merge で消え、マージ後に合意の証跡が残らない
- **合意のたびに即時投稿**: 記録の粒度は上がるが、投稿回数が増えて MR のコメント欄が会話ログ化する。切れ目ごとの要約で足りる
- **squash merge をやめて履歴を残す**: wip の全履歴が main に残り、片付け設計全体と衝突する

## 影響

- `00-workflow-issue-mr-driven.md`（切れ目の処理に書き写しと wip パス参照禁止を追加）
- `10-task-overall-plan.md`（非機能要件: マージ後の合意記録の正の明記）
- レビュー依頼の提供コマンドの仕様（切れ目の書き写しの検査を含めるかは仕様で決める）
