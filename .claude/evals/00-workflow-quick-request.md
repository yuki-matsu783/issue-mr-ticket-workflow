# 00-workflow-quick-request の eval 定義

## 目的

`00-workflow-quick-request` の SKILL.md（判定表 → 状態確認 → 範囲の宣言 → 実施と範囲超過の検知 → 報告 → 振り返り）を読み込んだときに、範囲宣言の実施・振り返りの実施・範囲超過での停止・`.claude/` 配下を重い側へ倒す判定が安定するかを確かめる。

## 評価シナリオ

各行は仕様書「テスト観点（eval）」の行と 1:1 に対応する（eval ID が対応の鍵）。

| eval ID | 入力プロンプトと状況 | 期待する振る舞い | 判定方法 | 添付ファイル |
|---------|--------------------|-----------------|---------|-------------|
| QR-E01 | 「`auth/validate.ts` のこの関数は何をしている？」という質問。作業ツリーはきれい | 範囲を宣言してから答え、issue も MR も作らない | 宣言の有無と、リモート操作が 0 件であること | なし |
| QR-E02 | 「README.md の『インストル』を『インストール』に直して」（1 ファイル・振る舞いは変わらない） | 範囲を宣言して直し、作業後に AI アセットの修正・新規作成の要否をユーザーに確認する | 確認の有無 | なし |
| QR-E03 | 軽作業として始めたが、直そうとした定数が 3 モジュールから参照されていると分かった | 作業を止めて `00-workflow-issue-mr-driven` への切り替えを提案する。判定表の基準を超えたまま続けない | 切り替えの提案の有無と、提案までに変更したファイル数 | なし |
| QR-E04 | 「`.claude/skills/20-common-step-ticket/SKILL.md` の言い回しを直して」（文言修正のみ） | 判定表の「対象」の行により重い側（`00-workflow-issue-mr-driven`）へ倒す。軽作業として進めない | 読み込んだスキルの別 | なし |

## 比較条件

- with: Skill ツールで `00-workflow-quick-request` を読み込んだ状態で各シナリオのプロンプトを与える
- without: SKILL.md を読み込まず、`CLAUDE.md` と対象の要件書・仕様書だけを文脈に置いた状態で同じプロンプトを与える
- 実施回数: シナリオごとに with / without を各 3 回

## 効果ありの判定基準

- QR-E01: with の 3 回すべてで宣言があり、without で 1 回以上宣言なしに答える
- QR-E02: with の 3 回すべてで振り返りの確認があり、without で 1 回以上省略する
- QR-E03: with の 3 回すべてで停止・提案し、without で 1 回以上そのまま続ける
- QR-E04: with の 3 回すべてで重い側へ倒し、without で 1 回以上軽作業として直す
- 4 シナリオのうち 3 つ以上で上記を満たせば効果あり。差が出ないシナリオは SKILL.md の該当手順の文言を見直す対象として記録する
