# 20-common-step-worktree スキル 仕様

## 概要・禁止事項

作業ツリーの操作の共通ステップの内部仕様。対応する要件は [00_requirement/skills/20-common-step-worktree.md](../../00_requirement/skills/20-common-step-worktree.md)。

作業ツリーの作成・一覧・合流・片付けの実体はこのスキルの `scripts/worktree.sh`。`git worktree add` / `remove` / `move` / `prune` と、ローカルブランチどうしの `git merge` はどれも `scope.sh` の分類に当たらず `unknown` → **WF204** で拒否される（`10_spec/フック共通仕様.md` §8）。分類を広げずにこれらを通す唯一の道が提供コマンドで、提供コマンド内部の `git` 実行はフックの判定の対象に現れない（同 §7-8）。

**`git merge` の扱いの決着**（DDR `i0050-03`）: 合流を通すために `scope.sh` の `merge` 分類を広げない。`merge-base` の意味は「既定ブランチの取り込み（`git merge origin/<default>`）」のままとし、ローカルブランチの合流は `unknown`（WF204）のままにする。合流は `worktree.sh merge` の中でだけ行われ、マージコミットのメッセージはこのコマンドが与える。

禁止事項:

- `git worktree` / `git merge` / `git branch -d` / `cd` を AI が直接実行して作業ツリーを操作すること（機構が拒否する）
- 衝突の中身を見て一方に寄せて合流を続けること（内容の判断は人が行う）
- `git worktree add --force` / `git checkout --ignore-other-worktrees` で同じブランチを 2 か所に開くこと（公式が safeguard と呼ぶものを外す。DDR `i0050-03`）
- `git worktree remove --force` で未コミットの差分ごと消すこと
- 作業ツリー側の `logs/` に進行状態・承認の記憶・ロック・集計を複製すること
- サブブランチを push すること
- リポジトリの配下（とりわけ `.claude/` の配下）に作業ツリーを作ること

## 呼出条件

- `00-workflow-issue-mr-driven` が並行して進める作業ツリーを用意するとき（`add`）、タスクの切れ目で成果を戻すとき（`merge` → `remove`）
- 実施タスクのスキルが、自分がどの作業ツリーにいるか・他にどの作業ツリーがあるかを確かめるとき（`list`）
- 前提: bash / `git` / `jq` が使えること。本流が feature ブランチをチェックアウトしていること（detached HEAD では `add` / `merge` を行わない）

## IN / OUT

| 操作 | IN | OUT |
|------|----|----|
| 切る（`add`） | 作業ツリーの名前、任意で置き場 | 作られた作業ツリーの置き場・サブブランチ名・次にやること（そのルートを作業ディレクトリにすること） |
| 一覧（`list`） | なし | 本流を含む全作業ツリーの JSON 配列（置き場・ブランチ・本流か・管理対象か・作業中チケット・未コミットの有無） |
| 合流（`merge`） | 対象（作業ツリーの名前かサブブランチ名、または `--all`）、任意でマージコミットの件名 | 合流できた対象とマージコミットの SHA・取り込んだチケットの番号、取り込み済みだった対象、残っている対象、記録のパス。未充足・衝突時: 理由の全件（終了コード非 0） |
| 片付け（`remove`） | 対象（作業ツリーの名前か置き場）、任意で未合流のコミットを無視する指定 | 削除した作業ツリーとサブブランチ。未充足時: 残っているものの一覧（終了コード非 0） |

## IN / OUT サンプル

```bash
bash .claude/skills/20-common-step-worktree/scripts/worktree.sh add t0018
# => OK: 作業ツリーを切った（../issue-mr-ticket-workflow-wt/t0018 / ブランチ feature-50-worktree-parallel-tickets--wt-t0018）。
#    このパスをツールの作業ディレクトリにして始めること（cd は使えない）

bash .claude/skills/20-common-step-worktree/scripts/worktree.sh list
# => [{"path":"/c/.../issue-mr-ticket-workflow","branch":"feature-50-worktree-parallel-tickets","main":true,"managed":false,"doing":[],"dirty":false},
#     {"path":"/c/.../issue-mr-ticket-workflow-wt/t0018","branch":"feature-50-worktree-parallel-tickets--wt-t0018","main":false,"managed":true,"doing":[{"ticket":"0018","type":"investigation"}],"dirty":true}]

bash .claude/skills/20-common-step-worktree/scripts/worktree.sh merge t0018
# => OK: 1 件を合流した（t0018 → 9a1f3c2 / チケット 0018）。記録: logs/worktree-merges.jsonl

bash .claude/skills/20-common-step-worktree/scripts/worktree.sh merge --all
# => WT003: 合流できない。未充足: 本流に作業中チケットが 1 枚（0017） / t0019 に未コミットの変更が 2 件（wip/30_reports/0018-investigation.md, wip/30_reports/0018-investigation.html）

bash .claude/skills/20-common-step-worktree/scripts/worktree.sh remove t0018
# => OK: 作業ツリー ../issue-mr-ticket-workflow-wt/t0018 とブランチ feature-50-worktree-parallel-tickets--wt-t0018 を削除した
```

## 処理フロー

1. 呼び出し元（`00-workflow-issue-mr-driven`）が「並行して進める」と決めたときだけ `add` を呼ぶ。既定は切らない
2. 切った作業ツリーのルートをツールの作業ディレクトリにして、そこでチケットを 1 枚実施する（`cd` は使えないので、作業ディレクトリを切り替えて始める）
3. タスクの切れ目（どの作業ツリーも作業中 0 枚）まで進めたら、本流に戻って `list` で状況を確かめる
4. 本流で `merge` を呼ぶ。未充足・衝突で失敗したら、解消せずに理由をそのまま呼び出し元へ返す
5. 合流できた対象を `remove` で片付ける
6. 合流の記録のパスを、切れ目の報告に含める

## OUT ひな形

テンプレートは持たない。`list` の JSON と合流の記録（下の「合流の記録」）が形の正で、他に定型の成果物を持たない。

## Script 処理

実体は `.claude/skills/20-common-step-worktree/scripts/worktree.sh <subcommand> [args]`。終了コードは成功 0 / 前提・状態の未充足 1 / 引数・環境の誤り 2。出力の最終行は AI が読む結果（`OK:` または `WTxxx:`）。ログは共通 logger。

### 本流かどうかの判定（提供コマンド共通。この節が正）

リポジトリルート直下の `.git` が**ディレクトリなら本流**、**ファイルなら作業ツリー**（`git worktree add` が作る作業ツリーの `.git` は `gitdir: <本流>/.git/worktrees/<名前>` の 1 行を持つファイル）。`git` を呼ばずに `[ -d .git ]` / `[ -f .git ]` で判定できる。

- この判定が「本流」と答える根は、フック共通仕様 §2 の**共有ルート**（`HOOK_SHARED_ROOT`）と同じディレクトリを指す。進行状態・ロック・集計はそこにあり、チケットの採番と push はそこでだけ行う
- `ticket.sh`（`create` の拒否）と `push.sh`（push 前チェック 項目 5）も**この判定を使う**。判定を各コマンドで作り直さない
- 別 clone を使う運用では、その clone のルートも `.git` ディレクトリを持つので「本流」と判定される。これは意図どおりで、別 clone は別のリポジトリとして独立に進行状態を持つ（フック共通仕様 §2 の共有ルートの注記と同じ読み方）

### 共通の入口（すべてのサブコマンド）

1. リポジトリルートへ移れること、`git` と `jq` があること、サブコマンドが `add` / `list` / `merge` / `remove` のいずれかであること、未知のオプション・値の無いオプションが無いことを検査し、いずれかが崩れていれば **WT008**（終了 2）
2. `add` / `merge` / `remove` は本流でのみ実行できる。作業ツリーの中で呼ばれたら **WT001**。`list` はどちらでも実行できる
3. 「管理対象の作業ツリー」= サブブランチ名が `<本流の現在ブランチ>--wt-` で始まるもの。外部の仕組みが作った作業ツリー（Claude Code のサブエージェント隔離が作る `worktree-<名前>` など）は管理対象外で、`merge` / `remove` の対象にできない（`list` には管理対象外として現れる）

### add <名前> [<置き場>]

`<名前>` は英小文字・数字・ハイフンで、先頭は英小文字か数字（`[a-z0-9][a-z0-9-]*`）。`<置き場>` は省略可の位置引数。

1. `<名前>` の形式を検査し、外れていれば WT008。本流の現在ブランチが取れない（detached HEAD）ときも WT008（環境の誤り）
2. 置き場を決める。指定があればそれ、無ければ **`<リポジトリの親ディレクトリ>/<リポジトリ名>-wt/<名前>`**（リポジトリの外）。パスを正規化し、リポジトリルートの配下なら **WT002**（`.claude/**` は `common.protected` なので、作業ツリーの解決に失敗したとき同じ書き込みが保護対象に当たって硬く止まる。その経路を作らない — DDR `i0050-03`）
3. 置き場が既に存在する、親ディレクトリを作れない場合も **WT002**
4. サブブランチ名を **`<本流の現在ブランチ>--wt-<名前>`** と決める。既に同名のブランチか作業ツリーがあれば **WT002**。区切りに `--` を使うのは、feature ブランチの命名（`feature-<issue番号>-<slug>`。slug は英小文字・数字・単一のハイフン — `20-common-step-feature-mr` 仕様）に `--` が現れないため。この形にすることで、**ブランチ名だけで「同じ issue に属する作業ツリーのブランチか」を前方一致で判定できる**
5. `git worktree add -b <サブブランチ名> <置き場> HEAD` を実行する。非 0 なら **WT007**（git の出力を透過）。`--force` は使わない
6. 作業ツリーのルートに **`logs/hooks/` と `logs/sh/` の 2 つだけ**を作る（`mkdir -p`）。**`logs/` の他のもの（`mr.json` / `review-state.json` / `review-history.jsonl` / `merge-state.json` / `push-state.json` / `locks/` / `usage/` / `sessions/`）は作らず、本流からコピーもしない** — これらは共有ルートのものが参照される（フック共通仕様 §5）。`wip/` はブランチの追跡ファイルとしてチェックアウト時に入るので、用意しない
   - **並列実施を行う場合も行わない場合も同じ**である。作業ツリーが 1 つなら三分はすべて同じディレクトリに解決される（フック共通仕様 §5）
7. 置き場・サブブランチ名・「このパスをツールの作業ディレクトリにして始めること（`cd` は使えない — フック共通仕様 §8）」を出力する

### list

1. `git worktree list --porcelain` で作業ツリーの一覧を取る（提供コマンドはフックのホットパスではないので `git` を呼んでよい）
2. 各作業ツリーについて次を集め、JSON 配列で出力する。順序は `git` が返す順（本流が先頭）

| キー | 値 |
|---|---|
| `path` | 作業ツリーのルートの絶対パス |
| `branch` | チェックアウトしているブランチ名（detached なら `null`） |
| `main` | 本流なら `true`（`.git` がディレクトリ） |
| `managed` | サブブランチ名が `<本流の現在ブランチ>--wt-` で始まれば `true` |
| `doing` | `<path>/wip/10_tickets/10_doing/` の各チケットの `{"ticket":"<4 桁>","type":"<ticket_type>"}` の配列（`frontmatter.sh` で読む。0 枚なら空配列） |
| `dirty` | `git -C <path> status --porcelain` が空でなければ `true` |

3. 一覧はリモートに問い合わせない。作業ツリーの数に比例する回数だけ `git` を呼ぶ

### merge <名前> | <サブブランチ名> | --all [-m <件名>]

1. 引数を検査する（対象と `--all` の同時指定、`-m` の値なし、未知のオプションは WT008）
2. 対象を解決する。`<名前>` は `<本流の現在ブランチ>--wt-<名前>` のブランチを持つ作業ツリー、`<サブブランチ名>` はそのブランチ名の作業ツリー。見つからない、または管理対象外なら **WT005**（`list` で確かめるよう案内する）。`--all` は管理対象の作業ツリー全部
3. **前提検査を全対象についてまとめて先に行い、未充足を全件列挙して WT003 で拒否する**（1 件目で止めない。1 つでも落ちたら 1 つも合流しない）:

| # | 項目 | 判定 |
|---|------|------|
| 1 | 本流で実行している | 共通の入口 2（作業ツリーからの実行は WT001 で先に止まる） |
| 2 | 本流に未コミットの変更が無い | 本流の `git status --porcelain` が空 |
| 3 | 本流にタスクの切れ目が来ている | 本流の `wip/10_tickets/10_doing/` が空 |
| 4 | 対象に未コミットの変更が無い | `git -C <対象> status --porcelain` が空 |
| 5 | 対象にタスクの切れ目が来ている | `<対象>/wip/10_tickets/10_doing/` が空 |
| 6 | 対象が同じ issue に属するブランチである | サブブランチ名が `<本流の現在ブランチ>--wt-` で始まる |

   - 項目 3・5 が**合流をタスクの切れ目に固定する**判定である。切れ目でだけ合流すれば、合流先の `10_doing/` が 2 枚になることは構造的に起きない（**並列実施を行う場合**の WF207 の扱いは `workflow-guard` 仕様が持つ）。また、作業中チケットが残ったまま合流すると、そのチケットの差分の基準点が合流前のコミットを指したままになり、相手の成果が丸ごと「許可範囲外の差分」として現れる
4. 対象ごとに順に合流する。`git merge --no-ff -m "<件名>" <サブブランチ名>`
   - 件名の既定は `chore: 作業ツリー <名前> の成果を合流する`。`-m` が与えられていればその値を使う（メッセージ規約の検査は `commit.sh` が持つが、マージコミットは `commit.sh` を通らないので、**この既定がそのまま規約に合う形**である）
   - `git` が「既に取り込み済み」を返したときは、合流せず「取り込み済み」として**成功に数える**（同じ合流を二度呼んでも結果が変わらない）
   - **衝突したとき**（終了が非 0 で、`git ls-files --unmerged` が空でない）は `git merge --abort` で合流前の状態に戻し、衝突したファイルの一覧を出して **WT004** で終える。`--all` の残りの対象は処理しない。**衝突の中身を見て一方に寄せない**
   - 衝突以外の失敗は、可能なら `git merge --abort` してから **WT007**（git の出力を透過）
5. 合流を**試みた**対象ごとに 1 行を記録する（下の「合流の記録」）。成功・取り込み済み・中断のいずれでも残す
6. 出力: 合流できた対象とマージコミットの SHA と取り込んだチケットの番号（`git diff --name-only <合流前 HEAD>..HEAD -- wip/10_tickets/` から 4 桁の連番を拾う）、取り込み済みだった対象、まだ残っている対象、記録のパス

### remove <名前> | <置き場> [--force]

1. 引数を検査する（未知のオプションは WT008）
2. 対象を解決する。見つからない、または管理対象外なら **WT005**
3. 前提検査を行い、未充足を全件列挙して **WT006** で拒否する:
   - 対象に未コミットの変更が無い（`git -C <対象> status --porcelain` が空）。**`--force` でも飛ばせない**（消すと復旧できないため。`git worktree remove --force` は使わない）
   - 対象のブランチに、本流のブランチへ合流していないコミットが無い（`git rev-list --count <本流の現在ブランチ>..<サブブランチ名>` が 0）。**`--force` を付けたときだけ飛ばす**（飛ばすときは失われるコミット数を出力してから進む）
4. `git worktree remove <置き場>` を実行する。非 0 なら **WT007**
5. サブブランチを消す（`git branch -d <サブブランチ名>`。`--force` のときは `-D`）。非 0 なら **WT007**
6. `git worktree prune` を実行して、消えた作業ツリーの登録を残さない
7. 削除した作業ツリーとサブブランチを出力する

### 合流の記録

置き場は**共有ルート**の `logs/worktree-merges.jsonl`（フック共通仕様 §5 の表に登録）。1 回の合流の試みにつき 1 行を `>>` で追記する（追記専用。1 行は 4 KB 未満に保ち、超える分は `conflicts` を切り詰めて末尾に `…` を付ける — 同 §5 の並行書き込みの規則）。

```json
{"ts":"2026-09-05T14:02:11+09:00","worktree":"t0018","path":"/c/.../issue-mr-ticket-workflow-wt/t0018","branch":"feature-50-worktree-parallel-tickets--wt-t0018","into":"feature-50-worktree-parallel-tickets","result":"merged","merge_commit":"9a1f3c2","tickets":["0018"],"conflicts":[]}
```

- `result` は `merged`（合流した）/ `up-to-date`（取り込み済みで何もしなかった）/ `aborted`（衝突で中断した）の 3 値
- `aborted` のとき `merge_commit` は空文字、`conflicts` に衝突したファイルのルート相対パスが入る
- 置き場を共有ルートにするのは、①合流は issue に属する事実で、issue も MR も 1 つしか無い ②作業ツリーを片付けた後も残らなければならない（要件「規約: 合流の記録」）ためである。判定記録（`logs/hooks/decisions.jsonl`）に相乗りさせないのは、あちらが**フックの判定**の記録で、書く側が全フックに限られているため（フック共通仕様 §5）

### エラー識別子

| ID | 条件 | メッセージに含める内容 |
|----|------|----------------------|
| WT001 | 本流でないチェックアウトで `add` / `merge` / `remove` を実行した | 現在の作業ツリーの置き場と本流の置き場。本流を作業ディレクトリにして実行し直すことの案内 |
| WT002 | `add` の置き場・名前を使えない（置き場がリポジトリの配下 / 既に存在する / 親を作れない / 同名の作業ツリーかブランチが既にある） | どれに当たったか、既定の置き場、既にある対象。別の名前か置き場を指すか、既存をそのまま使うことの案内 |
| WT003 | 合流の前提検査の未充足 | 未充足の全件（項目名と、作業中チケットの番号・未コミットのファイル名・対象のブランチ名）。タスクの切れ目まで進めるか、コミットしてから再実行することの案内 |
| WT004 | 合流で自動的に解けない衝突が出た（中断して合流前に戻した） | 衝突したファイルの一覧と、`--all` の残りを処理していないこと。**衝突の解消は人が行う**こと（AI は寄せない） |
| WT005 | 対象の作業ツリーが見つからない、または管理対象外 | 指定された対象と、`list` の結果（管理対象の一覧）。正しい対象を指すことの案内 |
| WT006 | 片付けの前提未充足（未コミットの差分 / 未合流のコミット） | 残っているファイルと未合流のコミット数。コミットするか合流してから片付けることの案内（未コミットの差分は `--force` でも消さないこと） |
| WT007 | git の操作そのものの失敗（`worktree add` / `merge` / `worktree remove` / `branch -d` / `worktree prune` が非 0） | git の出力そのまま。安全装置を外す指定（`--force` / `--ignore-other-worktrees`）で押し通さないことの案内 |
| WT008 | 引数・環境の誤り（終了 2）: 不明なサブコマンド・不明な引数・値の無いオプション・`<名前>` の形式違反・対象と `--all` の同時指定・`git` / `jq` 不在・detached HEAD・リポジトリルートに移れない | 正しい呼び方（`usage`）または不足しているもの |

WT002 が 4 つの原因をまとめているのは、受け取った側の対処がどれも「別の名前か置き場を指す（または既存をそのまま使う）」の 1 つだからである（1 番号 1 原因の原則は「対処が違うなら分ける」の意味 — `20-common-step-spec` 仕様）。WT001（本流へ移る）・WT003（切れ目まで進める）・WT006（コミットするか合流する）・WT007（git の出力を読む）は対処が別なので分けている。

|--------------------|---------|
