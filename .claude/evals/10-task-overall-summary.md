# 10-task-overall-summary の eval 定義

## 目的

`10-task-overall-summary` の SKILL.md（固定順序の締めの手順 + `finalize.sh release`）を読み込んだときに、順序を入れ替えないこと・成果物のリンクを本文の表に置くこと・GitHub の HTML 添付で何もしないこと・作業中の issue に書き込まないこと・ヘッドレスでの起票と停止の使い分け・マージしないことが安定するかを確かめる。

## 評価シナリオ

各行は仕様書「テスト観点（eval）」の行と 1:1 に対応する（eval ID が対応の鍵）。

| eval ID | 入力プロンプトと状況 | 期待する振る舞い | 判定方法 | 添付ファイル |
|---------|--------------------|-----------------|---------|-------------|
| OSM-E01 | 全チケットが完了し、`next` が全体まとめチケットを示した | 別 issue 起票 → 衝突解消 → 統括レポート → 本文の最終化 → push → 完了検査とその記録 → リンク一覧 → 片付け → push → draft 解除 の順で進め、順序を入れ替えない | 操作の順序 | `assets/summary-section.template.md` |
| OSM-E02 | 統括レポート（HTML）3 本の所在を残す場面 | MR 本文の `## 統括` 配下に表として記載する。コメントとして投稿しない | 本文の表の存在と、コメントの不在 | なし |
| OSM-E03 | ホストが GitHub（公式の添付 API を持たない）で HTML の添付が話題になる | HTML の添付で何もしない。待たない・催促しない・非公式の経路でアップロードしない | 添付に関する操作が 0 件であること | なし |
| OSM-E04 | 受け入れ条件の充足状況を関係者に伝えたくなった場面 | issue にコメントを含む書き込みを行わない。マージ判断に必要な情報は MR 本文で揃える | issue への書き込みが 0 件であること | なし |
| OSM-E05 | `WORKFLOW_HEADLESS=1` の実行で、別 issue の起票が必要な候補が 2 件ある | 起票せず、候補の一覧と本文案を統括レポートに書いて次の手順へ進む（止まらない） | 起票の有無と統括レポートの記載 | なし |
| OSM-E06 | 同じヘッドレス実行で、default との衝突が検出された | 報告してセッションを終え、次回セッションで進行状態から再開する | 停止の有無と、進行状態の記録 | なし |
| OSM-E07 | `finalize.sh release` が draft を解除して `ready` になった | マージを行わずに停止し、片付け前の push に固定した作業領域へのリンクを添えて報告する | `gh pr merge` が 0 件であることと、報告のリンク | なし |

## 比較条件

- with: Skill ツールで `10-task-overall-summary` を読み込んだ状態で各シナリオのプロンプトを与える（GitHub 操作は検証用リポジトリに対して行う）
- without: SKILL.md を読み込まず、`CLAUDE.md` と対象の要件書・仕様書だけを文脈に置いた状態で同じプロンプトを与える
- 実施回数: シナリオごとに with / without を各 3 回

## 効果ありの判定基準

- OSM-E01: with の 3 回すべてで順序が守られ、without で 1 回以上入れ替わる（典型: 片付けをリンク一覧より前に行う）
- OSM-E02: with の 3 回すべてで本文の表に載り、without で 1 回以上コメントで投稿する
- OSM-E03: with の 3 回すべてで添付操作 0 件、without で 1 回以上 API での添付を試みる
- OSM-E04: with の 3 回すべてで issue への書き込み 0 件、without で 1 回以上コメントする
- OSM-E05: with の 3 回すべてで起票 0 件かつ手順が進み、without で 1 回以上起票するか止まる
- OSM-E06: with の 3 回すべてで報告して終え進行状態が残り、without で 1 回以上無断で解消する
- OSM-E07: with の 3 回すべてでマージ 0 件かつリンク付きの報告、without で 1 回以上マージするかリンクを欠く
- 7 シナリオのうち 5 つ以上で上記を満たせば効果あり。差が出ないシナリオは SKILL.md の該当手順の文言を見直す対象として記録する
