# 10-task-implementation-plan の eval 定義

## 目的

`10-task-implementation-plan` の SKILL.md（計画タスクの共通手順 + 実装計画の固有手順）を読み込んだときに、テストが通る単位でステップを区切ること・テスト ID を機械的に抜き出すこと・テスト ID が無いときの差し戻し・依存するテストを許可範囲に入れることが安定するかを確かめる。

## 評価シナリオ

各行は仕様書「テスト観点（eval）」の行と 1:1 に対応する（eval ID が対応の鍵）。

| eval ID | 入力プロンプトと状況 | 期待する振る舞い | 判定方法 | 添付ファイル |
|---------|--------------------|-----------------|---------|-------------|
| IMP-E01 | アプリの仕様書（テストシナリオ 6 件）を入力に実装計画を書く | 実装ステップをテストが通る単位で区切り、計画書の記述順とチケットの実行順を一致させる | ステップの並びと `predecessors` の一致 | `assets/implementation-plan.template.md` |
| IMP-E02 | テスト方針の節を書く場面 | 仕様書からテスト ID を機械的に抜き出し、抜き出しの件数と割付表の行数が一致することを書く | 抜き出しのコマンドと件数の記載 | なし |
| IMP-E03 | 仕様書のテストシナリオにテスト ID が振られていない | 推測で補わず、不足を結果報告に書いて設計フェーズへの差し戻しを提案する | 結果報告の記載と、実装チケットの有無 | なし |
| IMP-E04 | 関数名を変える修正を計画する場面（旧名がテストの期待値に現れる） | それを入力・期待値に持つテストを検索で洗い出し、同じチケットの書き込み範囲に含める | チケットの `allow.write` と検索の根拠 | なし |

## 比較条件

- with: Skill ツールで `10-task-implementation-plan` を読み込んだ状態で各シナリオのプロンプトを与える
- without: SKILL.md を読み込まず、`CLAUDE.md` と対象の要件書・仕様書だけを文脈に置いた状態で同じプロンプトを与える
- 実施回数: シナリオごとに with / without を各 3 回

## 効果ありの判定基準

- IMP-E01: with の 3 回すべてで記述順と実行順が一致し、without で 1 回以上入れ替わる
- IMP-E02: with の 3 回すべてで抜き出しコマンドと件数の一致が書かれ、without で 1 回以上目視で拾う
- IMP-E03: with の 3 回すべてで差し戻しを提案し実装チケットを作らず、without で 1 回以上推測で ID を補う
- IMP-E04: with の 3 回すべてで依存するテストが `allow.write` に入り、without で 1 回以上漏れる
- 4 シナリオのうち 3 つ以上で上記を満たせば効果あり。差が出ないシナリオは SKILL.md の該当手順の文言を見直す対象として記録する
