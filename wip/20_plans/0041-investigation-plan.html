この計画で何をするか

cmdpos.sh を Python の shlex に寄せられるかを設計フェーズが判断できるよう、shlex の守備範囲・現行実装との差分・ホットパスの起動コストの 3 つを実測で確かめる段取りを決める。

決めたこと

  • 観点は 5 つ（A-1 出力 10 項目の切り分け / A-2 扱えない構文 5 種 / A-3 現行との差分 / B-1 起動コストの実測 / B-2 実行環境の前提）
  • 調査チケットは 2 枚（0042 が A 系、0043 が B 系）。互いに依存させず、同じ type なのでレビュー境界は 1 回
  • 計測スクリプトと shlex 版の試作は wip/tmp/ に置き、追跡ファイルには残さない
  • Windows / Git Bash での python3 の可用性は測らない。この実行環境から測れないため、前提の列挙で代える

対象と範囲

観点問い効く判断点 / 根拠
A-1shlex は cmdpos.sh の出力 10 項目のうちどれをそのまま供給できるかshlex の置き場 / 受け入れ条件 1
A-2扱えない構文はどれか（ヒアドキュメント本文・$( ) とバッククォートの入れ子・&> と 2>&1・コメント・PowerShell のヒアストリングと行継続）shlex の置き場 / 受け入れ条件 1

方法とステップ

  1. 1

    出力 10 項目の対応表を作る（A-1）

    cmdpos.sh ヘッダの公開 API の定義を表に起こし、shlex.shlex(punctuation_chars=True) の出力と 1 項目ずつ突き合わせる。「shlex が供給する / 追加実装が残る」の 2 値で埋める。

  2. 2

    扱えない構文の最小入力を作る（A-2）

    5 つの構文それぞれに最小入力を用意し、shlex に食わせて実際の出力を記録する。落ちるのか、黙って違う結果を返すのかを区別して書く。

  3. 3

    現行実装との差分を取る（A-3）

    test_cmdpos.sh のテスト入力を流用し、wip/tmp/ の差分スクリプトで現行 cmdpos.sh と shlex 版の試作の出力を比べる。試作は差分を取れる最小限に留める。

  4. 4

    起動コストを測る（B-1）

    wip/tmp/ の計測スクリプトで、bash の cmdpos_parse 1 回と python3 起動 1 回をそれぞれ 50 回測り中央値を取る。5 本同時起動は 1 本あたりの差 × 5 で見積もる。

  5. 5

    実行環境の前提を列挙する（B-2）

    読み取りのみ。インタプリタの解決方法・起動オプション・import するモジュール・DDR i0001-14 を満たすために必要になる項目を並べる。

答えが出なかった問いは、理由付きで各レポートの「残課題」に残す。設計フェーズはこの 2 本を材料に、置き場を 3 案（本番置換 / テストの照合役 / 採用しない）から選ぶ。

0045 を差し込んだ経緯

当初は 0042（A 系）と 0043（B 系）の 2 枚だけを置いた。0042 に着手して python3 wip/tmp/a2_syntax.py を実行したところ、フックが WF204（分類外のコマンドは既定拒否）で拒否した。scope-limits.json の commands.build-test は npm の 6 コマンドしか列挙しておらず、scope.sh の分類は列挙されたコマンドとの前方一致で決まるため、チケット側で build-test を宣言しても python3 は分類外のままになる。

迂回せず、許可範囲を広げる実装チケット 0045 を先に差し込むことをユーザーと合意した（2026-09-03）。0042 は取り消し、同内容を 0046 として起こし直した。フェーズ順（設計 → 実装）から外れるが、調査を進めるための前提整備であり、変更の理由は 0045 の DDR に残す。
