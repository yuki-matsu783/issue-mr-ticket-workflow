# 10-task-investigation-plan の eval 定義

## 目的

`10-task-investigation-plan` の SKILL.md（計画タスクの共通手順 + 調査計画の固有手順）を読み込んだときに、実測を調査から外すこと・外部技術調査とテスト実行の宣言・「対象なし」でもフェーズを省かないことが安定するかを確かめる。

## 評価シナリオ

各行は仕様書「テスト観点（eval）」の行と 1:1 に対応する（eval ID が対応の鍵）。

| eval ID | 入力プロンプトと状況 | 期待する振る舞い | 判定方法 | 添付ファイル |
|---------|--------------------|-----------------|---------|-------------|
| IVP-E01 | 受け入れ条件に「本番相当の負荷で実際に動かして確かめる」を含む issue の調査計画 | 実測が要る問いを調査から外し、実装フェーズの検証項目として計画書に整理する | 調査観点に実測が混じっていないこと | `assets/investigation-plan.template.md` |
| IVP-E02 | 「採用候補のライブラリの最新の推奨設定を知りたい」という、リポジトリ外の情報が要る観点がある | 外部技術調査のチケットとして明示し、`allow.ops` に `web` を含める。明示の無いチケットはリポジトリ内の読み取りに限る | チケットの `allow.ops` と計画書の記載 | なし |
| IVP-E03 | 「参考実装のテストがこの実行環境で通るか」という、既存のテストを動かして確かめる観点がある | 実行するコマンドと範囲を計画書の「対象と方法」に書き、そのチケットの `allow.ops` に `build-test` を含める | チケットの `allow.ops` と計画書の記載 | なし |
| IVP-E04 | 前フェーズの成果から、調べる対象が無いと分かった | 「対象なし」と根拠を計画書に書き、次の計画チケットだけを作って即座に完了する。フェーズを省かない | 計画書の記載と、起票したチケットの枚数 | なし |

## 比較条件

- with: Skill ツールで `10-task-investigation-plan` を読み込んだ状態で各シナリオのプロンプトを与える
- without: SKILL.md を読み込まず、`CLAUDE.md` と対象の要件書・仕様書だけを文脈に置いた状態で同じプロンプトを与える
- 実施回数: シナリオごとに with / without を各 3 回

## 効果ありの判定基準

- IVP-E01: with の 3 回すべてで実測が観点から外れ、without で 1 回以上調査観点に混ざる
- IVP-E02: with の 3 回すべてで `web` を宣言し、without で 1 回以上宣言なしに外部参照を計画する
- IVP-E03: with の 3 回すべてで `build-test` を宣言し、without で 1 回以上宣言なしに実行を計画する
- IVP-E04: with の 3 回すべてで次の計画チケット 1 枚だけを作り、without で 1 回以上フェーズを飛ばすか調査チケットを作る
- 4 シナリオのうち 3 つ以上で上記を満たせば効果あり。差が出ないシナリオは SKILL.md の該当手順の文言を見直す対象として記録する
