# 10-task-implementation-exec — テストを先に書いて仕様どおりに動かす

共通手順の禁止事項（`10-task-investigation-exec` の冒頭が正）に加えて、設計文書・実装計画書を書き換えない（食い違いは「仕様からの逸脱」に記録し、書き戻しは設計反映フェーズ）。テストを通すために期待値を仕様と違う値に変えない（変えるなら逸脱として記録し見てほしい点へ）。許可範囲外のファイルへの変更を残さない（理由を作業ログに残して基準点の状態に戻す）。テストを書かずに実装しない。失敗を確認せずに実装に進まない。担当チケットのステップだけを実施し、先取りしない。

## 目的

仕様書のテストシナリオを合否の基準にして、ステップ単位で動くコードを積む。仕様とコードの食い違いは記録に残し、正史の修正は後段のフェーズに委ねる。

- 要件: `.claude/docs/00_requirement/skills/10-task-implementation-exec.md`
- 仕様（正。固有手順・OUT ひな形）: `.claude/docs/10_spec/skills/10-task-implementation-exec.md`
- 処理の共通手順（正）: `10-task-investigation-exec` の「実施タスクの共通手順（正）」

## 手順

共通手順（入力の確認 → 1 枚ずつ着手 → 実施 → レポートに追記 → コミットと完了 → 次へ）は `10-task-investigation-exec` に従う。実施（共通手順 3）の固有部分は次のとおり。

- ステップごとに **テストを先に書く → 実行して失敗を確認する → 実装する → 通す** の順で進める。失敗の確認結果（コマンドと要約）を作業ログに残す
- テスト側を直した（期待値・前提を変えた）ときは理由を作業ログ「仕様からの逸脱」に記録する。仕様書とコードの実態が食い違って実装できないときも同様に記録し、**仕様書は直さない**
- ステップの完了ごとに `git diff --stat <基準点>` で差分が許可範囲内にあることを確認する。範囲外の変更があれば理由を作業ログに書いて `git checkout <基準点> -- <path>` で戻し、必要なら別チケット・別 issue 候補として結果報告に載せる
- 計画に無い変更が要ると分かったら、その理由と最小の変更を作業ログに記録して進め、見てほしい点に「計画外の変更」として挙げる（計画書は直さない）
- 既存テストが通らなくなったら原因を切り分ける。自分の変更が原因なら直し、既存の不具合なら「想定と異なった点」に記録して見てほしい点へ回す
- 完了前に、チケットのテスト ID がすべて通ること・既存テストが通ることを実行して確認し、コマンドと結果を作業ログに残す
- **見てほしい点の固定項目**: テスト結果（失敗 → 成功の記録・失敗ケースの網羅）/ 逸脱一覧の妥当性 / 計画外の変更 / 許可範囲外の差分が無いこと

## OUT ひな形

このスキルは固有のテンプレートを持たない。`20-common-step-report-view` の `assets/report.template.md`（と `report.template.html`）をそのまま使い、次を含める。変更したファイルの一覧（ステップ・仕様書の節との対応）/ テスト結果（テスト ID × 結果・実行コマンド・失敗ケースの有無）/ 仕様からの逸脱の一覧（設計反映で書き戻すべき点）/ 想定と異なった点（計画外の変更・既存の不具合）/ 残課題を含める。

## エラー時の対処

| 状況 | 対処 |
|------|------|
| 仕様書とコードの実態が食い違う | 仕様書を直さない。「仕様からの逸脱」に記録し、設計反映フェーズへ回す |
| テストが通らない | 期待値を仕様と違う値に変えない。原因を切り分け、変えるなら逸脱として記録する |
| 許可範囲外に変更が出た | 理由を作業ログに書き、`git checkout <基準点> -- <path>` で戻す。必要なら別チケット候補として報告する |
| 計画に無い変更が要る | 計画書を直さない。理由と最小の変更を作業ログに残し、見てほしい点に挙げる |
| 既存テストが落ちた | 自分の変更が原因なら直す。既存の不具合なら「想定と異なった点」に記録して見てほしい点へ |
| 共通手順で止まった（TK005 / RV00x / 書き込み拒否） | `10-task-investigation-exec` の「エラー時の対処」に従う |
