# i0009-70. 拒否に倒す設計は、実際に踏む状況と拒否理由の噛み合いまで含めて設計する

## 背景

`block-chmod` は「実行体を特定できない段があり、かつコマンド全体に禁止語がある」とき拒否側に倒す。0036 で判定軸を「復元」から「難読化の検出」へ変えたとき、過剰拒否を**代償として明示的に受け入れた**。ただし頻度は測れていないと記録していた（0036 の r1）。

代償は**登録から 3 回目の Bash 呼び出し**で現実に出た。踏んだのは

```
cat > wip/tmp/dod28.py <<'PYEOF' … PYEOF
```

の形で、ヒアドキュメントの中身には DoD の根拠として引用した拒否理由の文字列（`chmod`）が入っていた。`cmdpos.sh` はクォート・コメント・**ヒアドキュメント本文**の 3 つを区別せずプレースホルダ `_` に潰すので、`_bc_exe_unknown` が本文由来の `_` を難読化と読む。ヒアドキュメント本文は実行位置ですらない（bash は決して実行しない）のに、実行体を特定できない段として数えられていた。再現は 4 形すべて（`<<'PY'` / `<<PY` / `<<-PY` / `<< PY`）で一致し、ヒアドキュメントを含むコマンドは必ず実行体 `_` の段を作ると分かった。

より重かったのは誤検知そのものではなく、**拒否理由が状況とまったく噛み合っていなかった**ことである。表示されたのは

> 禁止コマンド 'chmod' の実行。実行権限の変更は不要で、スクリプトは 'bash <パス>' で実行する。権限変更が本当に必要なら、迂回せずユーザーに提案すること

文書に `chmod` と書いただけの読み手にとって、この文は次の一手を 1 つも示していない。しかもこのプロジェクトはヒアドキュメントで一時スクリプトを書く運用で、かつ `chmod` について書く文書を大量に作るので、**踏み続ける構造**だった。

## 決定

- **拒否に倒す判定を設計するとき、拒否理由の文面を「正しい拒否のとき」だけでなく「代償として受け入れた過剰拒否のとき」でも読めるように書く**
- **縮退して拒否した**（判定の材料が揃わないので拒否側に倒した）ときは、**何が判定を妨げたか**を理由に添える（ヒアドキュメント・変数展開・クォート・コード文字列など）。「禁止のものをやろうとした」と断定しない
- **代償を受け入れる判断には、その代償を踏む頻度の見積もりを添える**。見積もれないなら、見積もる手段（実測の予定）を添える
- **過剰拒否を踏んでも迂回しない**。別のシェル構文で同じことをする・語を分割して書く・`WORKFLOW_<NAME>_ENFORCE=0` を立てる、はいずれも拒否の回避。0028 では同じ内容を Write ツール（シェルをまったく起動しない別の道具）で書いた
- **踏んだその場で判定を直さない**。範囲外の変更として別チケットに立て、元のチケットの目的を守る

## 理由

- **拒否は読み手への指示である**。止めるだけなら判定でよく、理由を書くのは次の一手を伝えるため。噛み合わない理由は、書いていないのと同じかそれ以下（誤った一手を促す）
- **縮退の拒否と本来の拒否は、読み手から見て別の出来事**。同じ文面を出すと、読み手は自分が禁止されたことをしたと信じ、実際にはしていないので直しようがない。文面を分けることは、判定の内部状態を読み手に見せることでもある
- **代償の見積もりが無いと、代償かどうかを判断できない**。「まれに起きる」と「3 回に 1 回起きる」は同じ設計判断の名前で呼べない。0036 の判断は「頻度は測れていない」まま受け入れており、実測は「登録から 3 回目」だった。頻度の欄が空のまま承認が通る形になっていたのが構造的な問題
- **迂回を許すと機構の意味が消える**。過剰拒否は仕様の欠陥として直すもので、その場で回避してよいものではない。回避が習慣になると、正しい拒否も回避される
- **踏んだ場で直さないのは、範囲の統制のため**。0028 の目的は「登録方式と deny の効き方を 1 本で測る」で、判定ロジックの変更を混ぜると、測定の結果がどの版のものか分からなくなる

## 却下した案

- **過剰拒否を許容し、拒否理由を一般化する**（「拒否側に倒した」とだけ書く）: 正しい拒否のときの案内（`bash <パス>` で実行する）まで失われる。分けて書くべきで、まとめて薄くするのではない
- **`chmod` を禁止語（`blocked-commands.txt`）から外す**: 判定の欠陥を設定で隠すことになり、他の禁止語を足したときに同じことが起きる
- **判定を「禁止語がコマンド全体にあるか」から「実行体が禁止語か」だけに戻す**: 0036 が判定軸を変えた理由（難読化の検出）が消える。`"chmod"` や `/usr/bin/chmod` で素通りする
- **踏んだ 0028 の中で直す**: 上記のとおり測定の範囲が崩れる。追加チケット（0037）として 0029 の前に置いた
