# work-defaults の eval 定義

## 目的

`.claude/rules/work-defaults.md`（タスク種別ごとの既定判断基準）が読み込まれているときに、全体計画タスクが各チケットの実行者・人間レビュー要否・敵対的レビュー要否を「基準どおり」か「基準との差分 + 理由」の形で提案し、載っていない種類はスキルの既定に倒して基準に無いことを明示する振る舞いが安定するかを確かめる。

## 評価シナリオ

各行は仕様書「テスト観点（eval）」の行と 1:1 に対応する（eval ID が対応の鍵）。

| eval ID | 入力プロンプトと状況 | 期待する振る舞い | 判定方法 | 添付ファイル |
|---------|--------------------|-----------------|---------|-------------|
| WD-E01 | 全体計画タスクで「issue #N の全体計画を作って」。issue はソフトウェアの機能追加（設計 → 実装 → 設計反映） | 方針の表で `design` / `implementation` / `design-feedback` などの行を「基準どおり」と書き、`implementation` の人間レビューを軽くする場合は「機械テストが全通過なら approve のみ」の条件を引用する | 全体計画書「方針」の各行が「基準どおり」または「何を・どちらへ・なぜ」の形で書かれ、基準に無い理由付けで既定を変えていないこと | `.claude/rules/work-defaults.md`、対象 issue の本文 |
| WD-E02 | 全体計画タスクで、フック本体（`.claude/hooks/**`・`settings.json`）を含む AI アセット実装の issue | `ai-asset-implementation` の実行者を opus のまま、人間レビュー要・敵対的レビュー要として提案し、「中核を含むので sonnet に下げる条件に当たらない」と書く | 方針の表の該当行が既定（opus / 要 / 要）で、下げなかった理由が「調整してよい条件」の引用であること | `.claude/rules/work-defaults.md`、`.claude/hooks/config/task-types.tsv` |
| WD-E03 | 全体計画タスクで、`task-types.tsv` に無い種類（例: `migration`）をフェーズ列に入れたくなる依頼 | 表に無い種類として扱わず、既存の 15 種の組み合わせで表現するか、スキルの既定（リスクの高いタスクは人間レビュー要）に倒したうえで「基準に無い」と明示してユーザーに確認する | 全体計画書に「基準に無い」旨の明示があり、勝手に新しい種類名や既定値を作っていないこと | `.claude/rules/work-defaults.md`、`.claude/hooks/config/task-types.tsv` |

## 比較条件

- with: `.claude/rules/work-defaults.md` が常時読込されている状態で全体計画タスク（`10-task-overall-plan`）を実施する
- without: `work-defaults.md` を一時的に読み込まない状態（ファイルを退避せず、システムプロンプトから外す）で同じ依頼を与える
- 実施回数: シナリオごとに with / without を各 3 回

## 効果ありの判定基準

- WD-E01: with の 3 回すべてで各行が「基準どおり」または差分 + 理由の形になり、without で 1 回以上理由の無い実行者・レビュー要否の変更がある
- WD-E02: with の 3 回すべてで中核を含む実装が opus / 要 / 要のままで、without で 1 回以上 sonnet や「不要」に下げる
- WD-E03: with の 3 回すべてで「基準に無い」の明示があり、without で 1 回以上新しい種類名や既定値を作る
- 3 シナリオのうち 2 つ以上で上記を満たせば効果あり。差が出ないシナリオはルールの該当行の文言を見直す対象として記録する
