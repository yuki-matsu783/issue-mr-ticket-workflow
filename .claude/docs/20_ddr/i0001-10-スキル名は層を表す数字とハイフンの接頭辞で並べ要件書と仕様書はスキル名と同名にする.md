# i0001-10. スキル名は層を表す数字とハイフンの接頭辞で並べ、要件書と仕様書はスキル名と同名にする

## 背景

参考実装 agent-workflow のスキル名は `workflow-*` / `work-*` / `task-*` の接頭辞で層を表していたが、`.claude/skills/` をディレクトリ一覧で見ると辞書順（task → work → workflow）に並び、層の上下関係が読み取れない。要件定義書・仕様書は `skill-<スキル名>.md` という別の接頭辞を持ち、スキル名との対応を目で追う必要があった。ユーザーからは `00_workflow_` / `10_work_` / `20_task_` を頭に付けて見やすくする提案があった。

## 決定

- スキルのディレクトリ名（= スキル名）は層を表す接頭辞で始める: ワークフロー層 `00-workflow-<名前>`、ワーク層 `10-work-<名前>`、タスク層 `20-task-<名前>`
- 区切りはアンダースコアではなく**ハイフン**にする（`00-workflow-issue-mr-driven`）。Agent Skills 仕様で `name` は「小文字英字・数字・ハイフンのみ、親ディレクトリ名と一致」と定められており、アンダースコアは使えない。数字始まりは許される
- 要件定義書と仕様書のファイル名はスキル名そのものにする（`.claude/docs/00_requirements/00-workflow-issue-mr-driven.md`、`.claude/docs/10_spec/00-workflow-issue-mr-driven.md`）。`skill-` の接頭辞は付けない
- 横断的な文書（特定のスキルに紐づかないもの）は従来どおり日本語名で置く（`自己改善ワークフロー機構.md` 等）
- 既存の 2 スキル（`workflow-issue-mr-driven` / `workflow-quick-request`）はこの決定に合わせて改名した

## 理由

- `ls .claude/skills/` の結果がそのまま「ワークフロー → ワーク → タスク」の層順に並び、機構の構造が一覧から読める
- 要件書・仕様書・スキルの 1 : 1 : 1（i0001-01 と要件定義書「文書の構成」）が、ファイル名の一致で機械的に確認できる
- 数字の接頭辞に 10 刻みの余白を持たせ、将来の層の追加（例: エージェント定義の層）に対応できる

## 却下した案

- **`00_workflow_` のようにアンダースコア区切りにする（提案の原案）**: ディレクトリ名としては読みやすいが、Agent Skills 仕様の `name` 制約に反し、Claude Code のスキルとして正しく扱われる保証が無い。意図（並び順で層を表す）はハイフンで同じく満たせる
- **接頭辞を付けず参考実装の `workflow-` / `work-` / `task-` のままにする**: 変更が不要だが、一覧の並びが層順にならない
- **要件書・仕様書に `skill-` 接頭辞を残す**: 横断文書と区別しやすいが、横断文書は日本語名なので接頭辞が無くても区別でき、スキル名との一致が崩れる

## 影響

- `CLAUDE.md`「作業の振り分け」「スキルの 3 層構造」の表
- 要件定義書・DDR 内のスキル名の参照をすべて新しい接頭辞に置き換えた
- 今後作るスキルはすべてこの接頭辞で命名する。スキル作成の task スキルはこの規則を手順に含める
