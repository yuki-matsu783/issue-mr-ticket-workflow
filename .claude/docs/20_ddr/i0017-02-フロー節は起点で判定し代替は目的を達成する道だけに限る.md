# i0017-02. フロー節は起点で判定し、代替フローは目的を達成する道だけに限る

## 背景

既存の要件定義書 45 件では、受け入れ基準の節の順序（メイン → 代替 → 例外）は全件守られている一方、どの記述をどの節に入れるかの基準が無い。結果として、性質が同じ記述が書によって別の節に入っている。

`20-common-step-feature-mr` では「同名のブランチが既に存在する → 上書きせず別案を返す」が代替フロー、「未コミットの変更がある状態で呼ばれた → ブランチを作らず返す」が例外フローにある。どちらも前提が満たされず処理を進めずに返す点で同じ性質を持つ。

さらに、同じ代替フロー節の中に終わり方の違うものが同居している。同書の代替フロー 2 項目のうち、片方（ブランチ名の衝突）は停止して呼び出し元の判断を仰ぎ、もう片方（open な MR が既にある）は別の道で目的を達成して完了する。節名からどちらか判別できない。

## 決定

- 記述の置き場は、次を上から当てて**最初に当たった**節に決める
  1. その道は、目的を達成するすべての実行が通るか → メインフロー
  2. その道に入る起点は正常か（呼び出し元の入力・選択の違い / 対象が既に目的の状態にある / 複数の正しい入力形式）→ 代替フロー
  3. その道に入る起点は異常か（前提の不充足 / 外部の操作の失敗 / 機構の拒否 / 利用者の誤用 / 壊れた状態）→ 例外フロー
  4. フローではなく成果物・データの中身の規定か → 規約節
  5. 他のアセットとの関係の規定か → 他のスキル・機構との整合
- 判定は**起点**で決める。終わり方は検算にだけ使う
- 検算: 代替フローの項目はすべて目的を達成して終わる。達成せずに返す項目が代替フローにあれば起点の判定を誤っている
- 例外フローの項目は、目的を達成せずに返すことも、回復してメインフローに戻ることもある。終わり方で例外かどうかを決めない
- 判定基準を当てても一意に決まらない記述は、書き手が自分で決めず、記述と理由を呼び出し元に返す

## 理由

- 起点を第一の軸にすると、背景で挙げた 4 例がすべて一意に決まる。「同名のブランチが既に存在する」は前提の不充足で例外、「未コミットの変更がある」も前提の不充足で例外、「open な MR が既にある」は対象が既に目的の状態にあるため代替、「push 前チェックを意図的に飛ばす」は呼び出し元の選択で代替
- 終わり方を検算に回すことで、代替フローが「目的を達成する道」だけになり、節名から中身の性質が読める。同居の問題が構造的に消える
- 判定順を固定したのは、複数の軸を同時に見ると書き手ごとに重みづけが変わり、基準を作った意味が無くなるため

## 却下した案

- **終わり方（達成する / 達成せず返す）を第一の軸にする**: 節の性質は揃うが、「回復してメインフローに戻る例外」（検査で拒否 → 直して再実行）が代替に入ってしまい、異常系が代替フローに紛れる
- **起点 × 終わり方の 2 軸のマトリクスで決める**: 網羅的だが、6 通りの升目のうち複数に当てはまる記述が出て一意にならない。書き手が升目を選ぶ手間も増える
- **回復可能かどうかで分ける**: 直感的だが「回復可能」の判断が書き手の想定に依存し、基準として機能しない
- **一意に決まらない記述は書き手が決めてよいことにする**: 進みは早いが、基準を作った目的（振り分けの揺れをなくす）が達成されない
