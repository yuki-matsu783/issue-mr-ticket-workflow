# i0001-13. 一時ファイルは wip/tmp に置き、ワークスペース外のパスを使わない

## 背景

参考実装 MR-driven-workflow の規約では、その場限りのスクリプトの切り出し先を「セッション用の一時ディレクトリ（scratchpad）」とし、agent-workflow でも `--body-file` 用の一時ファイルは「リポジトリ外（`/tmp/` 等）」に置くとしていた。本機構の要件定義の作業でも、issue 本文・MR 本文・置換用の perl スクリプトをセッション用の作業ディレクトリに置いていた。

## 決定

- 一時ファイル（issue / MR に投稿する本文、その場限りのスクリプト、中間結果）は **`wip/tmp/`** に置く
- OS の一時ディレクトリ（`/tmp`、`%TEMP%`）やセッション用の作業ディレクトリなど、**ワークスペース外のパスは基本的に使わない**
- `wip/tmp/` は `.gitignore` の対象とし、`.gitkeep` だけを追跡する。全体まとめの片付けで空にする
- 一時ファイルの説明は要件定義書 C 節、ドキュメント運用の対応表（H 節）に「追跡しない一時: `wip/tmp/`」として載せる

## 理由

- ワークスペース外のパスは環境ごとに異なり（Windows / WSL / CI / Claude Code on the web）、手順の再現性が下がる。`wip/tmp/` なら相対パスで書ける
- 作業中のファイルがリポジトリ内にあれば、ユーザーがエディタでそのまま確認・修正できる。セッション用ディレクトリは人間から見えにくい
- `wip/` は MR 単位で片付ける作業領域として既に定義されており、一時ファイルの寿命と一致する
- 参考実装が scratchpad を選んだ理由（使い捨てのスクリプトを `.claude/scripts/` に置くと配置ルールと衝突し残り続ける）は、`wip/tmp/` を gitignore して片付けの対象にすることで同じく満たせる

## 却下した案

- **セッション用の作業ディレクトリ（scratchpad）を使う（参考実装方式）**: 権限プロンプト無しに書けて手軽だが、ワークスペース外で環境依存、人間から見えず、セッションが変わると消える
- **`/tmp` 等の OS の一時ディレクトリを使う**: 同上。加えて Windows の git bash ではパス変換の罠がある
- **`wip/tmp/` も Git で追跡する**: 経緯が残るが、投稿本文やスクリプトの断片が MR の差分に混ざりレビューのノイズになる。残したいものは MR 本文・issue コメント・`.claude/docs/` に書き写す運用で足りる

## 影響

- `.gitignore` に `wip/tmp/*` と `!wip/tmp/.gitkeep` を追加
- 提供コマンド（レビュー依頼・issue 通知など `--body-file` を受け取るもの）の使い方の例は `wip/tmp/` のパスで書く
- 全体まとめの片付けは `wip/tmp/` の中身も削除する（`.gitkeep` は残す）
