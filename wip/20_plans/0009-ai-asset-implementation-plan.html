この計画で何をするか

レビュー済みの設計文書のとおりに AI アセット本体を変える。中核（scope-limits.json）を含むため、ロックアウトが起きないことを実装前に確かめる手順を決める。

決めたこと

  • 書き込みは .claude/skills/ .claude/rules/ .claude/hooks/config/ .claude/evals/ のみ
  • ルール本体 2 本・スキル本体 2 本・テンプレート 1 本・許可範囲設定とそのテスト・eval 定義の 8 か所
  • scope-limits.json は最後にまとめて変え、test_scope.sh を先に落としてから直す
  • run-tests.sh --ids の全通過を DoD にする

リスクと復旧

リスク影響対処・巻き戻し
common.protected に apl/*/.gitignore を足した結果、実装タスクが入れ子 .gitignore を作れないフェーズ 4 の移動が止まる実装タスクの allow に明示して判定順 (2) を通す（.gitattributes と同じ手当）。test_scope.sh でアサーションを固定する
旧置き場を全 type の deny から外した結果、計画・調査タスクが書けてしまう計画タスクがソースを触る計画・調査タスクの deny には残す。design-plan が src/x.ts を deny するアサーションを残す
apl/*/* を implementation の allow に足した結果、意図しないファイルまで書けるアプリルート直下の任意のファイルが無確認で書ける* は / を跨がないので src/ docs/ の中には届かない。apl/a/src/x.ts が apl/*/* に一致しないことをテストで固定する
フックが未登録で、変更しても機構が実際に止まらず誤りに気づけない誤った設定がマージされるtest_scope.sh が scope.sh を直接叩いて判定を検査するので、フック登録の有無に関わらず検出できる
scope-limits.json の JSON が壊れるすべての判定が WF210 で止まるjq . で構文を確かめてからコミットする。壊れたら git checkout で戻す
