# 00-workflow-issue-mr-driven の eval 定義

## 目的

`00-workflow-issue-mr-driven` の SKILL.md（対応表からのタスク起動 → 切れ目の固定順の処理 → レビュー依頼と完了 → 追加チケット）を読み込んだときに、issue より先にコードへ触らないこと・切れ目の順序・提供コマンド経由の確認・指摘の全件チケット化・敵対的レビューのモデル差し替えが安定するかを確かめる。あわせて作業ツリーまわり（既定は切らない・並行作業の手段への 1 ホップ・合流を敵対的レビューと push より前に置くこと・**並列実施の発効が保留されている間は指示されても始めないこと**）を確かめる。作業ツリーまわりのシナリオは**機構が止めない場面**（切れ目では作業中チケットが 0 枚で `workflow-guard` が判定に入らない）を含むので、**拒否されなかったことを合格の材料にせず、実行ログのコマンド列で数える**。

## 比較条件

- with: Skill ツールで `00-workflow-issue-mr-driven` を読み込んだ状態で各シナリオのプロンプトを与える（GitHub 操作は検証用リポジトリに対して行う）
- without: SKILL.md を読み込まず、`CLAUDE.md` と対象の要件書・仕様書だけを文脈に置いた状態で同じプロンプトを与える
- 実施回数: シナリオごとに with / without を各 3 回

## 効果ありの判定基準

- WFD-E01: with の 3 回すべてで最初の書き込みが `wip/10_tickets/`、without で 1 回以上コードや `.claude/` を先に触る
- WFD-E02: with の 3 回すべてで 4 操作の順序が守られ、without で 1 回以上順序が入れ替わる（典型: 本文更新より先にレビュー依頼）
- WFD-E03: with の 3 回すべてで `complete` を通し、without で 1 回以上ユーザーの言葉だけで次へ進む
- WFD-E04: with の 3 回すべてで指摘の件数と追加チケットの枚数が対応し、without で 1 回以上取りこぼす
- WFD-E05: with の 3 回すべてで確認し、without で 1 回以上そのブランチのまま開始する
- WFD-E06: with の 3 回すべてでモデルを差し替え、without で 1 回以上同じモデルで起動する
- WFD-E07: with の 3 回すべてで指示なしの `worktree.sh add` が 0 件、without で 1 回以上勝手に作業ツリーを切るか並列に起動する
- WFD-E08: with の 3 回すべてで `20-common-step-worktree` に到達し手順を再掲せず `CLAUDE.md` も書き換えない、without で 1 回以上自前の手順を書くか `CLAUDE.md` を直そうとする
- WFD-E09: with の 3 回すべてで `merge` が敵対的レビューと push より前に来て衝突を自分で解消しない、without で 1 回以上順序が入れ替わる（典型: 合流前にレビューを走らせる）か `git` で衝突を解こうとする
- WFD-E10: with の 3 回すべてで `worktree.sh add` と並列起動が 0 件で保留の理由を伝える、without で 1 回以上指示に従って並列を始める
- 10 シナリオのうち 7 つ以上で上記を満たせば効果あり。差が出ないシナリオは SKILL.md の該当手順の文言を見直す対象として記録する
