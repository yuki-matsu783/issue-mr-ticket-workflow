# i0009-15. `WF009` を共通ライブラリの既定として採番台帳に載せる

## 背景

issue #9 の調査 0005 f2 で、`HOOK_DENY_ID` の既定値 `WF009` が参考実装を含む 23 ファイルに現れる一方、共通仕様 §6 の**採番台帳に載っていない**ことが分かった。

台帳は `WF101–109`（`workflow-entry`）以降を百の位でフックに割り当てており、`WF009` は百の位を持たない。台帳の規則（`x09` は「判定不能で拒否側に倒した」で拒否側のフックだけが持つ）に当てはめると、`WF009` は「百の位が 0 のフック」の判定不能ということになるが、そんなフックは無い。

実際の `WF009` は、共通ライブラリ（`hook-common.sh` / `scope.sh`）の**読み込み行**が、呼び手のフックが `HOOK_DENY_ID` を代入する前に失敗したときの既定として使われている。各フックは読み込み行より前に `HOOK_DENY_ID=WFx09` を代入するので、正しく書かれたフックからは `WF009` は出ない。しかし代入を忘れた場合や、代入行そのものより前で失敗した場合には出力され得る。

## 決定

- **`WF009` を採番台帳の先頭行として登録する**。持ち主は「共通ライブラリ（`hook-common.sh` / `scope.sh` の読み込み行）」
- 台帳の説明に「**フックはこの番号を自分で出さない**（各フックは読み込み行より前に `HOOK_DENY_ID=WFx09` を代入する）」と明記する
- §6 の `x09` の規則の説明に「百の位を持たない `WF009` は共通ライブラリの読み込み行の既定で、フックが自分で出す番号ではない」を足す

## 理由

- **実際に出力され得る番号を台帳から欠落させない**。台帳の目的は「この識別子を見たら誰が出したか分かる」ことで、出得るのに載っていない番号があると、ユーザーが `WF009` を見たときに調べる先が無い
- 番号を変える（例: `WF099` にする）案もあるが、23 ファイルに散っている既定値を書き換える利益が小さい。`0` は「どのフックにも属さない」を素直に表しており、規則の説明を 1 文足せば読み解ける
- 「フックが自分で出す番号ではない」を明記することで、**`WF009` が出たら実装の誤り**（`HOOK_DENY_ID` の代入忘れ）だと分かる。運用上のシグナルとして機能する

## 却下した案

- **`WF009` を廃止して各フックの `WFx09` に統一する**: 読み込み行はライブラリの先頭で走るため、呼び手が代入する前に失敗する経路が必ず残る。既定値を無くすと、その経路で識別子の無い deny が出る
- **番号を `WF099` に変える**: 23 ファイルの書き換えと、参考実装との差分が増える。`x09` の規則に見た目を寄せるだけで、実質は変わらない
- **台帳に載せず、規則の説明にだけ書く**: 台帳は「新しい識別子はここに追加してから使う」という運用の入口なので、載っていないものが使われている状態は運用そのものの例外になる

## 影響

- `10_spec/フック共通仕様.md` §6（台帳の先頭行を追加・`x09` の規則の説明を追記）
- **実装フェーズへ**: 各フックは読み込み行より前に `HOOK_DENY_ID=WFx09` を代入する。`WF009` が出たら代入忘れとして扱う
