# i0009-34. 戻り値 0/1/2 の規約は読み込み系の関数だけに適用する

## 背景

`i0009-16` は「`frontmatter.sh` のスタブは戻り値 2」と決め、§8 に「**`scope.sh` の関数の戻り値**: 0 = 判定できた / 1 = チケットの記載不正 / 2 = `frontmatter.sh` を読み込めていない」と書いた。**関数を限定していない**書き方だった。

境界レビュー（付録 A の R7）の指摘: `scope.sh` には**真偽を返す述語関数**がある。

- `scope_match <path> <pattern>`: 最終行が `[[ "$p" =~ $re ]]` で、**一致 0 / 不一致 1**
- `scope_op_declared <class>`: `(( in_type && in_decl ))` で、**宣言なしが 1**

この規約のまま実装すると、`scope_match` の「一致しない（戻り値 1）」が呼び手の側で「チケットの記載不正 → WF211」と誤読される。HK-T16 が「戻り値が 0/1/2 を区別して返す」ことを固定するので、テストの期待値も曖昧になる。

## 決定

- 戻り値 0 / 1 / 2 の規約を **「読み込み」の 3 関数**（`scope_load` / `scope_load_ticket` / `scope_load_approvals`）**だけ**に適用すると §8 に明記する
- **述語関数**（`scope_match` / `scope_op_declared`）は真偽（一致 0 / 不一致 1）を返し、この規約の対象外とする
- **判定関数**（`scope_resolve` / `scope_classify`）の戻り値は常に 0 で、結果は `SC_*` 変数に置く（`i0009-33`）
- HK-T16 を「読み込み系 3 関数は 3 状態を区別して返し、述語関数は同じ環境でも真偽を返す」に書き直す

## 理由

- **bash の慣習に沿う**。`[[ ]]` や `grep` と同じく、述語は真偽を戻り値で返すのが自然。`if scope_match "$p" "$pat"; then` と書けるのが読みやすさの本体で、ここを 3 状態にすると呼び手が毎回 `case $? in` を書くことになる
- **規約は「どの関数に効くか」まで書かないと規約にならない**。`i0009-16` は `frontmatter.sh` 側の話として書いたので `scope.sh` 側の関数の種類を見ていなかった。適用範囲を明示するのが是正
- 3 種類（読み込み / 判定 / 述語）の区別は `i0009-33` の「出力の形」の表に列として持たせたので、読み手が表を見れば分かる

## 却下した案

- **述語関数も 3 状態にする**: `scope_match` が「ライブラリ不在」を返す場面が無い（パターン照合は純 bash で、`frontmatter.sh` に依存しない）。無い状態のために呼び出し側を複雑にする理由が無い
- **述語関数をやめて判定関数に統合する**: `scope_match` は `scope_resolve` の内部で何度も呼ばれる部品で、統合すると 1 回の判定で `SC_*` を何度も上書きすることになる
- **戻り値を使わず、すべての結果を変数で返す**: 述語を `if` で使えなくなり、呼び出し側が冗長になる

## 影響

- `10_spec/フック共通仕様.md` §8（出力の形の表と規約の適用範囲）・§11（HK-T16）
- **実装フェーズへ**: 参考実装 `.claude/hooks/lib/scope.sh` の `scope_match` / `_sc_any_match` / `scope_op_declared` は既に真偽を返しているので、変更不要
- 関連: `i0009-16`（3 状態の由来）・`i0009-33`（出力の形）
