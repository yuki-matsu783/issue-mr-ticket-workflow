# i0050-07. 作業ツリー解決は相互参照の双方向を要求し、差分の事後検査は判定対象の作業ツリーを見る

## 背景

issue #50 の調査で、作業ツリーの解決をめぐって**正史と実装が逆を書いている箇所が 2 つ**見つかった。どちらも設計の前提として読まれる場所である。

| # | 正史の記述 | 実装の実際 |
|---|---|---|
| D1 | フック共通仕様 §13「意図的な緩和」に「差分の事後検査（`workflow-diff-check`）は `HOOK_ROOT` の作業ツリーだけを見る。worktree の中で起きた書き込みは事後の差分検査に現れない」とあり、`i0009-64` の「残る穴」も同じことを書く | `workflow-diff-check.sh` は作業中チケットの取得・差分の取得・基準点との比較のすべてを判定対象の作業ツリー（`HOOK_WORKTREE`）に対して行う。`git log -S` で追うと初版からこの形で、「穴」は最初から無かった |
| D2 | `i0009-64` の「決定」に「判定は fork ゼロの 2 経路のどちらかが成り立つこと。**片方でよい**」「両方を要求すると正しい worktree を本流に倒してしまう」とある | 作業ツリーの判定は**相互参照の双方向**（候補の `.git` が登録を指し、その登録が候補を指し返すこと）を要求する。共通仕様 §2 も双方向で書かれている |

D1 は「緩和として受け入れる」と書かれた穴が実在しないという食い違いで、D2 は同じ DDR の「決定」節と「影響」節の中で記述が食い違っている（影響節には双方向にした旨だけが書かれている）。どちらも、正史だけを読むと現在の実装より**緩い**前提に立つことになる。

## 決定

- **実装を正とし、正史をそれに合わせて書き戻す。**
  - 作業ツリーの判定は**相互参照の双方向**を要求する。`i0009-64` の「片方でよい」を上書きする
  - 差分の事後検査は**判定対象の作業ツリー**（操作が行われた作業ツリー）を見る。フック共通仕様 §13 から「差分の事後検査は `HOOK_ROOT` の作業ツリーだけを見る」という緩和の項目を外し、`workflow-diff-check` の仕様に「判定の対象は `HOOK_WORKTREE` に閉じる」と明記する
- 双方向を要求した結果として本流に倒れる状態（ディレクトリを移した後で `git worktree repair` を実行していない作業ツリー、作って消した後の stale な登録が残っている場所）は、**倒れてよい**ものとして受け入れる

## 理由

- **双方向のほうが安全側である。** 片方向（登録側から探すだけ）では、worktree を作って消した後に残る stale な登録の指し先に別のディレクトリを置くだけで、そこが作業ツリーとして信用される。作業ツリーとして信用された場所では、その中の空の `wip/10_tickets/10_doing/` が読まれ、宣言範囲の強制が全面的にバイパスされる
- 双方向で本流に倒れたときに起きるのは「本流の作業中チケットで判定される」ことであり、判定が消えるのではなく厳しい側に寄る。実測でも、参考実装のディレクトリは本流に倒れ、全面バイパスは起きていない
- **正史を実装に合わせないと、本フェーズ以降の判断が誤った前提の上に乗る。** 「差分の事後検査は worktree で効かない」という記述を信じると、worktree 運用では二重の守りが 1 枚しか無いことになり、必要のない補強を設計に足すことになる
- DDR は経緯の記録なので後から書き換えないが、「決定」節だけを読むと現在の実装を誤解する状態は、置き換えの DDR を足すことでしか解けない

## 却下した案

- **`i0009-64` の決定（片方向でよい）を維持し、実装を緩める**: 安全側で動いているものを、文書に合わせるためだけに緩めることになる。緩めた先で開くのは「`cd` 一つで機構が全面バイパスされる」経路そのもので、`i0009-64` の背景が防ごうとしたものと同じである
- **フック共通仕様 §13 の緩和の記述を残したまま、実装の側に注記だけを足す**: 正史が「穴がある」と書き、仕様書の別の節が「穴は無い」と書く状態になる。どちらを信じるかが読み手に委ねられ、食い違いが解けない
- **`i0009-64` の本文を直接書き換える**: マージ済みの DDR の本文は変更しない運用に反する。無効になった範囲は `status` と置き換え先で表す

## 影響

- `10_spec/フック共通仕様.md` §13 から「worktree の中の差分の事後検査」の項目を外す（同じ位置に、リポジトリの外への書き込みが保護対象でないことを緩和として書く）
- `10_spec/hooks/22-PostToolUse/workflow-diff-check.md` の概要・入出力・制御方式に「判定の対象は `HOOK_WORKTREE` に閉じる」を明記し、テスト DC-T08・DC-T09（負のコントロール込み）で固定する
- `i0009-64` のうち無効になるのは「片方でよい」という判定の緩さだけで、上向き探索そのもの・fork ゼロの制約・正規化の規則は有効なまま
