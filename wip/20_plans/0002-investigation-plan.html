この計画で何をするか

issue #9 の主作業（フック本体 11 本の実装）に入る前に、読み取りだけで答えられる問いを 3 枚の調査チケットに割り付ける。実測が要る問い（フック共通仕様 §12 の TBD）はこの調査では実施せず、「実装フェーズの検証項目」として確かめ方だけを整理する。

決めたこと

  • 調査チケットは 3 枚（0005 / 0006 / 0007）。1 観点のまとまり = 1 チケット
  • 外部技術調査（公式 hooks リファレンスの閲覧）は 0007 に閉じ、そのチケットだけ allow.ops に web を宣言する
  • .claude/** への一時的な変更（settings.json へのフックの一時登録を含む）は計画しない（10-task-investigation-plan 仕様「調査計画の固有手順」）
  • 既存のテスト・ビルドの実行は計画しない（build-test はどのチケットにも宣言しない）
  • 次の計画チケットは 0008-ai-asset-design-plan。predecessors に 0005・0006・0007 を入れる

方法とステップ

  1. 1

    Q1 の洗い出し（0005）

    .claude/docs/10_spec/hooks/**/*.md 11 本と フック共通仕様.md を読み、フックごとに「判定順の要約 / エラー識別子 / 終了方式 / テスト ID / 依存する lib・設定」の表を作る。識別子は §6 の台帳と、テスト ID は既存テストの ID と突き合わせて重複を見る（実行はせず grep で足りる）。

  2. 2

    Q2 の結線（0006）

    .claude/hooks/lib/*.sh の関数定義と、各フック仕様が呼ぶと書いている関数名を突き合わせる。引数・戻り値・出力先の食い違い、仕様にあって lib に無い関数、lib にあって誰も呼ばない関数を列挙する。

  3. 3

    Q3 の参考実装（0006 に同居）

    参考ディレクトリ/agent-workflow/.claude/hooks/ を読み、流用できる構造とテストの書き方を挙げる。終了方式の差は §12 T6 の予備知識として整理する。

  4. 4

    Q4 の外部技術調査（0007）

    公式 hooks リファレンスを閲覧し、イベント名・入力フィールド・出力スキーマを確認する。仕様の前提（§2・§12 の T3・T4・T7）と「一致 / 相違 / 記載なし」を 1 行ずつ判定し、出典 URL を添える。

  5. 5

    Q5 の T5 と git 'commit'（0007 に同居）

    .claude/docs/20_ddr/ と #6 の作業ログで T5 の結論を探し、hook-common.sh が PowerShell を吸収しているかを読む。cmdpos.sh の CP_GITLIKE 周りと block-direct-git 仕様の「特定できない」の扱いを突き合わせる。

  6. 6

    実装フェーズの検証項目の整理（0005 の成果物）

    §12 の T1〜T4・T6〜T8 と agent_type について「何を・どの記録で・いつ（段階登録のどの段で）確かめるか」の表を作る。この調査では実施しない。
