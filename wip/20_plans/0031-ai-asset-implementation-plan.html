この計画で何をするか

設計 0028〜0032 が仕様に書いた「実装を伴う変更」9 件 — 識別子 CP007 / CP008 / RV008 / TK008 の付け替え、ticket.sh の完了検査（見出し重複）と create の YAML エスケープ、hook_payload --session、HK-T15 の付番、SC-E への改名、テンプレート 2 本のガイド、SKILL.md 4 本のエラー表 — を固定順（テンプレート → 中核 → 中核のテスト → スキル・eval → 参照更新）のステップに割り、テスト ID を割り付け、自分が使っている提供コマンドを自分で変えるときの復旧手順を決めて、実装チケット 4 枚と全体まとめチケットを起こす。

  • 前回（0011）との違い: 提供コマンドとテストランナーは稼働中で切り替え境目は無い。代わりに各チケットで「変更後の自分のコマンドで自分をコミット・完了させる」最初の操作を決めた
  • 実行者は全チケットともメインエージェント。人間レビューは実装の切れ目 1 回（承認④により opus 自己レビューで代替）、敵対的レビュー 1 回
