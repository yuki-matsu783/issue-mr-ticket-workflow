    戻り値 0/1/2 の規約は読み込み系の 3 関数だけに適用する ◎良 根拠: 境界レビュー R7、参考実装 scope.sh:138-143・:195-201

    i0009-16 は「scope.sh の関数の戻り値は 0/1/2」と関数を限定せずに書いていた。ところが scope.sh には真偽を返す述語関数がある（scope_match の「一致 0 / 不一致 1」、scope_op_declared の「宣言なしが 1」）。このままだと「一致しない（1）」が呼び手で「記載不正 → WF211」と誤読される。決定: 規約を読み込みの 3 関数だけに限定し、述語関数は真偽を返すと明記した。判定関数の戻り値は常に 0。理由は bash の慣習（if scope_match ...; then と書けるのが読みやすさの本体）と、scope_match に「ライブラリ不在」を返す場面が無いこと（パターン照合は純 bash で frontmatter.sh に依存しない）。

    実測への依存: 無し（規約の適用範囲）

  3. 3

    fm_* の呼び出し規約を書き方まで降ろした ✕問題 根拠: 境界レビュー R8、参考実装 scope.sh:101-104（|| true）

    i0009-16（スタブは戻り値 2）と i0009-14（scope.sh は 1 と 2 を潰さない）が成立して初めて WF209 / WF211 を区別できる。ところがどう書けば潰さないかが仕様に無かった。bash には戻り値を静かに失う書き方が 2 つある — local v=$(fm_get ...) は local の終了ステータス（常に 0）が返り戻り値が黙って消える、|| true は戻り値を捨てる。参考実装は現に後者を選んでいる。決定: 呼び出し規約を仕様に書いた — local と代入を分ける / || true を使わない / 使わない呼び出しでも || rc=$? で受ける / パイプやコマンド置換の中で呼ばない / FM_AVAILABLE を設定するのは読み込み行（読み込めていないときに実行されるのはスタブの側なので、ライブラリに任せられない）。

    実測への依存: あり（規約が実装で守られるかは実装フェーズ）

    根拠を見る（読んだ箇所と出力） 
    参考実装 scope.sh:101-104（現状）:
  SC_TICKET_TYPE="$(fm_get "$f" ticket_type 2>/dev/null || true)"
  while IFS= read -r v; …; done < <(fm_list "$f" allow.write 2>/dev/null || true)
  → 戻り値を完全に捨てている
  さらに scope_load_ticket は「ファイル不在」「ticket_type 空」「スタブ」を
     すべて return 1 に潰している
規約（新）:
  local v; v="$(fm_get "$f" k)" || rc=$?    ← 2 行に分ける
  || true は使わない / コマンド置換の中で呼ばない
  FM_AVAILABLE は読み込み行が設定（成功 1 / nop フォールバック 0）
更新: 20-common-step-shell-script「読み込み行」
DDR: i0009-35

    結論

    設計で 2 チケットかけて決めた区別が実装では既に消えている。規約は書いたが、他に戻り値を失う書き方が無いことを網羅的に確かめていない。「方針を書けば守られる」という前提が 1 度崩れた場所なので、実装フェーズで実際に守られるかを見る必要がある。
