# 10-task-design-feedback-plan の eval 定義

## 目的

`10-task-design-feedback-plan` の SKILL.md（計画タスクの共通手順 + 設計反映計画の固有手順）を読み込んだときに、食い違いごとにどちらを正とするかを計画で決めること・「対象なし」の扱い・実装を正とする理由を残すことが安定するかを確かめる。

## 評価シナリオ

各行は仕様書「テスト観点（eval）」の行と 1:1 に対応する（eval ID が対応の鍵）。

| eval ID | 入力プロンプトと状況 | 期待する振る舞い | 判定方法 | 添付ファイル |
|---------|--------------------|-----------------|---------|-------------|
| DFP-E01 | 実装結果レポートの逸脱一覧に、仕様との食い違いが 5 件ある | 書き戻す文書と箇所を一覧にし、食い違いごとにどちらを正とするかを計画の段階で決める | 計画書の一覧と、正の決定の記載 | `assets/design-feedback-plan.template.md` |
| DFP-E02 | 逸脱一覧が空で、書き戻す対象が無いと分かった | 「対象なし」と根拠を書き、設計反映チケットを起こさず次の計画チケットだけを作る | 起票したチケットの枚数 | なし |
| DFP-E03 | エラーメッセージについて、実装（UI 文言集）のほうが仕様より正しいと判断する場面 | 実装を正とする理由を書き、仕様側を直す方針を計画書に残す。実装を仕様に合わせて壊さない | 計画書の理由の記載 | なし |

## 比較条件

- with: Skill ツールで `10-task-design-feedback-plan` を読み込んだ状態で各シナリオのプロンプトを与える
- without: SKILL.md を読み込まず、`CLAUDE.md` と対象の要件書・仕様書だけを文脈に置いた状態で同じプロンプトを与える
- 実施回数: シナリオごとに with / without を各 3 回

## 効果ありの判定基準

- DFP-E01: with の 3 回すべてで 5 件それぞれに正の決定が付き、without で 1 回以上「設計反映チケットで決める」に送る
- DFP-E02: with の 3 回すべてで次の計画チケット 1 枚だけ、without で 1 回以上不要なチケットを作る
- DFP-E03: with の 3 回すべてで理由が書かれ、without で 1 回以上理由なしに片側へ寄せる
- 3 シナリオのうち 2 つ以上で上記を満たせば効果あり。差が出ないシナリオは SKILL.md の該当手順の文言を見直す対象として記録する
