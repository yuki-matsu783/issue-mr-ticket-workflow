# work-defaults ルール

## 概要

ワークの種類ごとの既定判断基準（既定の実行者・人間レビュー要否とその理由・調整してよい条件）を定める行動ルールの要件を定義する。全体計画ワークが各チケットの実行者と人間レビュー要否を提案するときの基準であり、プロジェクトごとに置き換えられる。参考実装には無い新設のルール。

- **背景**: 既定をスキルに固定するとプロジェクトごとの調整のたびにスキルを直すことになり、既定を持たないと issue ごとに提案がぶれて合意の往復が増える。「このプロジェクトでどこまで AI に任せるか」の方針はスキルの手順ではなくプロジェクトの規約に属する。
- **目的**: 全体計画の提案が「基準どおり」か「この issue では基準から外す」かの差分で読め、合意が速く済む状態を作る。
- **スコープ**:
  - 含む: このルールが定めるべき内容（ワーク種ごとの既定値の項目）、全体計画からの参照のされ方、ルールが無い場合の振る舞い
  - 含まない: ワークの種類の定義（`00-workflow-issue-mr-driven.md`「ワークの構成」が正）、提案と合意の手順（`10-work-overall-plan.md` が正）、ルールの書式（表の形などは仕様書が定める）

---

## ユーザーストーリー

**[As a]** issue を AI に任せる開発者として、

**[I want]** どの種類のワークをどのモデルに任せ、どこで人間が見るかの既定をプロジェクトの規約として決めておきたい。

**[So that]** issue のたびに同じ議論を繰り返さず、全体計画は基準からの差分だけを判断すれば済むため。

---

## 受け入れ基準（Acceptance Criteria）

### メインフロー

- When 全体計画ワークが各チケットの実行者と人間レビュー要否を提案するとき、Shall このルールが置かれていればそれを基準にし、issue の性質に応じた調整は基準との差分として理由付きで提案されなければならない。
- When このルールを書くとき、Shall すべてのワークの種類（15 種。正は `00-workflow-issue-mr-driven.md`「ワークの構成」）について、**既定の実行者（モデル）**・**人間レビュー要否**・**その理由**・**調整してよい条件**を持たなければならない。
- When 既定の実行者を書くとき、Shall Claude Code のサブエージェントで選択できるモデルから指定しなければならない。
- When プロジェクトがこのルールを調整するとき、Shall ルールファイルの編集だけで置き換えられ、スキル本体の変更を要してはならない。

### 代替フロー

- If このルールが置かれていない場合、Then 全体計画はスキルの既定（リスクの高いワークは人間レビュー要）を使い、基準が無かった旨を全体計画書に書かなければならない。
- If ワークの種類が追加された場合、Then このルールに行を追加すれば全体計画の提案に反映されなければならない。

### 例外フロー

- If このルールに載っていないワークの種類のチケットを起こす必要がある場合、Then 全体計画はスキルの既定に倒し、基準に無いことを明示してユーザーと合意しなければならない（黙って既定を作らない）。

### 見直しの入力

- When フィードバック計画や振り返りで既定判断基準を見直すとき、Shall チケットに機械的に記録された着手・完了の時刻と作業ログを材料にでき、見直しの結果はこのルールの編集として反映されなければならない。

---

## 前提条件

- ワークの種類と担当（メインエージェント / サブエージェント）は `00-workflow-issue-mr-driven.md`「ワークの構成」が正であること
- チケットの着手・完了の時刻は提供コマンドが機械的に記録すること
- 行動ルール（章スキーマ対象外）であり、効くタイミングは全体計画のとき

---

## 制約条件

- **技術的制約**: 実行者に指定できるのは Claude Code のサブエージェントで選択できるモデルに限る
- **ビジネス的制約**: 基準は提案の既定であって強制ではない。issue ごとの最終決定は全体計画でユーザーと合意する（必要になれば強制への格上げを別途検討する）

## 非機能要件

| 項目 | 説明 |
|------|------|
| 一貫性 | ワーク種の名称は `00-workflow-issue-mr-driven.md` と同じ文言を使い、別名を作らない |
| 保守性 | 既定の変更が 1 ファイルの編集で閉じる |
| 可読性 | 理由と調整条件は 1〜2 行で書き、全体計画がそのまま提案文に引用できる粒度にする |
