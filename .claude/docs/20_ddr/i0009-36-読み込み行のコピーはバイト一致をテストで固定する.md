# i0009-36. 読み込み行のコピーはバイト一致をテストで固定する

## 背景

`20-common-step-shell-script` 仕様は「各スクリプトはこの行を**コピー**して引数だけを変え、中身を自作・改変しない（行の実体は `assets/script.template.sh` が正）」と定めている。実際に `__ss_load` を持つファイルはリポジトリ内に **20 本以上**ある（`.claude/hooks/lib/scope.sh`、その `tests/`、`.claude/skills/*/scripts/` とその `tests/`、雛形 2 本）。

境界レビュー（付録 A の R9）の指摘は 3 つ。

1. 現行の全コピーは `fm_get() { return 1; }` 相当のスタブで、**`FM_AVAILABLE` をどこにも設定していない**（`i0009-35` で「読み込み行が設定する」と決めた項目が全コピーに無い）
2. 0015 の申し送りは「`assets/script.template.sh` の読み込み行も合わせる」としか書いておらず、**既存のコピーへの波及に触れていない**
3. 唯一の関連テスト `test_templates.sh` は**雛形だけ**を読んでおり、各コピーが雛形と一致することを検査するテストが**存在しない**

`scope.sh` こそ `nop` ポリシーの主役（`i0009-14`）なので、直し忘れると `HK-T16` が通らないか、通っても本番経路が旧仕様のまま残る。

## 決定

- テスト **`SS-T05`** を新設する: リポジトリ内のすべての `.sh`（`.claude/hooks/**` と `.claude/skills/*/scripts/**`）の `^__ss_load() {` から始まる行が、`assets/script.template.sh` のそれと**バイト一致**する。1 か所でも違えば失敗し、**違うファイルを列挙する**
- 0016（実装計画）に「**読み込み行の一斉置換**（20 本以上）」を明示的な作業項目として立てる

## 理由

- **「コピーせよ」という規約は、一致を検査しない限り必ずドリフトする**。今回の `FM_AVAILABLE` の追加がまさにその 1 回目で、次に読み込み行を変えるときも同じことが起きる
- **検査は安い**。`grep -rl '^__ss_load() {'` でファイルを集め、各ファイルの当該行を雛形のそれと文字列比較するだけで、数秒で終わる。`test-lib.sh` の `assert_eq` で書ける
- **失敗時にファイルを列挙する**のが要点。「どこかが違う」だけでは直せない
- 一斉置換を実装計画の作業項目に立てるのは、20 本以上を手で直す作業が見積もりから漏れると必ず後回しになるため

## 却下した案

- **読み込み行を 1 ファイル（`lib/loader.sh`）に切り出して `source` する**: 「読み込み行はリポジトリルートを解決するための行」なので、それ自体を `source` するにはルートが要る。鶏と卵で、逐語コピーは避けられない構造
- **雛形からの生成をビルド手順にする**: この機構にビルド段階が無く、`.sh` は直接実行される。生成物と原本の乖離を別の手段で検査することになり、問題が 1 段深くなる
- **バイト一致ではなく「機能が同じ」を検査する**: 各コピーを実際に実行して振る舞いを比べることになり、20 本分のテストが要る。文字列一致で十分
- **既存のコピーはそのままにして、雛形だけ新仕様にする**: `scope.sh` が旧スタブのままだと `WF209` / `WF211` の区別（設計の成果）が本番で効かない

## 影響

- `10_spec/skills/20-common-step-shell-script.md` テスト観点（`SS-T05` を追加）
- **0016 へ**: 実装計画に「読み込み行の一斉置換（20 本以上）」を作業項目として立てる
- **実装フェーズへ**: 雛形（`script.template.sh` / `test.template.sh`）を先に直し、`SS-T05` を通してから他のファイルを合わせる
- 関連: `i0009-35`（`FM_AVAILABLE` の持ち主が読み込み行であること）
