# i0001-15. レビュー完了時は未解決スレッドの有無を必ず確認し、ユーザーの言葉だけで次に進まない

## 背景

`00-workflow-issue-mr-driven` はワークの切れ目で MR 上のレビューを依頼し、レビュー完了の連絡を受けてから指摘を取得して追加チケットにする。参考実装 agent-workflow の `work-boundary.sh complete` は `CHANGES_REQUESTED` と「返信の無いインラインスレッド」で止まるが、返信済みで resolve されていないスレッドは通過し、ユーザーが「指摘なし」と伝えればそのまま次のワークへ進めた。レビュアーが後で見返すつもりで開けたままにしたスレッドや、返信したが合意に至っていないスレッドが、次のワークの陰に隠れる。

## 決定

- レビュー完了の連絡を受けたら、ユーザーの言葉（「指摘なし」「OK」を含む）だけで判断せず、**必ず MR 上に未解決（unresolved）のスレッドが無いかを確認する**
- 未解決のスレッドが 1 つも無く指摘も 0 件のときだけ、確認なしで次のワークに進む
- 未解決のスレッドが残っているときは、そのスレッドを提示して MR 上で resolve することを勧め、**改めて次のワークに進んでよいかをユーザーに確認する**。OK なら進み、OK でなければそのスレッドを同じ種類の追加チケットとして起こす
- この確認は `00-workflow-issue-mr-driven` が自身で持つ 2 つ目の承認ポイントとする（1 つ目は切れ目の MR レビュー待ち）

## 理由

- レビューの完了は「レビュアーが見終わった」ではなく「開いた論点が閉じた」ことで判定したい。unresolved は MR 上に残る客観的な状態で、チャットの言葉より確かめやすい
- ユーザーが「指摘なし」と言うのはスレッドを忘れている場合もある。機械的に止めるのではなく、状態を見せて判断を仰ぐことで、意図的に残したスレッド（後続ワークで扱う等）を尊重しつつ見落としを防ぐ
- 返信済みだが未解決のスレッドを常に追加チケットにすると、軽い確認コメントまでチケット化して往復が増える。「進んでよいか」の確認 1 回で済ませる

## 却下した案

- **未解決スレッドがあれば機械的に先へ進めない**: 確実だが、レビュアーがメモとして開けたスレッドや後続ワークで扱う論点まで塞ぎ、ユーザーが resolve のためだけに MR を開く手間が増える
- **未返信スレッドだけを見る（参考実装方式）**: 返信済みで合意に至っていない論点を見落とす
- **ユーザーの「指摘なし」を信じて進む**: 最も軽いが、レビューの証跡（unresolved の状態）と進行が食い違い、後から「見たはずの指摘が残っていた」になる

## 影響

- `00-workflow-issue-mr-driven.md` のメインフロー（レビュー完了の 4 項目）と承認ポイント
- レビュー完了の提供コマンドは、未返信スレッドに加えて未解決スレッドの一覧を返す必要がある（仕様で定める）
- ヘッドレス実行では「進んでよいか」の確認ができないため、未解決スレッドを報告してセッションを終える（既存のヘッドレス時の扱いに含まれる）
