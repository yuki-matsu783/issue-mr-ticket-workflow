# 10-task-ai-asset-implementation-plan の eval 定義

## 目的

`10-task-ai-asset-implementation-plan` の SKILL.md（計画タスクの共通手順 + AI アセット実装計画の固有手順）を読み込んだときに、固定順のステップ・提供コマンド自身を変える手順・テストの分類を両方宣言すること・抜き出しの正規表現の一致・テスト観点が無いときの差し戻し・変更箇所を実際に踏むロックアウト対策が安定するかを確かめる。

## 評価シナリオ

各行は仕様書「テスト観点（eval）」の行と 1:1 に対応する（eval ID が対応の鍵）。

| eval ID | 入力プロンプトと状況 | 期待する振る舞い | 判定方法 | 添付ファイル |
|---------|--------------------|-----------------|---------|-------------|
| AIP-E01 | フック 1 本・スキル 2 本・参照更新を含む仕様書を入力に実装計画を書く | ステップを固定順（設定・定義 → 中核 → 中核のテスト → スキル・ルール → 参照更新）で並べ、記述順とチケットの実行順を一致させる | ステップの並びと `predecessors`・連番の一致 | `assets/ai-asset-implementation-plan.template.md` |
| AIP-E02 | `ticket.sh` 自身を書き換えるステップがある | 変更後の自分のコマンドで自分をコミット・完了させる最初の操作と、失敗時に戻す基準点を書く | ステップの記述 | なし |
| AIP-E03 | テストを実行するチケットの許可範囲を書く場面 | テストの置き場に対応する分類（`build-test` と `hook-test`）を両方宣言する | チケットの `allow.ops` | なし |
| AIP-E04 | テスト方針の節を書く場面 | 抜き出しの正規表現を `run-tests.sh` の抽出規則と同じにし、抜き出しの件数と割付表の行数の一致を書く | 正規表現の一致と件数の記載 | なし |
| AIP-E05 | 対象アセットのうち 1 本の仕様書にテスト観点が無い | 実装計画で補わず、不足を結果報告に書いて設計の追加チケットを起こす提案を返す | 結果報告の記載と、起票したチケットの種類 | なし |
| AIP-E06 | `settings.json` の matcher を変えるステップがある | 変更箇所を**実際に踏む**テストまたはログの確認をロックアウト対策として書く。踏まないテストを対策にしない | 対策として挙げたテストが変更箇所を通ること | なし |

## 比較条件

- with: Skill ツールで `10-task-ai-asset-implementation-plan` を読み込んだ状態で各シナリオのプロンプトを与える
- without: SKILL.md を読み込まず、`CLAUDE.md` と対象の要件書・仕様書だけを文脈に置いた状態で同じプロンプトを与える
- 実施回数: シナリオごとに with / without を各 3 回

## 効果ありの判定基準

- AIP-E01: with の 3 回すべてで固定順かつ記述順と実行順が一致し、without で 1 回以上崩れる
- AIP-E02: with の 3 回すべてで自己適用の手順と基準点が書かれ、without で 1 回以上欠ける
- AIP-E03: with の 3 回すべてで両方宣言し、without で 1 回以上片方だけになる
- AIP-E04: with の 3 回すべてで正規表現が一致し件数が書かれ、without で 1 回以上目視で拾う
- AIP-E05: with の 3 回すべてで差し戻しを提案し、without で 1 回以上推測でテスト観点を補う
- AIP-E06: with の 3 回すべてで対策のテストが変更箇所を通り、without で 1 回以上通らないテストを対策にする
- 6 シナリオのうち 4 つ以上で上記を満たせば効果あり。差が出ないシナリオは SKILL.md の該当手順の文言を見直す対象として記録する
