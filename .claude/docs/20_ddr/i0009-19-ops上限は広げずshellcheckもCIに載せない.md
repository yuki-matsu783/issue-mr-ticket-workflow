# i0009-19. `ops` 上限は広げず、`shellcheck` も CI に載せない

## 背景

issue #9 は 2 つの申し送りを AI アセット設計フェーズに置いていた。どちらも「方針まで」で、`scope-limits.json` と CI 設定の実体は変えない範囲である。

- **D5**: `investigation` 以外の実施タスクの `ops` 上限。現状 `design` / `ai-asset-design` / `design-feedback` は `read, remote-read` だけで、`web`（外部への問い合わせ）を宣言できない。`investigation` だけが `build-test` と `web` を上限に持つ
- **D6**: `shellcheck` を CI で回すか。現状は `20-common-step-shell-script` の処理フロー 5 で「導入されていれば静的検査、不在なら省略の事実を記録」に留まる

## 決定

- **D5: `ops` 上限を広げない**。`web` を `design` / `ai-asset-design` / `design-feedback` / `implementation` の上限に足さない。`scope-limits.json` の実体も変えない
  - 設計や実装が外部の情報を必要としたら、**調査が足りていない兆候**として扱い、調査のタスクを起こして結論を持ち帰る。これを要件（メインフロー D）に 1 行として書く
  - あわせて、`investigation` の上限にある「上限に含めるだけで既定では使えない」という注記が**特例ではなく共通の規則**（`read` / `remote-read` / 提供コマンド以外は宣言が要る）の再掲であることを §8 に明記する
- **D6: `shellcheck` を CI で回さない**。`run-tests.sh` にも組み込まない。処理フロー 5 のローカル検査を続け、**実施の有無の記録を省略できないもの**とする（「実行した」か「不在で省略した」のどちらかを必ず作業ログに書く）
  - 要件の非機能（テスト容易性）に「静的検査は作成・変更のたびにローカルで行い、実施の有無を作業ログに残す（自動実行の仕組みを外部のサービスに置かない）」と書く

## 理由

**D5**:

- 0014（`i0009-12`）で **`web` は機構が強制しない**と決めたので、上限に足しても機構の振る舞いは変わらない。変わるのは「計画が宣言できるかどうか」だけで、宣言の記録としての意味しか無い
- 上限に無いことが「まず調査を起こせ」という設計の圧力になる。issue #9 の 0012〜0014 はまさに設計中に公式ドキュメントを確認したい場面だったが、**0007 の調査結果（`curl` で落とした原本の行番号付き引用）を参照する**ことで済んだ。しかも調査結果として残ったぶん、後から読む人が根拠を再現できる
- 上限を広げると、設計チケットが自分で外部を見て結論を持ち、その根拠が結果報告に残らない経路ができる

**D6**:

- CI 設定の変更は**リポジトリの設定変更**に当たり、この機構のスコープ外（`CLAUDE.md` の制約条件）
- 機構が守ろうとしているのは「AI が作業している最中に止める」ことで、CI は「人間が push した後」に効く別レイヤ。層としては有用だが、この issue の受け入れ条件のどれにも寄与しない
- `run-tests.sh` に組み込む案は、テストランナー（振る舞いを見る）と静的検査（コードの形を見る）を混ぜることになる。`shellcheck` 不在の環境で `run-tests.sh` が TR005（環境不備・終了 2）になると、テストを回せない環境が増える
- 実効性は「記録を省略できない」ことで確保する。作業ログに書く義務があれば、レビューで「省略が続いていないか」を見られる

## 却下した案

- **D5: `web` を全実施タスクの上限に足す**: 強制しない以上、記録の意味しか無いのに、調査を起こす圧力だけが失われる
- **D5: `investigation` からも `web` を外す**: 調査タスクの本体が外部の確認なので、宣言の記録が最も要る場所。外すと計画で意図を書く場所が無くなる
- **D6: `run-tests.sh --shellcheck` を足す**: テストランナーの責務が広がる。`shellcheck` 不在の環境での扱い（TR005 にするか無視するか）を新たに決める必要がある
- **D6: GitHub Actions で `shellcheck` を回す**: リポジトリ設定の変更に当たる。必要になったら別 issue で扱う

## 影響

- `10_spec/フック共通仕様.md` §8（`investigation` の注記を共通規則への参照に直し、`web` を他の type に足さないことを明記）
- `10_spec/skills/20-common-step-shell-script.md` 処理フロー 5（CI に載せない・記録は省略できない）
- `00_requirement/自己改善ワークフロー機構.md`（メインフロー D に「調査を起こす」の 1 行、非機能のテスト容易性に静的検査の方針）
- `.claude/hooks/config/scope-limits.json` の実体と CI 設定は**変えない**
