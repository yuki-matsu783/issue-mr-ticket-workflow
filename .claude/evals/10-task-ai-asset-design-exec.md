# 10-task-ai-asset-design-exec の eval 定義

## 目的

`10-task-ai-asset-design-exec` の SKILL.md（実施タスクの共通手順 + AI アセット設計の固有手順）を読み込んだときに、要件を外部視点で節順どおりに書くこと・「要件との対応」表を全件そろえること・写した元の位置を残すこと・1 つの決定の波及を洗い出すこと・番号の振り直しを他文書まで追随させること・受け入れ条件の対応小節を置くことが安定するかを確かめる。

## 評価シナリオ

各行は仕様書「テスト観点（eval）」の行と 1:1 に対応する（eval ID が対応の鍵）。

| eval ID | 入力プロンプトと状況 | 期待する振る舞い | 判定方法 | 添付ファイル |
|---------|--------------------|-----------------|---------|-------------|
| ADE-E01 | 新しいフックの要件定義書を書く | 受け入れ基準を EARS で書き、節を メイン → 代替 → 例外 → 規約 → 整合 の順に置く。内部構造を仕様書へ回す | 節順と、要件書に内部構造が無いこと | 設計計画書 |
| ADE-E02 | 対応する仕様書を書き終える場面 | 「要件との対応」表が受け入れ基準を全件カバーし、行数が一致する。実現箇所の無い要件と要件の無い節が無い | 表の行数と基準の件数の一致 | なし |
| ADE-E03 | 既存の実装（フックのスクリプト）を正として仕様に写す | 写した元の位置（ファイルと行）を作業ログに残す | 作業ログの記載 | なし |
| ADE-E04 | 既存の仕様書の処理フローを 1 項目変える | 1 つの決定がその文書の何か所に効くかを書き換える前に洗い出し、まとめて直す。文書の要約（`description`・`keywords`）も対象にする | 改訂した箇所の網羅性と frontmatter の更新 | なし |
| ADE-E05 | 仕様の段階番号を 7 段階から 8 段階に振り直した | 同じ番号を参照する他の文書を検索して揃える。同じ文書の中だけを直して終わらない | 全文検索の実行と、他文書の追随 | なし |
| ADE-E06 | 受け入れ基準を追加・変更した | 概要章に「issue の受け入れ条件との対応」の小節を置き、起点の issue の条件を全件対応づける | 小節の存在と、条件の網羅 | なし |

## 比較条件

- with: Skill ツールで `10-task-ai-asset-design-exec` を読み込んだ状態で各シナリオのプロンプトを与える
- without: SKILL.md を読み込まず、`CLAUDE.md` と対象の要件書・仕様書だけを文脈に置いた状態で同じプロンプトを与える
- 実施回数: シナリオごとに with / without を各 3 回

## 効果ありの判定基準

- ADE-E01: with の 3 回すべてで節順が守られ内部構造が無く、without で 1 回以上崩れる
- ADE-E02: with の 3 回すべてで表の行数が一致し、without で 1 回以上ずれる
- ADE-E03: with の 3 回すべてで写した元の位置が残り、without で 1 回以上欠ける
- ADE-E04: with の 3 回すべてで波及箇所と frontmatter が揃い、without で 1 回以上 1 か所だけ直す
- ADE-E05: with の 3 回すべてで他文書が追随し、without で 1 回以上自文書だけで終わる
- ADE-E06: with の 3 回すべてで対応小節があり条件を全件覆い、without で 1 回以上欠ける
- 6 シナリオのうち 4 つ以上で上記を満たせば効果あり。差が出ないシナリオは SKILL.md の該当手順の文言を見直す対象として記録する
