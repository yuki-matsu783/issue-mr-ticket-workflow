この計画で何をするか

VS Code チケットボード拡張のソース・テスト・ビルド設定を src/vscode-ticket-board/ から apl/vscode-ticket-board/ へディレクトリごと移し、npm test が通ることを確かめる。

決めたこと

  • 18 ファイルを階層を変えずに git mv で移す
  • ビルド設定はアプリルート相対なので中身を変えない
  • 内容を直すのは README の 1 行だけ（自分の置き場）
  • npm test を通すには先に commands.build-test への列挙が要る

対象と範囲

対象内容根拠・仕様の節
package.json / package-lock.json / tsconfig.json / .gitignoreそのまま移す（内容の変更なし）アプリルート相対の設定
README.md30 行目の置き場の記述だけ直す（1 行）src/vscode-ticket-board/ → apl/vscode-ticket-board/
src/*.ts（2）・src/core/*.ts（5）そのまま移す。ヘッダの 仕様: docs/10_spec/… はアプリルート相対として正しくなるフェーズ 6 の移動で解消
test/*.ts（5）・test/fixtures/*.md（1）そのまま移す（内容の変更なし）npm test で検証

方法とステップ

  1. 1

    基準を取る

    移動前に src/vscode-ticket-board/ で npm test を通し、全件 pass を記録する

  2. 2

    commands.build-test に npm test を足し、run-tests.sh --ids の 14 本 PASS を確認する

  3. 3

    移す（T2）

    git mv src/vscode-ticket-board apl/vscode-ticket-board。移動元の削除の ask WF202 を承認する

  4. 4

    参照を直す（T2）

    apl/vscode-ticket-board/README.md の 30 行目を apl/vscode-ticket-board/ にする

  5. 5

    検証（T2）

    V1〜V5 を順に実行し、結果を作業ログに残す

リスクと復旧

リスク影響対処・巻き戻し
移動元の削除が判定順 (7) の ask WF202 に落ちる移動が止まる承認単位は src/vscode-ticket-board。一度きりの移行としてこの ask を承認する（フック共通仕様 §8「旧置き場」）
commands.build-test の変更で機構が壊れるコマンドの分類が変わる前方一致の追加のみで既存の分類を狭めない。追加後に run-tests.sh --ids の 14 本 PASS を確認してから T2 に進む
git mv でなく削除と新規作成になり履歴を失う拡張の由来が追えないgit mv を使い、移動後に git log --follow が移動前のコミットを含むことを確かめる
npm test が移動後に落ちる移動が原因か既存の不具合か切り分けられない移動前に src/vscode-ticket-board/ で npm test を 1 度通して基準を取る
フェーズ 4 単独ではソースのヘッダの参照先が存在しない1 コミット分だけ参照が切れる許容する。フェーズ 6 の docs/ の移動で解消する（フェーズを分けたのは許可範囲の制約。DDR i0020-01）
