# 10-task-ai-asset-implementation-exec スキル 仕様

## 概要・禁止事項

AI アセット実装・テスト実施タスクの内部仕様。対応する要件は [00_requirement/skills/10-task-ai-asset-implementation-exec.md](../../00_requirement/skills/10-task-ai-asset-implementation-exec.md)。処理フローの共通手順は `10_spec/skills/10-task-investigation-exec.md`「実施タスクの共通手順（正）」に従い、ここでは固有部分だけを書く。

禁止事項（共通手順の禁止事項に加えて）:

- 要件・仕様・DDR の書き換え（仕様どおりに作れない場合は逸脱として記録し、設計反映はフィードバック計画へ）
- eval の実行（定義まで。実行は人間の判断）
- 中核（フック・提供コマンド・`settings.json`）を複数まとめて変えてからテストすること
- 自分が止まったときの `WORKFLOW_ENTRY_ENFORCE=0` などの強制無効化（ユーザーの明示があるときだけ）、フックの迂回
- 許可範囲外のファイルへの変更を残すこと

## 呼出条件

- `next` が AI アセット実装チケットを示したとき、全体計画で合意した実行者（サブエージェント）で読み込まれる。中核を含むチケットは `rules/work-defaults.md` の実行者に従う

## IN / OUT

| IN | OUT |
|----|----|
| AI アセット実装計画書（ステップ・許可範囲・テスト方針・参照更新一覧・ロックアウト対策）、要件定義書・仕様書、AI アセット実装チケット群 | アセット本体とテストの変更（コミット済み）、eval の定義、AI アセット実装結果レポート（md + HTML）、完了済みチケット群、結果報告 |

## IN / OUT サンプル

- 作業ログ: 「ステップ 2 `workflow-diff-check.sh` 除外判定を追加 → WD-T06 実行: 失敗（追加前）→ 成功。ステップ 3 の前に `wip/tmp/x.md` を Write して自分が止まらないことを確認」
- 結果報告の見てほしい点: 「機械テストの結果と eval が未実行であること / 検査結果（プレースホルダ・frontmatter・参照更新）が 0 件か / 逸脱一覧 / 中核変更後に自分で動作確認した記録」

## 処理フロー

共通手順に加えて（3 の実施）:

- 計画書の**固定ステップ順**（設定・定義 → 中核 → その機械テスト → スキル・ルール・エージェント → 参照更新）で担当ステップを実施する。アセットの置き場・命名・frontmatter は `20-common-step-ai-asset-creator`、シェルスクリプトは `20-common-step-shell-script`（logger を含む）に従う
- **中核の変更は小さく**: 1 つ変えるごとに機械テストと、計画書のロックアウト対策に書いた最初の操作で自分が止まらないことを確認する。止まったら復旧手順（基準点へ戻す `git checkout <基準点> -- <path>`）で戻し、原因を作業ログに書いてから再試行する
- 機械テストはテスト先行（失敗確認 → 実装 → 成功）で、コマンドと結果を作業ログに残す。**eval は定義**（入力・期待する振る舞い・判定方法）を仕様の ID で書くまでとし、実行しない
- 完了前の**検査**: プレースホルダ（`<...>`・`TODO`・`TBD`）0 件、frontmatter が種別ごとの必須項目を満たす、参照更新一覧の検索語で旧名が 0 件（DDR・用語辞書の別名を除く）。結果はコマンドと件数で作業ログに残す
- 仕様どおりに作れない（フックのイベントで取れない情報がある等）場合は、作れる範囲を作り、逸脱の内容と理由を作業ログ「仕様からの逸脱」に記録する。設計文書は直さない
- `git diff --stat <基準点>` で許可範囲内であることを確認し、範囲外は理由を残して戻す
- 見てほしい点の固定項目: 機械テストの結果と eval 未実行の明記 / 検査結果 0 件 / 逸脱一覧 / 中核変更後の動作確認の記録

## OUT ひな形

AI アセット実装結果レポート（report-view のレポートテンプレート）に次を含める: 作成・更新したアセットの一覧（仕様書の節との対応）/ テスト結果（機械テスト ID × 結果・実行コマンド、eval ID × 定義済み・未実行の明記）/ 検査結果（プレースホルダ・frontmatter・参照更新の件数）/ 仕様からの逸脱の一覧 / 想定と異なった点（自分が止まった事象と復旧）/ 残課題。
