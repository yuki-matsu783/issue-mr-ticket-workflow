# 10-task-design-exec — 正史としての要件定義書と仕様書を書く

共通手順の禁止事項（`10-task-investigation-exec` の冒頭が正）に加えて、ソースコードと `.claude/` 配下に書き込まない（コードに書きたい内容は仕様書のインターフェース定義へ、AI アセットに書きたい内容はフィードバック計画へ）。実装の詳細（コード）に踏み込まない。設計計画書・調査結果レポートを書き換えない（骨子どおりに書けないときは「未解決事項」へ）。既存設計書の本文に変更履歴・経緯を書かない（経緯は DDR）。推測で骨子を変えない。

## 目的

設計計画が決めた骨子を、実装が読める粒度の正史（要件定義書・仕様書）に落とす。判断の経緯は DDR に分ける。

- 要件: `.claude/docs/00_requirement/skills/10-task-design-exec.md`
- 仕様（正。固有手順・OUT ひな形）: `.claude/docs/10_spec/skills/10-task-design-exec.md`
- 処理の共通手順（正）: `10-task-investigation-exec` の「実施タスクの共通手順（正）」

## 手順

共通手順（入力の確認 → 1 枚ずつ着手 → 実施 → レポートに追記 → コミットと完了 → 次へ）は `10-task-investigation-exec` に従う。実施（共通手順 3）の固有部分は次のとおり。

- 書き方の正は `20-common-step-requirement` と `20-common-step-spec`（章立て・EARS・正史のみ・線引き）。置き場はアプリルート `apl/<アプリ名>/` の `docs/` 配下（既存の構成に従う）
- **要件定義書**: 受け入れ条件を EARS（When / Shall、If / Then、Shall not）の受け入れ基準に落とし、前提・制約・依存を書く
- **仕様書**: 入出力・処理フロー・インターフェース・エラーハンドリング・テストシナリオを実装可能な粒度で書き、テストシナリオにテスト ID を振る（実装の DoD と対応させる）
- 「設計チケットで結論を書く」とされた判断点は根拠付きで正史に書き、**採らなかった案と理由を DDR に残す**
- 既存設計書の更新は、本文をその時点の正史に書き換える（差分の履歴を本文に残さない）
- 書き終えたらプレースホルダ 0 件と、用語・インターフェースが既存の設計書と整合していることを確認する
- 骨子どおりに書けない（前提が崩れた）ときは書ける範囲を書き、「未解決事項」と代わりの案をレポートに残す（必要なら設計計画の追加チケットを結果報告で提案する）
- **見てほしい点の固定項目**: 受け入れ条件の落とし込みの網羅 / 結論の根拠と調査結果との整合 / 実装可能な粒度とコードへの踏み込み / 既存設計書との整合

## OUT ひな形

このスキルは固有のテンプレートを持たない。`20-common-step-report-view` の `assets/report.template.md`（と `report.template.html`）をそのまま使い、次を含める。作成・更新した設計書と DDR の一覧 / 判断点の結論とその根拠の要約 / 受け入れ条件 × 受け入れ基準・テストシナリオの対応表 / 想定と異なった点 / 残課題（骨子どおりに書けなかった点・未解決事項）を含める。

## 参照

- 実施タスクの共通手順（正）: `10-task-investigation-exec`
- 設計書の書き方: `20-common-step-requirement` / `20-common-step-spec`
- DDR の形式: `.claude/docs/20_ddr/` の既存の書（アプリ側の DDR も同じ形式）
- 骨子と設計書の一覧の出どころ: `10-task-design-plan` が作った設計計画書

## エラー時の対処

| 状況 | 対処 |
|------|------|
| 骨子どおりに書けない（前提が崩れた） | 骨子を書き換えず、書ける範囲を書いて「未解決事項」と代案をレポートに残す |
| コードに手を入れたくなった | 入れない。仕様書のインターフェース定義に落とすか、残課題として実装フェーズへ回す |
| `.claude/` 配下を直したくなった | 直さない。フィードバック計画へ回す（作業ログ「AI アセットに反映すべき内容」にも残す） |
| 既存設計書と用語・インターフェースが食い違う | 黙って片方に寄せない。整合させた根拠をレポートに書き、判断が要るなら見てほしい点に載せる |
| 共通手順で止まった（TK005 / RV00x / 書き込み拒否） | `10-task-investigation-exec` の「エラー時の対処」に従う |
