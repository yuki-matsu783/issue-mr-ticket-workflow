# 20-common-step-shell-script スキル

## 概要

シェルスクリプト作成の共通ステップの要件を定義する。スキルのスクリプト（`scripts/*.sh`）とフック（`.claude/hooks/**/*.sh`）を作成・変更するときの手順 — 雛形からの作成、規約の適用、共通 logger の組み込み、テストの作成と実行、検査 — を標準化する。共通 logger の実体（`logger.sh`）と sh の雛形はこのスキルが持ち、すべての sh はここから logger を読み込む。

- **背景**: 機構の実体はほぼ bash スクリプトであり、書き方（規約・ログ・テスト・エラー出力）が書き手ごとにぶれると、フックの応答チャネルの汚染や検査の空振りといった機構自体を壊す不具合につながる。共通で使う logger も、置き場と読み込み方が 1 か所に決まっていないと各スクリプトが独自に持ち始める。
- **目的**: どの sh も同じ雛形・同じ規約・同じ logger・同じテストの型で作られ、作成のたびに機械的な検査を通った状態で提出される。
- **スコープ**:
  - 含む: sh の作成・変更の手順、雛形（スクリプト・テスト）、共通 logger の提供と組み込み方、テストの作成と実行、機械的な検査（構文・規約）、結果の記録
  - 含まない: bash 規約の中身（`rules/` の bash-script ルール）、ログの規約の中身（`rules/logger.md`）、各スクリプトの仕様（対象アセットの仕様書）、AI アセット全体の作成手順（`20-common-step-ai-asset-creator`）

---

## ユーザーストーリー

**[As a]** 機構を保守する開発者として、

**[I want]** どのスクリプト・フックも同じ雛形と規約で書かれ、共通 logger を読み込み、テストと検査を通った状態で届いてほしい。

**[So that]** 書き手ごとの流儀の違いで機構が壊れず、ログとテストから不具合を機械的に追えるため。

---

## 受け入れ基準（Acceptance Criteria）

### メインフロー

- When sh ファイルを新規に作るとき、Shall スキルはこのスキルが持つ雛形をコピーして作り、白紙から書いてはならない（雛形は規約の必須事項と共通 logger の読み込みを含む）。
- When sh を書くとき、Shall bash 規約（`rules/` の bash-script ルール）とログの規約（`rules/logger.md`）に従い、ログはこのスキルが提供する共通 logger を読み込んで書かなければならない（独自のログ方式を持たない）。
- When sh を作成・変更したとき、Shall 対応するテスト（正常系・境界・異常系。対象の仕様書のテスト観点に対応）をテストの雛形から作り、既存のテストとあわせて実行し、結果を作業ログに残さなければならない。
- When sh を提出する前に、Shall 機械的な検査（構文検査と、導入されていれば静的検査）に通し、結果を作業ログに残さなければならない。
- When 共通 logger を使うとき、Shall 読み込みはこのスキルの配下にある実体を指す 1 行で行い、コピーして持ち回ってはならない。

### 代替フロー

- If 既存の sh を変更する場合、Then スキルは雛形を当て直さず、既存の構成に合わせて差分を小さくし、規約からの逸脱が既にあれば直すか作業ログに残さなければならない。
- If 静的検査ツールが環境に無い場合、Then スキルは構文検査だけで提出してよく、静的検査を省略したことを作業ログに残さなければならない。

### 例外フロー

- If テストが失敗した場合、Then スキルはテストの無効化や期待値の書き換えで通さず、原因を直すか、仕様側の誤りとして呼び出し元に返さなければならない。
- If 対象スクリプトの仕様書が無い・テスト観点が無い場合、Then スキルは作らず、設計が先であることを呼び出し元に返さなければならない。

### 共通 logger の提供

- When このスキルを導入するとき、Shall 共通 logger の実体と雛形（スクリプト・テスト）がこのスキルの配下に置かれ、他のスキル・フックはそれらを重複して持ってはならない。
- When 共通 logger 自体を変更するとき、Shall 利用中の変更は行わず、AI アセットのフェーズ（設計 → 実装・テスト）で行い、全利用者のテストを回帰させなければならない。

### 他のスキル・機構との整合

- When `20-common-step-ai-asset-creator` がスクリプト・フックを含むアセットを作るとき、Shall sh の作成はこのスキルの手順で行わなければならない。
- When 他のスキルが sh の書き方を説明するとき、Shall not 手順を再掲せず、このスキルを参照しなければならない。

---

## 前提条件

- bash が使える実行環境であること（`rules/` の bash-script ルールの前提と同じ）
- 対象スクリプトの仕様書（テスト観点を含む）が存在すること

---

## 制約条件

- **技術的制約**: 実体は bash。共通 logger は source して使う形で提供する
- **外部的制約**: 規約の中身は `rules/` が正、logger の内部仕様は仕様書が正。このスキルは手順と実体の置き場を担う

---

## 依存関係

- `rules/`（bash-script ルール・logger ルール）
- `20-common-step-ai-asset-creator`（呼び出し元）
- 共通 logger の実体・sh とテストの雛形（このスキルの配下。未作成）
- `logs/` の規定（自己改善ワークフロー機構の要件・DDR i0001-28）

---

## 非機能要件

| 項目 | 説明 |
|------|------|
| 一貫性 | どの sh も同じ雛形・同じ logger・同じテストの型で作られる |
| 検証性 | 提出される sh は構文検査とテストを通っている |
| 保守性 | logger の変更が 1 か所で済み、利用者側の変更を要しない |
