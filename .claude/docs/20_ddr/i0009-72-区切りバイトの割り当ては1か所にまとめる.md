# i0009-72. 区切りバイトの割り当ては 1 か所にまとめる

## 背景

lib は bash の変数に構造を持たせるために制御文字を区切りに使う。0027 の時点で `__HC_US`（`hook-common`）/ `_SC_US`（`scope`）/ `CP_ARGS`（`cmdpos`）の 3 つが**すべて 0x1E** を使っていた。深さが 1 段しか無いうちは衝突しない。

ここに副入力（`hook_read_input` が 1 回の jq で読む `scope-limits.json` などの射影）を載せる必要が出た。同じ 0x1E に載せると、0x1E で区切ったフィールドの中に 0x1E 区切りのレコードが入ることになり、**割った側から入れ子が復元できない**。

計画 0016 は「副入力の行区切りに 0x1D」と書いていたが、実装は違う割り当てになった。stdin のフィールド列が既に 0x1E を使っているので、副入力の**セクション**を 0x1D、レコードの **key/value** を 0x1F に割り当てた。計画がずれたのは、計画時に stdin 側の既存の 0x1E を勘定に入れていなかったため。

## 決定

- 割り当てを**深さ 3 段**に固定する

| バイト | 役割（深さ） | 実体 |
|---|---|---|
| 0x1D | セクション（stdin のフィールド列と副入力のかたまりを分ける） | `__HC_GS` |
| 0x1E | レコード（フィールド / 引数 / 副入力の 1 レコード） | `__HC_US` / `_SC_US` / `CP_ARGS` / `CP_REDIRECTS` / `CP_WRITE_TARGETS` |
| 0x1F | key-value（レコードの中の key と value） | `__HC_RS` / `_SC_KV` |

- **この表を 1 か所（フック共通仕様）に置き、各 lib の節からはそこを参照する**。lib ごとに区切りを書かない
- 新しい構造を足すときは、この 3 段のどこに載るかを**先に決める**。段が足りないなら段を足すのであって、既存のバイトを別の意味で使い回さない
- 内部プレースホルダ（`cmdpos` が使う `\x01` / `\x02` / `\x03`）の割り当ても同じ表の並びに置く

## 理由

- **同じバイトを 2 つの深さで使うと入れ子が復元できない**。深さごとに別のバイトを割り当てるのが唯一の解で、エスケープを導入する（区切りを二重化する）よりも読み書きが速く、素の bash で書ける
- **割り当てが散っていると衝突に気づけない**。0027 で衝突が見つかったのは、たまたま副入力を足す人が 3 つの定義を横断して読んだから。表が 1 か所にあれば「空いているのは 0x1D と 0x1F」が一目で分かる
- **計画と実装がずれた原因も、正が無かったこと**。表があれば計画の時点で気づけた。この DDR の主眼は割り当ての内容そのものより、**割り当ての正を 1 か所に持つ**ことにある
- **jq は文字列リテラル中の生の制御文字を受け付ける**（実測で確認済み）ので、jq の出力に直接載せられる。エスケープを介さないぶん、割り当てさえ間違えなければ安全
- **制御文字はコマンドやパスに現れない**。ユーザーや AI が渡す文字列と衝突する確率が実質ゼロで、伏字化や切り詰めの後でも壊れない

## 却下した案

- **構造を JSON のまま持ち回る**: 取り出しのたびに jq が要る。`i0009-46`（ホットパスの jq は最大 2 回）に反する
- **`declare -A` の連想配列で持ち回る**: 関数の戻り値として渡せず、グローバルの名前空間を lib どうしで共有することになる。名前の衝突が今度は変数名の側で起きる
- **既存の 0x1E を副入力に譲り、`CP_ARGS` を別のバイトに移す**: 呼び手（`cmdpos_args` を使うフックすべて）に影響が及ぶ。後から来た側が空いているバイトを取るほうが変更が小さい
- **各 lib が自分の区切りを自由に決める（現状維持）**: 衝突が起きたことがこの DDR の背景そのもの
- **区切りを廃してエスケープ方式（`\x1e` を `\\x1e` に置換）にする**: 置換と復元が全経路に要り、`i0009-68` で問題になった長い文字列のパターン照合を増やす

## 影響

- `10_spec/フック共通仕様.md` §7（`cmdpos` の出力の形。区切りバイトと内部プレースホルダの割り当て表をここに置き、§1 の副入力と §8 の `scope.sh` から参照する）
- 実装は 0027 で反映済み（`__HC_GS` / `__HC_US` / `__HC_RS` の定義と、`scope.sh` の `_SC_US` / `_SC_KV`）
- 関連: `i0009-47`（副入力は `--rawfile` と `fromjson` で読み、破損で判定ごと落とさない）・`i0009-63`（`SC_TARGETS` は同じ 0x1E 区切りのスカラ）・`i0009-46`（jq は最大 2 回）
- **注意**: 変数名は ASCII の呼称と一致していない（`__HC_US` が 0x1E = ASCII では RS、`__HC_RS` が 0x1F = ASCII では US）。表を読む側は**名前ではなくバイトの値で照合する**。名前を直すなら、実体と呼び手を同じ変更で揃える（`i0009-62` の規約）
