# i0009-45. BG のテスト ID を通番に直し、語彙表の全要素を踏破する

## 背景

`block-direct-git` のテスト観点表に 2 つの不備があった。

1. **ID と並びの乱れ**: 表は `BG-T01`〜`T08` → **`BG-T09b`**（PowerShell のヒアストリング。正常系）→ `BG-T10` → **`BG-T09`**（入力 JSON 不正。異常系）の順に並んでいた。`BG-T09b` は名前だけ見れば `BG-T09` の派生に見えるが、両者は無関係である。`run-tests.sh` の抽出正規表現（`[A-Z]{2,6}-[TE][0-9]{2}[a-z]?`）には適合するので、**機械では検出されない**
2. **語彙表の踏破漏れ**: 制御方式 3 は「コミットを生成するサブコマンド」として `revert` / `cherry-pick` / `am` / `rebase` / **`commit-tree`** を挙げ、**`stash` は対象外**・`merge` は例外として許可すると定める（`i0004-07`）。`BG-T10` は `revert` / `cherry-pick` / `rebase` / `am` と `merge` しか踏んでおらず、`commit-tree` と `stash` が抜けていた。`HK-T05`（`cmdpos.sh`）には「語彙表の全要素踏破」を課しているのに不揃いだった

## 決定

- **`BG-T09b` → `BG-T09`**（PowerShell の正常系。`BG-T08` の直後という位置はそのまま）
- **もとの `BG-T09`（入力 JSON 不正）→ `BG-T11`**（表の末尾）。表の並びを `T01`〜`T11` の通番にする
- **`BG-T10` に 2 要素を足す**: `git commit-tree abc123` が WF401、`git stash` は通る。観点の文言を「制御方式 3 の『コミットを生成するサブコマンド』の**全要素**」「**明示的に対象外の 2 つ**（`merge` / `stash`）は通る」と、語彙表との対応が分かる形にする
- `i0009-08`（テスト ID の接頭辞）の「`BG-T09b` のような枝番は正規表現に合うので現状維持でよい」は、**抽出の規則を変えない**という趣旨として残し、`BG-T09b` 自体を直したことを注記する

## 理由

- **枝番は「同じ観点の派生」を表す記法**として読まれる。無関係の観点に付けると、読み手が `BG-T09` を探して混乱する。ID の付け直しは参照が 1 ファイルに閉じている今が一番安い
- **入力不正の観点を末尾に置く**のは他のフックの表と揃う（正常系 → 異常系 → 境界 → 入力不正）。通番に直すのと同時にやれば追加のコストが無い
- **語彙表を持つ判定は全要素を踏むのが規約**（`HK-T05` に既に課している）。踏まない要素があると、実装で落としても誰も気づかない。`commit-tree` は低レベルだが `commit.sh` の規約検査を確実に迂回する経路で、`stash` は「対象外」という判断そのものがテストで固定されるべきもの
- **`git commit-tree abc123` という形を選ぶ**理由: `git commit-tree $(git write-tree)` にするとコマンド置換が実行位置として別の判定（`BG-T04`）を呼び、観点が混ざる

## 却下した案

- **`BG-T09b` をそのまま残して並べ替えだけ行う**: 枝番が無関係の派生に見える問題が残る
- **`BG-T09b` → `BG-T11` にして末尾へ移す**: PowerShell の正常系が `BG-T08`（PowerShell の異常系）から離れる。観点の並びが壊れる
- **`commit-tree` / `stash` を新しい `BG-T12` として足す**: `BG-T10` が既に「コミットを生成するサブコマンド」の観点そのものなので、同じ観点を 2 行に分ける理由が無い
- **`run-tests.sh` の正規表現から `[a-z]?` を外して枝番を機械的に禁じる**: `i0009-08` が「抽出の規則は変えない」と決めており、他のアセットの ID にも影響する。今回の 1 件は目視で直せば足りる
