# 10-task-design-plan の eval 定義

## 目的

`10-task-design-plan` の SKILL.md（計画タスクの共通手順 + 設計計画の固有手順）を読み込んだときに、骨子までで止めること・「対象なし」の扱い・推測で結論を決めないこと・次の計画チケットを 1 枚だけ作ることが安定するかを確かめる。

## 評価シナリオ

各行は仕様書「テスト観点（eval）」の行と 1:1 に対応する（eval ID が対応の鍵）。

| eval ID | 入力プロンプトと状況 | 期待する振る舞い | 判定方法 | 添付ファイル |
|---------|--------------------|-----------------|---------|-------------|
| DGP-E01 | 調査結果レポートを入力に、アプリの設計計画を書く | 文書の一覧（新規 / 更新・置き場・骨子）と判断点の結論方針を書き、設計の本文を書き始めない | 計画書に骨子までしか無いこと | `assets/design-plan.template.md` |
| DGP-E02 | 受け入れ条件が既存の設計文書の変更を必要としないと分かった | 「対象なし」と根拠を書き、設計チケットを起こさず次の計画チケットだけを作って完了する | 起票したチケットの種類と枚数 | なし |
| DGP-E03 | 調査結果だけでは判断点 2 の結論方針を立てられない | 推測で決めず、「設計チケットで結論を書く」か「調査の追加が要る」として結果報告に書く | 結果報告の記載と、計画書に推測の結論が無いこと | なし |
| DGP-E04 | 機能のまとまりが 3 つあり、設計チケットを 3 枚起こす場面 | 先行チケットで依存を表し、次の計画チケットを 1 枚だけ作る。それより先のチケットは作らない | `predecessors` と、起票したチケットの種類 | なし |

## 比較条件

- with: Skill ツールで `10-task-design-plan` を読み込んだ状態で各シナリオのプロンプトを与える
- without: SKILL.md を読み込まず、`CLAUDE.md` と対象の要件書・仕様書だけを文脈に置いた状態で同じプロンプトを与える
- 実施回数: シナリオごとに with / without を各 3 回

## 効果ありの判定基準

- DGP-E01: with の 3 回すべてで骨子までに留まり、without で 1 回以上設計本文を書き始める
- DGP-E02: with の 3 回すべてで次の計画チケット 1 枚だけ、without で 1 回以上不要な設計チケットを作る
- DGP-E03: with の 3 回すべてで保留が明示され、without で 1 回以上推測の結論が書かれる
- DGP-E04: with の 3 回すべてで `predecessors` が付き次の計画チケットが 1 枚、without で 1 回以上先回りして作る
- 4 シナリオのうち 3 つ以上で上記を満たせば効果あり。差が出ないシナリオは SKILL.md の該当手順の文言を見直す対象として記録する
