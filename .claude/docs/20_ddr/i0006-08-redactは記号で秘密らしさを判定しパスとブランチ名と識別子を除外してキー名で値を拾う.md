# i0006-08. redact は「40 文字以上の語」からパス・ブランチ名・識別子を除外し、スラッシュを含む秘密はキー名で拾う

## 背景

フックの記録（`logs/hooks/decisions.jsonl` 等）はコマンド文字列を含むため、`hook-common.sh` の `redact` が秘密らしい語を `***` に置き換える。当初の仕様 §3 は「40 文字以上の 16 進 / base64 様の語」を一律に対象にしていた。実装（issue #6 チケット 0014・0025）で次が分かった。(1) base64 の文字集合は `/` を含むため、長いパス（`.claude/skills/20-common-step-.../scripts/tests/test_x.sh`）が丸ごと消えて記録が読めない。(2) ブランチ名（`feature-6-workflow-foundation-...`）やチケット名・関数名など 40 文字を超える識別子も消える。(3) 一方で AWS のシークレットアクセスキーは `/` を含み得るので、`/` を除外すると拾えなくなる。(4) 置換結果 `***` にパターンが再一致すると置換が止まらない（実装結果レポート 0013 の逸脱 D-24、レビュー F-10、テスト HK-T10）。

## 決定

- 40 文字以上の語の規則に除外条件を足す: `/` を含む語（パスと区別できない）、ハイフンを 2 個以上含み大文字を含まない語（ブランチ名・チケット名・スキル名）、英小文字と `_` だけの語（識別子）は秘密と見なさない
- `/` を含む秘密は**キー名で拾う**: `token=` / `password=` / `passwd=` / `secret=` と、`api` `access` `private` `auth` `client` `secret_access` に `_key=` / `-key=` / `key=` が続くキー（大文字小文字を問わない）の値は、形を問わずマスクする
- 各パターンは `***` に再一致しない形に書く（`*` を文字集合に含めない）

## 理由

- 記録の目的は「なぜ止まったか」を後から読むことで、パスやブランチ名が消えると目的を果たせない。誤検知（読めない記録）と見逃し（秘密の漏れ）のうち、見逃しの方は「キー名で拾う」で別に塞げる
- 秘密の多くは環境変数やオプションのキー名と一緒に現れる（`AWS_SECRET_ACCESS_KEY=...`、`--api-key ...`）。裸の 40 文字語より、キー名の方が秘密らしさの手がかりとして確実
- 除外条件は「人間が読むために付けた名前」の形（区切りにハイフンやアンダースコアを使い、大文字を混ぜない）に寄せた。秘密の乱数列がこの形になる確率は低い

## 却下した案

- **40 文字の規則を廃止しキー名だけにする**: キー名を伴わない裸のトークン（コマンドの引数に直接貼られたもの）を見逃す。GitHub / GitLab のトークンは接頭辞で拾えるが、それ以外の乱数列を拾う手段が無くなる
- **`/` を含む語も対象のまま、パスだけ白名単で除外する**: リポジトリ内のパスは列挙できるが、引数に現れる任意のパス（一時ファイル・外部ツール）は列挙できない
- **記録にコマンド文字列を残さない**: 判定の根拠が消え、ヘッドレス実行で「なぜ拒否されたか」を後から追えない

## 影響

- `10_spec/フック共通仕様.md` §3（マスク対象）と §11 HK-T10
- `.claude/hooks/lib/hook-common.sh` の `redact`（実装は 0025 で済み。仕様が実装に追いついた形）
- 記録の読み手: `***` の位置がキー名の直後にあれば値だけが消えている
