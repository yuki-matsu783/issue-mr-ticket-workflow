# 10-task-design-feedback-exec — 実装を根拠に設計書を正史へ戻す

共通手順の禁止事項（並列実施しない、サブエージェントを入れ子起動しない、完了済みチケットを戻さない）に加えて、ソースコード・テストを書き換えない（実装の誤りを見つけてもコードは直さず「実装漏れ」として報告する）。設計書の本文に変更履歴・経緯を書かない（経緯は DDR）。実装漏れを設計書側で吸収しない。設計反映計画書の差分一覧の行を削除しない（消込は「一致」への更新、新差分は行の追加）。実装に根拠の無い設計書の変更をしない。

## 目的

設計書を「今の実装が正しいと言える状態」に戻す。判断の経緯は DDR に分け、実装側の不足はコードを触らずに報告へ回す。

- 要件: `.claude/docs/00_requirement/skills/10-task-design-feedback-exec.md`
- 仕様（正。固有手順・OUT ひな形）: `.claude/docs/10_spec/skills/10-task-design-feedback-exec.md`
- 処理の共通手順（正）: `10-task-investigation-exec` の「実施タスクの共通手順（正）」

## 手順

共通手順（入力の確認 → 1 枚ずつ着手 → 実施 → レポートに追記 → コミットと完了 → 次へ）は `10-task-investigation-exec` に従う。実施（共通手順 3）の固有部分は次のとおり。

- 差分一覧の担当行ごとに、**実装（ファイル・行・テスト）を根拠に**設計書の該当節をその時点の正史へ書き換える。分類「設計に無い決定」は追記、「設計書が古い」は置き換え。いずれも採らなかった案・理由を DDR に残す
- 仕様書のテスト ID を実装のテストと突き合わせ、名称・番号のずれを**設計書側で**合わせる（実装のテストは触らない）
- 反映した行は計画書の差分一覧を「一致」に更新する（消込）。作業中に新しい差分を見つけたら行を追加して分類し、担当範囲なら反映、そうでなければ残課題に書く
- 実装の誤り（設計書が正しく実装が違う）を見つけたら、コードは直さず差分一覧の分類を「実装漏れ」に改め、レポートの実装漏れ一覧に載せる
- 書き終えたら設計書のプレースホルダ 0 件と、用語・インターフェースの整合を確認する
- **見てほしい点の固定項目**: 書き戻しと実装の実態の一致（根拠の行）/ 差分一覧の消込漏れ / 新たに見つかった差分・実装漏れ / DDR に経緯が残っているか

## OUT ひな形

このスキルは固有のテンプレートを持たない。`20-common-step-report-view` の `assets/report.template.md`（と `report.template.html`）をそのまま使い、次を含める。更新した設計書・節・DDR の一覧（根拠とした実装の箇所）/ 差分一覧の消込結果（残った行とその理由）/ 実装漏れ一覧（実装の追加が要る点）/ 想定と異なった点（新差分）/ 残課題を含める。

## エラー時の対処

| 状況 | 対処 |
|------|------|
| 実装が明らかに誤っている | コードを直さない。分類を「実装漏れ」に改め、レポートの実装漏れ一覧に載せる |
| 差分一覧に無い差分を見つけた | 行を削除・改変せず、行を追加して分類する。担当範囲外なら残課題に書く |
| 書き戻す根拠が実装に見つからない | 書き換えない。根拠が無い旨を残課題に書き、見てほしい点に載せる |
| 設計書の用語が既存と食い違う | 黙って片方に寄せない。整合させた根拠をレポートに書く |
| 共通手順で止まった（TK005 / RV00x / 書き込み拒否） | `10-task-investigation-exec` の「エラー時の対処」に従う |
