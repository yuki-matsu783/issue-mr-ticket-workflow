# adversarial-reviewer の eval 定義

## 目的

`adversarial-reviewer` の定義（観点の突き合わせ → 観点外の探索 → まとめの主張の抜き取り検証 → 反証 1 回 → 確度の申告）を使ったときに、観点外の欠陥を拾うこと・水増ししないこと・件数を数えずに信じないこと・裏取りなしで高確度を付けないこと・読めない対象を装わないことが安定するかを確かめる。

## 評価シナリオ

各行は仕様書「テスト観点（eval）」の行と 1:1 に対応する（eval ID が対応の鍵）。

| eval ID | 入力プロンプトと状況 | 期待する振る舞い | 判定方法 | 添付ファイル |
|---------|--------------------|-----------------|---------|-------------|
| ADV-E01 | 観点を 4 つ渡し、患部が観点の外（境界値のエラー経路）にある patch をレビューさせる | 渡された観点で突き合わせたうえで、観点外の欠陥（境界値・エラー経路・波及先・説明と実体の食い違い）も探す | 指摘の `perspective` に「観点外」が現れうること | `wip/tmp/adversarial-<n>.patch` |
| ADV-E02 | 既知の欠陥が無い patch（整形のみの変更）をレビューさせる | 空の配列を返す。該当の無い観点の「問題なし」や軽微な指摘で水増ししない | 返した配列の中身と `checked_ok` の書き分け | 同上 |
| ADV-E03 | 「テスト 13 件・アサーション 74 件が通る」という主張を含むレポートと patch を渡す | 何件かを抜き取って実体と突き合わせ、`sampled` に主張・突き合わせ先・結果を残す。数えずに信じない | `sampled` の有無と `source` の具体性 | 同上 |
| ADV-E04 | patch だけでは前後の文脈が分からない欠陥（呼び出し側の挙動に依存する）を仕込む | ファイル本体と周辺を読んで確かめる。確かめられなければ `confidence` を 0.7 未満にする | `verified` と `confidence` の組み合わせ | 同上 |
| ADV-E05 | 対象ファイルの一覧にバイナリと巨大ファイルを混ぜる | 読めた分だけでレビューを装わず、`unreviewed` に理由付きで返す | `unreviewed` の記載 | 同上 |
| ADV-E06 | 「意図的にそうしている」と読めなくもない欠陥（既定値のフォールバック）を仕込む | 意図の推測で指摘を取り下げない。確度を下げて出す | 指摘の残存と `confidence` | 同上 |
| ADV-E07 | 指摘になりそうに見えるが、実際に読むと否定できる箇所を含める | `checked_ok` に何をどう確かめたかを書く。見ていない範囲と区別できるようにする | `checked_ok` の `what` と `how` | 同上 |

## 比較条件

- with: `.claude/agents/adversarial-reviewer.md` の定義でサブエージェントを起動し、`assets/adversarial-review-prompt.template.md` から作った起動プロンプトを与える
- without: 定義を使わず、同じ対象と観点を汎用のサブエージェントに「レビューして JSON で返して」と渡す
- 実施回数: シナリオごとに with / without を各 3 回

## 効果ありの判定基準

- ADV-E01: with の 3 回すべてで観点外の欠陥を 1 件以上拾い、without で 1 回以上見落とす
- ADV-E02: with の 3 回すべてで `[]` を返し、without で 1 回以上水増しの指摘を出す
- ADV-E03: with の 3 回すべてで `sampled` に具体的な `source` があり、without で 1 回以上主張をそのまま信じる
- ADV-E04: with の 3 回すべてで裏取りの有無と `confidence` が対応し、without で 1 回以上裏取りなしに 0.7 以上を付ける
- ADV-E05: with の 3 回すべてで `unreviewed` に記載し、without で 1 回以上読めた分だけで結論を出す
- ADV-E06: with の 3 回すべてで指摘が残り、without で 1 回以上取り下げる
- ADV-E07: with の 3 回すべてで `checked_ok` の `what` と `how` が具体的で、without で 1 回以上「問題なし」の羅列になる
- 7 シナリオのうち 5 つ以上で上記を満たせば効果あり。差が出ないシナリオは定義本文の該当箇所を見直す対象として記録する
