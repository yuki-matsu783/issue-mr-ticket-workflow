# チケットボード拡張 要件定義

## 概要

チケット駆動ワークフローの作業領域 `wip/10_tickets/` にあるチケット Markdown を読み取り、状態ディレクトリを列としたカンバンボードを VS Code の Webview に表示する拡張。読み取り専用で、チケットの状態は変更しない。

- **背景**: チケットの残りを知るには 4 つのディレクトリを `ls` して Markdown を開く必要がある。作業の合間に「今どれが残っているか」を把握するたびにエディタを離れることになる。
- **目的**: 残チケットとその属性を、エディタを離れずに一目で把握できるようにする。
- **スコープ**:
  - 含む: チケットの走査・表示、列ごとの件数、カードからのファイル表示、ファイル変更への追従、不備のあるチケットの提示
  - 含まない: チケットの状態変更（着手・完了・取り消し）（担い先: 提供コマンド `ticket.sh`）、依存グラフの表示（担い先: 今回のスコープ外。将来の別 issue）、`wip/20_plans/` と `wip/30_reports/` の可視化（担い先: 同上）、GitHub の issue / PR 情報との連携（担い先: 同上）、Marketplace への公開（担い先: 同上）

---

## ユーザーストーリー

**[As a]** チケット駆動ワークフローで作業する開発者として、

**[I want]** 残っているチケットとその属性を VS Code 上で一覧したい、

**[So that]** 次に何をすべきかを、ディレクトリを辿らずに判断できるため。

---

## 受け入れ基準（Acceptance Criteria）

### メインフロー

- **When** 利用者がコマンドパレットから「チケットボードを開く」を実行したとき、**Shall** 未着手・作業中・完了・取り消しの 4 つの状態を列として並べたボードを表示する
- **When** ボードを表示するとき、**Shall** 各チケットについて番号・タイトル・チケットの種類・実行者・人間レビュー要否・敵対的レビュー要否を読み取れるカードとして、対応する状態の列に置く
- **When** ボードを表示するとき、**Shall** 列ごとのチケット件数と、残チケット（未着手と作業中の合計）の件数を表示する
- **When** 利用者がカードを選択したとき、**Shall** そのチケットの Markdown をエディタで開く
- **When** チケットのファイルが追加・削除・編集され、または状態の異なるディレクトリへ移動されたとき、**Shall** ボードの表示をその変化を反映した内容に更新する
- **When** 利用者がコマンドパレットから「チケットボードを更新」を実行したとき、**Shall** その時点のチケットを読み直してボードを更新する
- **When** ボードが既に開かれている状態で「チケットボードを開く」が実行されたとき、**Shall** 新しいボードを増やさず既存のボードを前面に出す

### 代替フロー

- **If** チケットが 1 枚も無いとき、**Then** エラーとせず、チケットが無いことが読み取れる表示にする
- **If** ある状態の列にチケットが 1 枚も無いとき、**Then** その列を消さず、件数 0 の空の列として表示する
- **If** チケットのタイトルが本文の見出しから読み取れないとき、**Then** ファイル名を代わりに表示する

### 例外フロー

- **If** チケットの frontmatter が解析できない、または必要な項目が欠けているとき、**Then** 処理を中断せず、そのチケットを不備のあるカードとして表示し、何が読み取れなかったかを示す
- **If** チケットの種類が既知の一覧に無い値のとき、**Then** その値をそのまま表示したうえで、既知でないことを示す
- **If** ファイル名の番号と本文の見出しの番号が食い違うとき、**Then** ファイル名の番号を採用し、食い違いを不備として示す
- **If** ワークスペースが開かれていない、または `wip/10_tickets` が存在しないとき、**Then** ボードを開かず、対象が見つからない旨を利用者に伝えて終了する
- **When** いずれかのチケットの読み取りに失敗したとき、**Shall not** 他のチケットの表示を取りやめる
- **Shall not** チケットのファイル、その状態、およびワークスペースのいかなるファイルも変更しない

### 他のスキル・機構との整合

- **Shall** チケットの状態を、ファイルが置かれている状態ディレクトリから判定する（frontmatter の項目からは判定しない）
- **Shall** 状態ディレクトリの直下にある、4 桁の番号で始まる Markdown だけをチケットとして扱う
- **Shall** frontmatter を、提供コマンドが書き出し提供ライブラリが読み取る形の範囲で解釈する

---

## 前提条件

- ワークスペースの直下に `wip/10_tickets/` があり、その下に未着手・作業中・完了・取り消しの 4 つの状態ディレクトリが存在する
- チケットは提供コマンド `ticket.sh` が作成・更新したものである（人手で編集されている場合があることは例外フローで扱う）
- 利用者の VS Code が、拡張が宣言する最小バージョン以上である

---

## 制約条件

- **技術的制約**: 拡張のうち VS Code の API に触れる部分は、VS Code の外では実行できないため自動テストの対象にできない。受け入れ基準のうち「カードを選択したとき」と「ワークスペースが開かれていないとき」の確認は、利用者の環境での手動確認に委ねる
- **技術的制約**: ボードの表示内容は外部のネットワーク資源に依存しない
- **ビジネス的制約**: チケットの状態を変更する経路を作らない。状態遷移の唯一の経路が提供コマンドであるという前提を崩さない
- **外部的制約**: チケットの形式は提供コマンドが定めており、拡張はそれに追従する。拡張の都合で形式を変えない

---

## 依存関係

- チケットの形式: 提供コマンド `ticket.sh` とそのテンプレート、チケットの種類の一覧 `task-types.tsv`
- frontmatter の解釈範囲: 提供ライブラリ `frontmatter.sh` が扱う形
- 実行環境: VS Code の拡張ホスト

---

## 非機能要件

| 項目 | 説明 |
|------|------|
| 堅牢性 | 1 枚のチケットの不備が他のチケットの表示を妨げない。読み取れなかった項目は欠落として扱い、例外で処理を止めない |
| 追跡性 | 不備のあるチケットについて、どの項目が読み取れなかったかを利用者が識別できる |
| 一貫性 | 表示されるチケットの集合と件数は、その時点のファイルシステムの状態と一致する |
| 応答性 | チケットのファイルが変化してから表示に反映されるまでの遅延は、利用者が待たされたと感じない範囲に収める |
| 安全性 | 表示するボードは外部の資源を読み込まない。チケットの本文に含まれる文字列が表示を壊したり意図しない動作を起こしたりしない |
| 再現性 | 同じチケットの集合からは常に同じボードが得られる |
