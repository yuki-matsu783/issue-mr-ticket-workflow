# 10-task-design-feedback-exec の eval 定義

## 目的

`10-task-design-feedback-exec` の SKILL.md（実施タスクの共通手順 + 設計反映の固有手順）を読み込んだときに、要件を先に直すこと・「要件との対応」表の行数を揃えること・DDR との矛盾を同じ変更の中で解消することが安定するかを確かめる。

## 評価シナリオ

各行は仕様書「テスト観点（eval）」の行と 1:1 に対応する（eval ID が対応の鍵）。

| eval ID | 入力プロンプトと状況 | 期待する振る舞い | 判定方法 | 添付ファイル |
|---------|--------------------|-----------------|---------|-------------|
| DFE-E01 | 計画書が指す食い違い 5 件（うち 2 件は要件側の誤り）を書き戻す | 要件を先に直してから仕様を直す。要件側の誤りを仕様側の辻褄合わせで吸収しない | 変更の順序と、要件・仕様の整合 | 設計反映計画書 |
| DFE-E02 | 書き戻しの結果、受け入れ基準が 2 件増えた | 仕様の「要件との対応」表に行を足し、行数を受け入れ基準の件数に揃える | 表の行数と基準の件数の一致 | なし |
| DFE-E03 | 書き戻した内容が、マージ済みの DDR の結論と矛盾する | 片方だけ直さず、矛盾する文書を特定して同じ変更の中で揃える。マージ済みの DDR は新しい DDR で置き換える | 変更した文書の範囲と DDR の扱い | なし |

## 比較条件

- with: Skill ツールで `10-task-design-feedback-exec` を読み込んだ状態で各シナリオのプロンプトを与える
- without: SKILL.md を読み込まず、`CLAUDE.md` と対象の要件書・仕様書だけを文脈に置いた状態で同じプロンプトを与える
- 実施回数: シナリオごとに with / without を各 3 回

## 効果ありの判定基準

- DFE-E01: with の 3 回すべてで要件 → 仕様の順になり、without で 1 回以上仕様だけで吸収する
- DFE-E02: with の 3 回すべてで表の行数が一致し、without で 1 回以上ずれる
- DFE-E03: with の 3 回すべてで矛盾が同じ変更の中で解消され、without で 1 回以上片方だけ直す
- 3 シナリオのうち 2 つ以上で上記を満たせば効果あり。差が出ないシナリオは SKILL.md の該当手順の文言を見直す対象として記録する
