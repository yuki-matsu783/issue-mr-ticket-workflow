# i0009-25. 登録表は `command` 文字列の材料を持ち、HK-T01 は変換で照合しない

## 背景

§1 の登録表は 17 行で、HK-T01 が「この表と `settings.json` を行単位で照合する」ことになっている。しかし表の 5 列（位置 / イベント / matcher / フック / 役割）だけでは `command` 文字列を組み立てられない。

- **引数を取る登録が 2 行**: SubagentStop と Stop の `post-push-usage-report` は `--accumulate` を渡す。表のフック列の表記は `command` 文字列の定義ではない
- **実体のディレクトリと登録先イベントが一致しない行が 4 行**:

| 実体 | 登録先イベント |
|---|---|
| `12-SubagentStart/subagent-start-check.sh` | PreToolUse（`Agent`） |
| `13-SubagentStop/subagent-stop-check.sh` | PostToolUse（`Agent`） |
| `22-PostToolUse/post-push-usage-report.sh` | SubagentStop |
| `22-PostToolUse/post-push-usage-report.sh` | Stop |

ディレクトリ名は**主たるイベント**を表す（DDR `i0001-24`）。§1 の「実体: `.claude/hooks/<NN-Event>/<name>.sh`」にはその旨が書かれていなかったため、実装者は `11-Stop/post-push-usage-report.sh` を作るべきか迷う。境界レビュー（付録 A の R12）の指摘。

## 決定

- §1 の「実体」の説明に「**`<NN-Event>` は主たるイベント**で、登録先のイベントと一致しないことがある（DDR `i0001-24`。実際に一致しない登録が 4 行ある）」を明記する
- 登録表の直後に「**表に現れない登録の細部**（HK-T01 が照合する `command` 文字列の材料）」として、引数を取る 2 行と一致しない 4 行を列挙する
- **HK-T01 は「イベント名 → ディレクトリ」の機械的な変換で照合しない**。この表に対応する **17 行分の `command` 文字列の一覧**を検査の期待値として持つ

## 理由

- 変換で照合しようとすると、4 行の例外を変換規則に埋め込むことになる。例外が規則の中にあると、次に例外が増えたときにテストの規則を書き換えることになり、「表が正」という建て付けが崩れる
- **期待値を素の文字列で持てば、表を変えたらテストが落ちる**という関係が素直に成立する。17 行なので手で書ける量
- ディレクトリを「主たるイベント」と決めているのは要件書の置き場（`i0001-24`）と揃えるためで、この決定を覆すと 1:1:1（アセット : 要件 : 仕様）の対応が崩れる。覆さずに、一致しないことを明記する方が安い

## 却下した案

- **実体を登録先イベントのディレクトリに置き直す（同じスクリプトを複数箇所に置く / シンボリックリンク）**: 実体の重複は禁止事項（同じ判定が 2 か所になる）。シンボリックリンクは Windows で扱いが不安定
- **登録表に `command` 列を足して 17 行すべてに書く**: 表が横に長くなり、`${CLAUDE_PROJECT_DIR}` を含む文字列が 17 回繰り返される。注記で例外だけを挙げる方が読める
- **`--accumulate` を引数ではなくイベント名（`hook_event_name`）で分岐する**: 技術的には可能だが、引数が明示されている方が `settings.json` を読んだ人に意図が伝わり、テストの期待値も具体的になる。現行の形を維持する

## 影響

- `10_spec/フック共通仕様.md` §1（「実体」の説明・登録表の直後の注記）・§11（HK-T01）
- **0016 へ**: HK-T01 の期待値として 17 行分の `command` 文字列の一覧を用意する（`i0009-20` の絶対パス形式を含む）
- 関連: `i0001-24`（要件書はスクリプト単位で主たるイベントの下に置く）
