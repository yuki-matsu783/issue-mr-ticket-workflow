# i0004-02. 全体まとめは添付後に毎回 push して統括レポートを履歴に載せ、報告に片付け前コミットのリンクを添える

## 背景

従来の順序は「添付 → （レビュー要の場合のみ push + レビュー依頼）→ 片付け → push → draft 解除」で、レビュー不要の既定では統括レポート・各レポートが**一度も push されずに片付けで消える**ことがあった。squash merge 後は wip の履歴が main に残らないため、HTML レポートを後から取り出す手段が MR への添付だけになる。また draft 解除の報告からレポートに辿る導線が無かった。

## 決定

- HTML 添付まで終えたら、人間レビューの要否によらず**毎回 push する**（統括レポートを含む成果物を、片付けで消える前にブランチの履歴に載せる）。順序は 別 issue 起票 → 衝突解消 → 統括レポート → MR 本文最終化 → 添付 → **push** →（レビュー要のみ依頼）→ 片付け → push → draft 解除
- 片付けの提供コマンド（cleanup）は前提に「統括レポートを含む HEAD が push 済み」を加え、片付け直前の HEAD の SHA を `pre_cleanup_sha` として `logs/merge-state.json` に記録する
- draft 解除（ready）の出力と報告に、`pre_cleanup_sha` に固定した作業領域リンク（`.../tree/<SHA>/wip/30_reports`）を含め、片付け後も HTML レポートを簡単にダウンロードできるようにする

## 理由

- push 済みのコミットはブランチ削除後もホスティング上で SHA から辿れることが多く、添付と二重の取り出し口になる
- 「レビュー要のときだけ push」だと、既定（レビュー不要）の運用でレポートが履歴に残らないという逆転が起きていた
- コミット固定のリンクは「MR 本文・コメントに wip パスを恒久参照として書かない」規則（ブランチ相対の参照が対象）と衝突しない。報告（チャット）に添える導線として最も安い

## 却下した案

- **レビュー要のときだけ push（従来）**: 既定の運用でレポートが履歴に残らない
- **報告にリンクを含めず添付だけに頼る**: 添付が縮退（非公式エンドポイントの廃止など）した環境で取り出し口が消える
- **HTML を main に残す**: 片付け設計（wip は main に残さない）と衝突する

## 影響

- `00_requirement/skills/10-task-overall-summary.md`・`10_spec/skills/10-task-overall-summary.md`（順序・FN001・pre_cleanup_sha・ready の出力）
- `logs/merge-state.json` のスキーマ（`pre_cleanup_sha` の追加）
