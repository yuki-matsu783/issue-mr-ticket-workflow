# 20-common-step-requirement — 要件は外から見える振る舞いだけを、正史として書く

内部構造（スクリプト名・コマンド・判定順・スキーマ・実パス）は書かず仕様書へ回す。経緯（検討・却下案・変遷）は本文に書かず DDR へ分離する。本文に変更履歴・追記の印を残さない。「関連するドキュメント」「レビュー記録」の節を置かない。合意されていない決定を書かない。同じ内容を複数の書に書かない（1 か所に書き、他は参照）。書く内容の合意は呼び出し元が担う。

- 要件: `.claude/docs/00_requirement/skills/20-common-step-requirement.md`
- 仕様（正。章順・フロー節の順序・DDR の形式・eval ID RQ-E01〜03）: `.claude/docs/10_spec/skills/20-common-step-requirement.md`

## 手順

1. **配置と命名**: 対象の種別からディレクトリ（`skills/` / `hooks/<イベント番号ディレクトリ>/` / `agents/` / `rules/`）を決め、対象と同名のファイルにする（1 対象 1 書。2 アセットを 1 書にまとめない）。横断的な内容はどれか 1 つの書に寄せ、他からは参照する
2. **新規作成**: `cp .claude/skills/20-common-step-requirement/assets/requirements.template.md .claude/docs/00_requirement/<種別>/<対象名>.md` し、frontmatter（`type: requirement` / `title` / `description` / `tags` / `keywords`）と章を順に埋める。章順は 概要（背景・目的・スコープ）→ ユーザーストーリー → 受け入れ基準 → 前提条件 → 制約条件 → 依存関係 → 非機能要件。各章のガイド（HTML コメント）は記入時に消す。スコープの「含まない」には担い先（どのスキル・タスクが担うか）を添える
3. **受け入れ基準**: EARS（`When 〜 Shall` / `If 〜 Then` / `Shall not`）で書き、節を メインフロー → 代替フロー → 例外フロー → 他のスキル・機構との整合（規約・整合）の順に置く。見出しは「メインフロー」等の規定文言で始める（補足の後置は可）
4. **線引きの判定**: 記述ごとに「外部の観察者（利用者・レビュアー）に見えるか」を問い、見えないもの（実現手段）は仕様書へ回す。既存の要件書に内部構造を見つけたら、仕様書へ移す提案を呼び出し元に返す
5. **経緯の分離**: 決定に検討・却下案があれば DDR `.claude/docs/20_ddr/i<issue 番号 4 桁>-<連番 2 桁>-<タイトル>.md`（`type: ddr`。背景 / 決定 / 理由 / 却下した案 / 影響）を起こし、本文には現在の正だけを書く
6. **更新**: 既存の書は該当箇所を直接書き換える（履歴・「以前は〜」を残さない）。他の書と矛盾したら、矛盾する書を特定して呼び出し元に返す（片方だけ直さない）
7. **セルフレビュー**: 章順・フロー節の順序・禁止節（関連するドキュメント / レビュー記録 / 変更履歴）の不在・EARS の形式・プレースホルダ（`{{ }}` とガイドのコメント）の残存が無いことを確認して呼び出し元に返す

## 参照

- テンプレート: `assets/requirements.template.md`（frontmatter と全章の骨格。各章に書き方の 1 行ガイドをコメントで持つ）
- 章立て・書き方の規約: `rules/`（設計文書ルール `design-docs` / `ai-asset-design-docs`）
- 対になる仕様書の書き方（内部構造の行き先）: `20-common-step-spec`
- DDR の形式の手本: `.claude/docs/20_ddr/` の既存の書。正史と DDR の分離の決定: DDR `i0001-01`
- 呼び出し元: `10-task-design-exec` / `10-task-ai-asset-design-exec`（内容の合意と人間レビュー）

## エラー時の対処

| 状況 | 対処 |
|------|------|
| 書こうとする内容が内部構造（コマンド・判定順・スキーマ） | 要件書に書かず、仕様書（`20-common-step-spec`）へ回す |
| 決定に経緯・却下案がある | 本文に書かず DDR を起こし、本文は現在の正だけにする |
| 他の要件書・仕様書と矛盾する | 片方だけ直さない。矛盾する書と箇所を特定して呼び出し元に返す |
| 合意されていない決定を書くよう求められた | 書かない。合意を呼び出し元に返す |
| 2 アセットを 1 文書にまとめる依頼 | 1 アセット 1 文書に分ける。分けられない理由があれば返す |
| 「関連するドキュメント」「レビュー記録」「変更履歴」を求められた | 置かない（git の履歴と MR、DDR が担う）。理由を添えて返す |
| セルフレビューでプレースホルダ・ガイドのコメントが残っている | 埋めるか消してから返す |
