# i0050-06. issue-MR 駆動の開始時に作業ツリーを切る既定は「切らない」

## 背景

作業ツリー（`git worktree`）の操作は提供コマンド `worktree.sh`（`20-common-step-worktree`）で通せるようになり、同一フェーズのチケットの並列実施も採用した（DDR `i0050-01`）。残るのは「開発作業を始めるとき、既定で作業ツリーを切るのか」である。

- 切ると、本流のチェックアウトを触らずに作業でき、複数のチケットを同時に進められる
- 切ると、作業ツリーごとに記録と実行ログの置き場を用意し、タスクの切れ目で合流し、片付ける手順が毎回要る。合流では成果物（レポート）の衝突が出得る
- 1 issue = 1 ブランチ = 1 MR は維持し、push は本流でだけ行う（`20-common-step-commit-push`）。チケットの新規作成も本流だけ（DDR `i0050-05`）

つまり作業ツリーを切っても、本流に戻ってくる回数（切れ目・採番・push）は減らない。切ることの利得は「同時に進められること」だけで、単独で進めるかぎりは 0 である。

## 決定

- **issue-MR 駆動を開始するときに作業ツリーを切る既定は「切らない」。** 本流のチェックアウト 1 つだけで進める
- **切るのは、同じフェーズの依存しないチケットを並列に実施すると決めたときと、ユーザーが明示に指示したときだけ**。切ると決めた場合も、切るのは並列に進めるチケットのぶんだけで、本流はそのまま残す
- **切る / 切らないの判断は `00-workflow-issue-mr-driven` が持つ。** 作業ツリーを切る・一覧する・合流する・片付ける操作そのものは `20-common-step-worktree` が持ち、判断と操作を同じ場所に置かない
- **ヘッドレス（ユーザーが応答できない実行形態）でも承認を求めず、既定のまま「切らない・並列にしない」で進める。** 合流はタスクの切れ目で自動的に行い、自動で解けない衝突が出たら止めて人に返す

## 理由

- 単独で進めるかぎり利得が無く、記録の置き場の用意・合流・片付けのコストと、合流で衝突が出る危険だけが増える。既定は「増えるものが無い側」に置く
- 並列にするかどうかは、そのフェーズに依存しない実施チケットが何枚あるかで決まる。開始時点（全体計画の前）にはチケットが 1 枚も無く、判断の材料が存在しない。したがって「開始時に切る」を既定にすると、材料が無いまま切ることになる
- 切らない側を既定にしても、後から切ることはいつでもできる（`worktree.sh add` は作業の途中でも呼べる）。逆に切ってから戻すには合流と片付けが要り、非対称である
- ヘッドレスで確認に倒すと、そこで止まって進めなくなる。既定が「切らない」であれば確認は要らず、止まらない。一方で合流の衝突は成果物の中身の判断なので、機械に寄せず人に返す（`20-common-step-worktree` の例外 **[E2]**）

## 却下した案

- **常に切る（開始時に必ず作業ツリーを作り、本流では作業しない）**: 単独で進める大多数の issue で、記録の置き場の用意・合流・片付けが毎回発生する。合流のたびに成果物（1 タスク 1 本のレポート）の衝突を解く可能性を負い、得られるものは無い。加えて push とチケットの採番は本流でしか行えないので、「本流を触らない」も達成できない
- **開始時にユーザーへ毎回確認する**: 判断の材料（並列にできるチケットが何枚あるか）が開始時点では存在しないので、確認しても答えられない。ヘッドレスでは確認が拒否になり、開始そのものが止まる
- **並列にできるチケットが 2 枚以上あれば機構が自動で切る**: 「依存しない」の判定は先行チケットの記載だけでは足りず（同じ文書を触るチケットは番号の上で独立でも並列にできない）、機械が誤って切ると合流の衝突を人が解くことになる。並列にするかどうかは計画の判断として人と AI に残す
- **作業ツリーを使わず、別 clone を既定にする**: clone は進行状態・ロック・集計を共有せず（フック共通仕様 §2 の共有ルート）、1 つの issue の中で成果を 1 本の feature ブランチに積む形にならない。別 clone は「別の issue を並行して進める」ときの手段として残す

## 影響

- `00_requirement/skills/00-workflow-issue-mr-driven.md` に、既定は切らないこと・切ると決めたときの並列実施の起動・タスクの切れ目での合流を書く（受け入れ条件 A2）
- `10_spec/skills/00-workflow-issue-mr-driven.md` の手順に、`worktree.sh add` → 割り付け → 切れ目で `list` → `merge` → `remove` の順を書く。切る / 切らないの判断が既定どおりかは eval（`WFD-E07`）で見る
- `00_requirement/rules/work-defaults.md` に「並列してよいタスクの種類」を置き、既定は並列にしないことをそこでも明示する
- `agents/task-executor` は、並列で起動されたとき自分の作業ツリーの中だけで作業する（チケットを作らない・push しない・合流しない）
- 切らない既定のもとでは、`20-common-step-worktree` の代替フロー **[A1]**（切らずに本流だけで進める）が通常の経路になる
