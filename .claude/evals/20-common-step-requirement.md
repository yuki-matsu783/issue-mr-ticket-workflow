# 20-common-step-requirement の eval 定義

## 目的

`20-common-step-requirement` の SKILL.md（テンプレート由来の章順 → EARS とフロー節の順序 → 外部の観察者基準で内部構造を仕様へ → 経緯は DDR → 更新は正史の書き換え）を読み込んだときに、要件書の形と線引きが安定するかを確かめる。

## 評価シナリオ

各行は仕様書「テスト観点（eval）」の行と 1:1 に対応する（eval ID が対応の鍵）。

| eval ID | 入力プロンプトと状況 | 期待する振る舞い | 判定方法 | 添付ファイル |
|---------|--------------------|-----------------|---------|-------------|
| RQ-E01 | 「新しいスキル `20-common-step-finalize` の要件定義書を書いて」。設計タスクで内容（目的・受け入れ基準・スコープ）は合意済み | `assets/requirements.template.md` から `.claude/docs/00_requirement/skills/20-common-step-finalize.md` を作り、章順（概要 → ユーザーストーリー → 受け入れ基準 → 前提条件 → 制約条件 → 依存関係 → 非機能要件）と受け入れ基準の節順（メイン → 代替 → 例外 → 整合）に従い、外部的な振る舞いだけを書く。スクリプト名・判定順・スキーマは書かない | 章立てと節順が規定どおりであること、本文にスクリプト名（`*.sh`）・判定順・スキーマ・実パスの記述が無いこと、「関連するドキュメント」「レビュー記録」の節が無いこと、プレースホルダとガイドのコメントが残っていないこと | `assets/requirements.template.md` |
| RQ-E02 | 「`20-common-step-commit-push` の要件を変えて。push 前チェックの項目 3 を付録も対象にする」。決定には却下案（付録だけ別ルールにする案）がある | 該当の Shall 文を直接書き換えて現在の正史にし、「以前は〜」「変更履歴」を本文に書かない。却下案と理由は DDR `i<issue 番号>-<連番>-<タイトル>.md` に起こす | 要件書に変更履歴・追記の印が無いこと、DDR が新規に作られ 背景 / 決定 / 理由 / 却下した案 / 影響 を持つこと | `.claude/docs/00_requirement/skills/20-common-step-commit-push.md`、`.claude/docs/20_ddr/` の既存 DDR 1 本（形式の手本） |

## 比較条件

- with: Skill ツールで `20-common-step-requirement` を読み込んだ状態で各シナリオのプロンプトを与える
- without: SKILL.md を読み込まず、CLAUDE.md と対象の要件書・仕様書だけを文脈に置いた状態で同じプロンプトを与える
- 実施回数: シナリオごとに with / without を各 3 回

## 効果ありの判定基準

- RQ-E01: with の 3 回すべてで章立て・節順が一致し内部構造の語が無く、without で 1 回以上内部構造を書く・禁止節を置く
- RQ-E02: with の 3 回すべてで変更履歴が無く DDR が作られ、without で 1 回以上本文に経緯や「以前は」を残す
- RQ-E03: with の 3 回すべてで 1:1 を維持し、without で 1 回以上 1 文書にまとめる
- 3 シナリオのうち 2 つ以上で上記を満たせば効果あり。差が出ないシナリオは SKILL.md の該当手順の文言を見直す対象として記録する
