# ワークフロー用語

### 振り分け

依頼ごとに、開発作業（`00-workflow-issue-mr-driven`）か[軽作業](#軽作業)（`00-workflow-quick-request`）のどちらのワークフロースキルで進めるかを決めて読み込むこと。機構はこの読み込みを作業の入口として扱う。

### タスク

issue の作業を分割する単位で、同じ種類の[チケット](#チケット)群として実現され、計画と実施を対にして進める。タスクの完了地点が[タスクの切れ目](#タスクの切れ目)になる。

### タスクの切れ目

1 つのタスクが完了し、次のタスクへ進む前の境界。push・MR 本文の更新・人間レビューなど、タスクの中では行わない境界処理をここで行う。

### フェーズ列

1 つの issue で実施するタスクの並び。issue の種別ごとのテンプレートを土台に、[全体計画](#全体計画)でユーザーと合意して確定する。

### 全体計画

開発作業の最初に行うタスク。issue の確定、feature ブランチと draft MR の作成、フェーズ列の選択、各チケットの[実行者](#実行者)と[人間レビュー要否](#人間レビュー要否)の合意までを担う。メインエージェントが行う。

### フィードバック計画

実装より後に置く振り返りのタスク。[作業ログ](#作業ログ)・レビュー指摘・拒否の記録から AI アセットへ反映すべき内容を洗い出し、この MR で対応するか別 issue に起票するかを決める。メインエージェントが行う。

### 全体まとめ

issue の最後に行うタスク。統括レポートの作成、MR 本文の最終化、[作業領域](#作業領域)の片付け、draft 解除までを担い、マージは行わない。メインエージェントが行う。

### チケット

作業の最小単位。タスクの種類・状態・先行チケット・実行者・人間レビュー要否・[やってよいこと](#やってよいこと)・目的・[DoD](#dod)・[作業ログ](#作業ログ)を持つファイルで、[提供コマンド](#提供コマンド)により未着手 → 作業中 → 完了と進む。

### やってよいこと

チケットが宣言する、書き込んでよい範囲と実行してよい操作の分類。機構が書き込み・操作を許可するか拒否するかを判定するときの入力になり、上限はタスクの種類ごとにユーザーが管理する設定が定める。

### 実行者

チケットを担当する LLM モデル。チケットに明記され、[全体計画](#全体計画)で合意する。既定値は[タスク別の既定判断基準](#タスク別の既定判断基準)が持つ。

### 人間レビュー要否

そのチケットの成果を[タスクの切れ目](#タスクの切れ目)で人間が MR 上でレビューするかどうかの宣言。理由とセットでチケットに明記され、既定値は[タスク別の既定判断基準](#タスク別の既定判断基準)が持つ。

### タスク別の既定判断基準

タスクの種類ごとの既定の実行者・人間レビュー要否とその理由・調整してよい条件をまとめた規約。[全体計画](#全体計画)が各チケットの実行者とレビュー要否を提案するときの基準で、プロジェクトごとに置き換えられる。

### DoD

チケットの完了条件。何をもって完了とするかの項目群で、チケット完了時の検査対象になる。

### 作業ログ

チケットに書き込む固定見出しの作業記録。現在地・判断と根拠・拒否や確認の記録・AI アセットに反映すべき内容などを持ち、[フィードバック計画](#フィードバック計画)の集約とセッション再開の入力になる。

### 提供コマンド

機構が用意する、状態の変更を担うスクリプト群。チケットの状態遷移・commit / push・レビュー依頼と完了・マージ前の片付けはこれを通して行い、AI の自己申告では状態が進まない。

### 敵対的レビュー

経緯を知らされない読み取り専用のレビュアー（サブエージェント）が、[成果物ルール](./ドキュメント体系用語.md#成果物ルール)の[観点章](./ドキュメント体系用語.md#観点章)に沿って欠陥を探すレビュー。人間レビューの前段として使う。

### 軽作業

issue と [MR](#mr) を作らずに、範囲を宣言してから進める作業。質問・調査・振る舞いを変えない小さな修正が該当し、`00-workflow-quick-request` で進める。

### 単独実行モード

issue と MR を作らず、チケット駆動だけを使う実行形態。タスクの切れ目の承認は MR ではなくチャット上の確認で取る。

### 外部委任モード

`glab` / `gh` CLI が使えない環境で、リモート操作（issue / MR の操作）を MCP ツールに代行させる実行形態。証跡の強度は CLI 実行時より劣る。

### MR

マージリクエスト。機構の文書は GitLab の用語で書き、GitHub では MR → PR、`glab` → `gh` と読み替える。

### 作業領域

チケット・計画書・レポート・進行状態など、ブランチ限りの作業ファイルを置く `wip/` 配下の領域。マージ前に片付けられ、main には残らない。

### wip/tmp

一時ファイル（issue / MR に投稿する本文、その場限りのスクリプト、中間結果）の置き場。コミット対象外で、ワークスペース外のパス（OS の一時ディレクトリなど）の代わりに使う。
