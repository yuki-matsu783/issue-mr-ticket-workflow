# i0009-17. 共有ライブラリは分類までとし、規約の照合は呼び手が行う

## 背景

`hook-common.sh` の `tool_class` は `Skill` ツールのとき `00-workflow-*` という接頭辞で「振り分けの宣言かどうか」を判定していた（`hook-common.sh:156-165`）。一方、振り分けスキル名の正は `.claude/hooks/config/entry-skills.txt` で、照合するのは `workflow-entry` である。**同じ規約が 2 か所にある**（DDR `i0009-03`）。

同じ形の問題が他のライブラリにもあり得るため、`i0009-03` は「`tool_class` は分類までに留める」と決めたうえで、その責務を `20-common-step-shell-script` 仕様に書くことを 0015 に送った。ここでは `tool_class` 1 件の話ではなく、**共有ライブラリ全体の責務の線引き**として定める。

## 決定

- `source` 専用のライブラリと `.claude/hooks/lib/` の共有ライブラリは、**入力を機械的に分類するところまで**を担う。「その値がプロジェクトの規約に照らして正しいか」の照合は**呼び手**が行う
- 具体的な線引きを `20-common-step-shell-script` 仕様に表として置く

| ライブラリの関数 | やること（分類） | やらないこと（照合。呼び手の責務） |
|---|---|---|
| `tool_class` | ツール名から種類を返す。`Skill` は `tool_input.skill` の値を見ずに**常に「宣言」** | 名前が振り分けスキルかの照合（`workflow-entry` が `entry-skills.txt` で行う） |
| `cmdpos.sh` | 実行位置のセグメント・実行体・第 1 サブコマンドを返す | そのコマンドを許してよいかの判断（`workflow-guard` / `block-*`） |
| `scope_classify` | 操作の分類（`read` / `build-test` / … / `provided`）を返す | その分類が宣言されているかの判断（呼び手が `allow.ops` と突き合わせる） |
| `frontmatter.sh` | frontmatter の値を返す（戻り値で 3 状態を区別 — `i0009-16`） | 値が仕様どおりかの検証（`ticket_type` が `types` にあるか等） |

- あわせてフック共通仕様 §2 の分類表の「宣言」の行から `tool_input.skill` の条件を外す

## 理由

- **二重定義は必ず片方だけ更新される**。`00-workflow-hotfix` のような振り分けスキルを将来足したとき、`entry-skills.txt` に足して `tool_class` の接頭辞判定を直し忘れる（あるいはその逆）ことが起きる。正を 1 つにすれば起きない
- **分類と照合では変更の頻度が違う**。ツールの種類（書き込み / 実行 / …）は Claude Code 側の都合で変わり、振り分けスキルの名前はプロジェクトの都合で変わる。変わる理由が違うものを同じ関数に入れない
- **ライブラリは呼び手の識別子を知らない**。`scope.sh` を使うのは `workflow-guard`（WF2xx）と `workflow-state-guard`（WF3xx）で、ライブラリの側で「どの番号で拒否するか」を決められない。分類までに留めれば、この非対称を持ち込まずに済む
- 接頭辞判定（`00-workflow-*`）は分類としても粗すぎる。`00-workflow-` で始まるが振り分けではないスキルを作れてしまう

## 却下した案

- **`tool_class` に `entry-skills.txt` を読ませる**: ライブラリがファイル I/O を持つことになり、ホットパス（毎ツール呼び出し）でのファイル読み込みが増える。しかも読めなかったときの失敗ポリシーをライブラリが決めることになり、`i0009-14` で否定した形に戻る
- **接頭辞判定を残したまま `workflow-entry` でも照合する（二重で持つ）**: 今の状態そのもので、更新漏れの危険が残る
- **`entry-skills.txt` をやめて接頭辞判定に一本化する**: `CLAUDE.md` の表と機械的に照合する手段（WE-T07）が失われる（`i0009-03` で却下済み）

## 影響

- `10_spec/skills/20-common-step-shell-script.md`（「ライブラリの責務の境界」の節を追加）
- `10_spec/フック共通仕様.md` §2（分類表の「宣言」の行）
- `10_spec/hooks/10-UserPromptSubmit/workflow-entry.md`（照合の責務はこのフック。既に `i0009-03` で反映済み）
- **実装フェーズへ**: `tool_class` から接頭辞判定を外す（参考実装からの差分になる）
