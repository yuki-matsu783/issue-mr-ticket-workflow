# 20-common-step-spec の eval 定義

## 目的

`20-common-step-spec` の SKILL.md（要件の存在確認 → 受け入れ基準の全件書き出し → 種別ごとの節構成 → TBD の明示 → 対応表の検査 → 台帳に追加してから識別子を使う）を読み込んだときに、仕様書の節構成・対応表の全件性・テスト ID / eval ID の扱いが安定するかを確かめる。

## 評価シナリオ

各行は仕様書「テスト観点（eval）」の行と 1:1 に対応する（eval ID が対応の鍵）。

| eval ID | 入力プロンプトと状況 | 期待する振る舞い | 判定方法 | 添付ファイル |
|---------|--------------------|-----------------|---------|-------------|
| SP-E01 | 「`20-common-step-finalize` の仕様書を書いて」。要件定義書（受け入れ基準 12 件）があり、実現方法は設計で合意済み | スキルの節構成（概要・禁止事項 / 呼出条件 / IN / OUT / IN / OUT サンプル / 処理フロー / OUT ひな形 / 参照ナレッジ / Script 処理 / 要件との対応）に従い、「要件との対応」表が受け入れ基準 12 件をすべてカバーする | 節構成が表と一致すること、対応表の行数が 12 で左列が要件の受け入れ基準と 1:1 であること、実現箇所の無い行が無いこと | 要件定義書のフィクスチャ（受け入れ基準 12 件） |
| SP-E02 | SP-E01 の対象がスクリプト `finalize.sh` を持つ。エラー識別子の接頭辞 `FN` は台帳（`フック共通仕様` §6）に未登録 | Script 処理にサブコマンド・判定順・エラー識別子（`FN001`〜）・テスト観点（テスト ID `FN-T01`〜）を書く。識別子・テスト ID は先に台帳へ接頭辞と範囲を追加してから使う | Script 処理にテスト ID の表があること、`フック共通仕様` §6 に `FN` の行が追加されていること、仕様書の識別子が台帳の範囲内であること | `.claude/docs/10_spec/フック共通仕様.md` |
| SP-E03 | 「`20-common-step-issue` のようにスクリプトを持たないスキルの仕様書を書いて」 | Script 処理に「なし」とその理由（単発の CLI 呼び出しで検査すべき内部状態を持たない等）を書き、テスト観点は eval ID（`<接頭辞>-E01`〜）の表で定義する | Script 処理に「なし」と理由があること、eval ID の表（入力 / 期待する振る舞い / 判定方法）があること、テスト ID（`-T`）を捏造していないこと | `.claude/docs/10_spec/skills/20-common-step-issue.md`（手本） |

## 比較条件

- with: Skill ツールで `20-common-step-spec` を読み込んだ状態で各シナリオのプロンプトを与える
- without: SKILL.md を読み込まず、CLAUDE.md と対象の要件書・仕様書だけを文脈に置いた状態で同じプロンプトを与える
- 実施回数: シナリオごとに with / without を各 3 回

## 効果ありの判定基準

- SP-E01: with の 3 回すべてで節構成が一致し対応表が全件カバーし、without で 1 回以上節が欠ける・対応表が不完全
- SP-E02: with の 3 回すべてで台帳への追加が先に行われ、without で 1 回以上台帳に無い識別子を使う
- SP-E03: with の 3 回すべてで「なし」と理由・eval ID の表があり、without で 1 回以上 Script 処理を省く・テスト ID を捏造する
- 3 シナリオのうち 2 つ以上で上記を満たせば効果あり。差が出ないシナリオは SKILL.md の該当手順の文言を見直す対象として記録する
