実施した内容と結果

  1. 1

    リポジトリ外のパスを承認単位にしない ✕問題 根拠: プローブ A5 の実測（記録された → なし）

    hook_rel_path はリポジトリの外のパスを絶対パスのまま返す。workflow-diff-check はその戻り値をそのまま承認単位にしていたので、リポジトリ外への Write が approvals.json に残っていた。scope_resolve の判定はルート相対のパスにしか当たらないので、外のパスを覚えても許可には使われない。

    根拠を見る（実行コマンドと出力） 
    （直す前）Write /tmp/outside/evil.md
[approvals] [{"scope":"C:/Users/taniyama/AppData/Local/Temp/outside", ...}]
（直した後）
[approvals] なし

    結論

    絶対パスと .. を含むパスを承認単位の候補から外した。記録が汚れず、SC_APPROVED を読む他のフックのノイズも消える。

  2. 2

    解決できない基準点をそのまま案内文に出していた ✕問題 根拠: プローブ A8 の実測（PLACEHOLDER が本文に出た）

    git rev-parse --verify に失敗したとき、直す前は警告を出して作業ツリーの差分だけで判定を続けていた。その結果 WF601 の本文と復旧指示が両方とも嘘になる。

    根拠を見る（実行コマンドと出力） 
    （直す前）
WF601: … 基準点は PLACEHOLDER。
- docs/g1.md（未追跡 / WF201）
復旧: 追跡済みの変更は git checkout PLACEHOLDER -- <path>、…
（直した後）無出力・終了 0

    結論

    仕様の制御方式 7「差分の取得に失敗 → 黙って抜ける」に寄せた。中間の選択肢（status だけで判定して出す）は、復旧の道を示せないので指示として成立しない。

  3. 3

    作業中 2 枚以上の扱いが 2 本のフックで食い違っていた △注意 根拠: プローブ A7 の実測（WF813 が出ていた → 出なくなった）

    workflow-diff-check は仕様どおり「2 枚以上は判定不能として黙って抜ける」。subagent-stop-check は先頭 1 枚の許可範囲で他方の差分まで範囲外と呼んでいた。同じ scope.sh を共有しているのに結論が食い違う。

    根拠を見る（実行コマンドと出力） 
    （直した後）WF811 と WF812 は出る / 「許可範囲外のパスに差分が残っている」は出ない

    結論

    workflow-diff-check 側に揃え、WF813 は 1 枚のときだけ出す。WF811（残ったチケット）と WF812（未コミット）は枚数と無関係に事実なので出し続ける。

  4. 4

    since_sha が勝手に進み、集計値と表示が食い違っていた ✕問題 根拠: UR-T04 に「初回 push の後も .since_sha が空」を追加

    直す前は初回 push で since_sha を HEAD にしていた。集計値はリセットしていない（投稿が完了していないため）ので、2 回目のレポートは「集計期間は push 1 の HEAD から」と表示しながら、数値には push 1 より前の分が入る。

    根拠を見る（実行コマンドと出力） 
    $ jq -r '.since_sha' logs/usage/main.json
（直す前）e0ebb56…
（直した後）

    結論

    起点を書くのは boundary.sh の責務（仕様の既定 5）なので、フックは書かない。初回は「（記録なし）」と出るが、これは「まだ 1 度も投稿していない」という事実そのもの。

  5. 5

    一覧の上限が 30 と 20 で不整合だった △注意 根拠: DC-T02 に「範囲外 25 件で 20 件 + 『他 5 件』」を追加

    WF601 は 30、WF812 / WF813 は 20 だった。仕様は subagent-stop-check 側にだけ「20 を超えれば先頭 20 件 + 件数」と明記している。

    根拠を見る（実行コマンドと出力） 
    assert_eq "DC-T02" "20" "$(printf '%s' "$R_OUT" | grep -o 'docs/g[0-9]*\.md（未追跡' | wc -l)"

    結論

    明記されている側を正として 20 に揃えた。値の出どころは 0032 で仕様に書く。

  6. 6

    縮退判定が decisions.jsonl の末尾 400 行に依存していた ✕問題 根拠: SP-T08 に「印がある」「記録が 600 行先にある」の 2 件を追加

    subagent-stop-check は「subagent-start-check の記録が 1 件も無ければ縮退」と判定する。直す前は tail -n 400 で見ていたので、記録が育つと誤って縮退と判定し WF801 を二重に出す（decisions.jsonl はツール呼び出しのたびに増える）。

    根拠を見る（実行コマンドと出力） 
    # 一次: 行数に依存しないセッション内の印
hook_session_dir
[[ -f "$REPLY/subagent-start-check.json" ]] && return 0

    結論

    subagent-start-check が PreToolUse Agent の判定のたびに印を置き、subagent-stop-check はまずそれを見る。印が無い古いセッション向けに decisions.jsonl の全走査（打ち切りなし）を二次経路として残した。
