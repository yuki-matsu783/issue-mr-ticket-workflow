# i0009-35. `fm_*` の呼び出し規約を定めて戻り値を潰さない

## 背景

`i0009-16` は「`frontmatter.sh` のスタブは出力なし・戻り値 2」と決め、`i0009-14` は「`scope.sh` は戻り値 1 と 2 を潰さずに呼び手へ返す」と決めた。この 2 つが成立して初めて `WF209`（機構の破損）と `WF211`（チケットの記載不正）を区別できる。

境界レビュー（付録 A の R8）の指摘: **どう書けば潰さないかが仕様に無い**。しかも bash には戻り値を静かに失う書き方が 2 つある。

- **`local v=$(fm_get "$f" k)`**: bash の仕様上、`local` 自身の終了ステータス（常に 0）が `$?` になる。**戻り値が黙って消える**
- **`|| true`**: `set -e` で落ちないようにするためだけに書かれるが、戻り値を捨てる

参考実装 `.claude/hooks/lib/scope.sh` は現に後者を選んでいる。

```
SC_TICKET_TYPE="$(fm_get "$f" ticket_type 2>/dev/null || true)"
while IFS= read -r v; …; done < <(fm_list "$f" allow.write 2>/dev/null || true)
```

さらに `scope_load_ticket` は「ファイル不在」「`ticket_type` 空」「スタブ」の 3 つをすべて `return 1` に潰している。設計で最重要とされた区別が、実装では消える。

## 決定

`20-common-step-shell-script` 仕様の「読み込み行」に**呼び出し規約**を定める。

- **`local` と代入を同じ行に書かない**。`local v; v="$(fm_get "$f" k)" || rc=$?` と 2 行に分ける
- **`|| true` を使わない**。`|| rc=$?` で受けて分岐する
- 戻り値を使わない呼び出しでも `|| rc=$?` で受け、**無視すると決めたことがコードから読める**ようにする
- **パイプやコマンド置換の中で `fm_*` を呼ばない**（`$(...)` の中の非 0 は `set -e` の対象外になり、判定が静かに変わる）
- **`FM_AVAILABLE` を設定するのは読み込み行**（読めたら 1、`nop` でフォールバックしたら 0）。`frontmatter.sh` 自身は設定しない — 読み込めていないときに実行されるのはスタブの側なので、ライブラリに設定を任せられない

## 理由

- **「潰さないこと」は方針ではなく書き方の問題**。方針だけ書いても、`set -e` を使う以上どこかで受けざるを得ず、受け方を決めないと `|| true` に落ちる。**規約は書き方まで降りて初めて効く**
- `local v=$(...)` の罠は bash を書く人でも見落とす。参考実装が現に踏んでいる以上、明示しないと再発する
- `FM_AVAILABLE` の持ち主を決めたのは、「読めなかった」ことを知っているのが読み込み行だけだから。`frontmatter.sh` が読み込まれていれば `FM_AVAILABLE=1` は書けるが、読み込まれていないときに `=0` を書ける主体が読み込み行しかない。**両方を同じ主体が書く**方が食い違わない

## 却下した案

- **`set -e` をやめる**: 提供コマンド・フックの雛形の骨格（`set -euo pipefail`）を変えることになり、影響が bash 規約全体に及ぶ。局所の書き方で解ける問題に大きすぎる
- **`fm_*` のラッパー（`fm_try`）を作って戻り値を `FM_RC` に置く**: 関数が 1 段増え、`frontmatter.sh` の呼び出し面が 2 系統になる。書き方の規約で足りる
- **戻り値ではなく `FM_AVAILABLE` だけで判断する**: `i0009-16` で却下済み（呼び手が確認を忘れると 1 と 2 を取り違える）
- **参考実装の `|| true` をそのまま踏襲する**: `WF209` / `WF211` の区別という設計の成果が実装で消える

## 影響

- `10_spec/skills/20-common-step-shell-script.md`「読み込み行」（呼び出し規約と `FM_AVAILABLE` の持ち主）
- **実装フェーズへ**: 参考実装 `scope.sh:101-104` の `|| true` を `|| rc=$?` に書き換える。`scope_load_ticket` が 3 つの失敗を `return 1` に潰している箇所を、1（記載不正）と 2（スタブ）に分ける
