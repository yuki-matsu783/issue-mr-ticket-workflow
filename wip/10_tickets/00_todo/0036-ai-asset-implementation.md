# 0036 レビュー 3 巡目の是正: block-chmod の判定軸を「復元」から「難読化の検出」へ変え、worktree の相互参照を双方向にする

## 目的

0035 が過剰拒否を消すのと引き換えに、最も基本的な拒否（`"chmod" +x a`）を落とした。文字列から実行体を復元する方針が 3 巡続けて破れているので、判定軸を変える

## DoD

- [ ] block-chmod の判定軸を「難読化を取り除いて実行体を復元する」から「実行位置に難読化の痕跡があれば拒否側に倒す」に変える。cmdpos の正規化後の実行体が `_`（潰れたクォート）・`$`・バッククォートを含み、かつコマンドに難読化に使える記号がある段は「実行体を特定できない」として扱い、一覧の語がコマンド全体（記号を落とした複製を含む）に現れたら拒否する（根拠: ）
- [ ] 中身のあるクォートで実行体を割る形を拒否する。0035 は `"chmod" +x a` `'chmod' +x a` `c"h"mod +x a` `ch"m"od +x a` `"/usr/bin/chmod" +x a` `sudo "chmod" 755 a` の 6 形すべてを ALLOW にしていた（0035 の直前では 6 形とも WF501。実測でいずれも chmod が起動する）（根拠: ）
- [ ] 中身が空でない展開で実行体を割る形を拒否する。実測で `ch$( )mod` `ch$( : )mod` `ch$(echo)mod` `ch${x:-}mod` `c${x}hmod` の 5 形が ALLOW（`ch$()mod` だけがテストにあり DENY だった）。原因は前置判定が「記号を落としただけの複製」で、展開の中身が空でないと再結合せず、制御方式 5 に到達しないこと（根拠: ）
- [ ] BC-T01 に「中身のあるクォート」6 形と「中身が空でない展開」5 形を足し、直す前は落ちる。BC-T02 の過剰拒否の負の対照（引用符の中に区切り文字と禁止語）は通ったままにする（根拠: ）
- [ ] BC-T02 に、判定軸を変えたことで新しく生む過剰拒否が無いことを確かめるケースを足す。少なくとも `bash script.sh -m "chmod の話"` `./my_tool.sh --note "chmod"` のように、実行体が難読化されていないのにコマンドが禁止語に言及する形が通ること（根拠: ）
- [ ] `__hc_is_worktree_of` の分岐 (b) も候補の `.git` の実在と `gitdir:` の指し先の相互一致を要求する（分岐 (a) と同じ双方向の確認を通す）。0035 は (b) が「`<root>/.git/worktrees/*/gitdir` の中身が候補の `.git` と一致する」だけを見ていたので、`git worktree add wip/tmp/wt` の後に prune を忘れた登録が残っていると、`wip/tmp/**`（無承認で書ける）に同名ディレクトリと `.claude/` を作って cwd を置くだけで HOOK_WORKTREE がそこへ移り、作業中チケットが 0 枚になる（実測で再現）（根拠: ）

- [ ] `_sc_web_add_out` が「本体の出力先か否か」を引数で受け取り、`dash_o` は本体側のときだけ立てる。0035 は値が `-` なら種類を問わず `dash_o=1` にしていたので、`wget -o -` `wget --output-file=-` `wget --append-output -` で既定の `_` が消え、`web` として素通りした（実測）（根拠: ）
