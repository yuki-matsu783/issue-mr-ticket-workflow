# 10-task-ai-asset-implementation-exec — 機構自身を小さく変えて毎回確かめる

共通手順の禁止事項（`10-task-investigation-exec` の冒頭が正）に加えて、要件・仕様・DDR を書き換えない（仕様どおりに作れないときは逸脱として記録し、設計反映はフィードバック計画へ）。eval を実行しない（定義まで。実行は人間の判断）。中核（フック・提供コマンド・`settings.json`）を複数まとめて変えてからテストしない。自分が止まったときに `WORKFLOW_ENTRY_ENFORCE=0` などで強制無効化しない（ユーザーの明示があるときだけ）。フックを迂回しない。許可範囲外のファイルへの変更を残さない。

## 目的

機構自身を仕様どおりに作り替える。1 つ変えるごとに機械テストと自分の動作で確かめ、壊れても戻せる状態を保つ。

- 要件: `.claude/docs/00_requirement/skills/10-task-ai-asset-implementation-exec.md`
- 仕様（正。固有手順・OUT ひな形）: `.claude/docs/10_spec/skills/10-task-ai-asset-implementation-exec.md`
- 処理の共通手順（正）: `10-task-investigation-exec` の「実施タスクの共通手順（正）」

## 手順

共通手順（入力の確認 → 1 枚ずつ着手 → 実施 → レポートに追記 → コミットと完了 → 次へ）は `10-task-investigation-exec` に従う。実施（共通手順 3）の固有部分は次のとおり。

- 計画書の**固定ステップ順**（設定・定義 → 中核 → その機械テスト → スキル・ルール・エージェント → 参照更新）で担当ステップを実施する。アセットの置き場・命名・frontmatter は `20-common-step-ai-asset-creator`、シェルスクリプトは `20-common-step-shell-script`（logger を含む）に従う
- **中核の変更は小さく**: 1 つ変えるごとに機械テストと、計画書のロックアウト対策に書いた最初の操作で自分が止まらないことを確認する。止まったら復旧手順（`git checkout <基準点> -- <path>`）で戻し、原因を作業ログに書いてから再試行する
- 機械テストは**テスト先行**（失敗確認 → 実装 → 成功）で、コマンドと結果を作業ログに残す。**eval は定義**（入力・期待する振る舞い・判定方法）を仕様の ID で書くまでとし、実行しない
- 完了前の**検査**: プレースホルダ（テンプレート由来の `{{名前}}`・`TODO`・`TBD`）0 件、frontmatter が種別ごとの必須項目を満たす、参照更新一覧の検索語で旧名が 0 件（DDR・用語辞書の別名を除く）。結果はコマンドと件数で作業ログに残す
- 仕様どおりに作れない（フックのイベントで取れない情報がある等）ときは、作れる範囲を作り、逸脱の内容と理由を作業ログ「仕様からの逸脱」に記録する。**設計文書は直さない**
- `git diff --stat <基準点>` で許可範囲内であることを確認し、範囲外は理由を残して戻す
- **見てほしい点の固定項目**: 機械テストの結果と eval が未実行であることの明記 / 検査結果（プレースホルダ・frontmatter・参照更新）が 0 件か / 逸脱一覧 / 中核変更後に自分で動作確認した記録

## OUT ひな形

このスキルは固有のテンプレートを持たない。`20-common-step-report-view` の `assets/report.template.md`（と `report.template.html`）をそのまま使い、次を含める。作成・更新したアセットの一覧（仕様書の節との対応）/ テスト結果（機械テスト ID × 結果・実行コマンド、eval ID × 定義済み・未実行の明記）/ 検査結果（プレースホルダ・frontmatter・参照更新の件数）/ 仕様からの逸脱の一覧 / 想定と異なった点（自分が止まった事象と復旧）/ 残課題を含める。

## エラー時の対処

| 状況 | 対処 |
|------|------|
| 中核を変えた直後に自分が止まった | 迂回・強制無効化をしない。復旧手順で基準点に戻し、原因を作業ログに書いてから再試行する |
| フックが WF2xx で操作を拒否した | 迂回しない。チケットの許可範囲内でやり直すか、範囲を広げる必要があれば作業を止めて提案する |
| 仕様どおりに作れない | 設計文書を直さない。作れる範囲を作り、「仕様からの逸脱」に記録する |
| eval を実行したくなった | 実行しない。定義まで書いて人間の判断に委ねる |
| 許可範囲外に変更が出た | 理由を作業ログに書き、基準点に戻す。必要なら別チケット候補として報告する |
| 参照更新の検索で旧名が残る | 残った箇所が DDR・用語辞書の別名かを確かめる。それ以外なら直してから完了する |
| 共通手順で止まった（TK005 / RV00x） | `10-task-investigation-exec` の「エラー時の対処」に従う |
