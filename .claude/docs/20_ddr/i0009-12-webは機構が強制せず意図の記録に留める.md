# i0009-12. `web`（外部への問い合わせ）は機構が強制せず意図の記録に留める

## 背景

チケットの `allow.ops` には `read` / `build-test` / `hook-test` / `remote-read` / `remote-write:*` と並んで **`web`**（外部への問い合わせ）がある。`workflow-guard` は `ops` を根拠に操作を許可・拒否するが、`web` に対応する強制の経路が仕様のどこにも無く、「宣言だけあって効いていない項目」の状態だった。

強制するとすれば `PreToolUse` の matcher に `WebFetch|WebSearch` を足して `workflow-guard`（または新しいフック）で判定する形になる。公式の matcher はツール名の完全一致または正規表現なので、技術的には可能である。

## 決定

- **`web` は機構が強制しない**。`WebFetch` / `WebSearch` を `PreToolUse` に登録しない
- チケットの `allow.ops` の `web` は**意図の記録**として残す（宣言と実際の使用がずれても機構は止めない）
- 共通仕様 §8 に理由付きで明記し、§13「意図的な緩和」にも 1 行として載せる

## 理由

- **判定の材料が合わない**: `scope_classify`（§8）はコマンド列を前提に分類する関数で、`tool_name` しか無い入力に同じ分類を当てられない。`web` のためだけに別系統の判定を `workflow-guard` に足すと、1 つのフックが 2 つの判定モデルを持つことになる
- **守る対象に当たらない**: 機構が守るのは「作業領域外への書き込み」「コミット / push」「進行状態の破壊」で、いずれも取り返しがつかないか、レビューをすり抜ける副作用を持つ。外部への問い合わせは副作用が読み取りに閉じており、同じ強度で守る理由が無い
- **記録として既に機能している**: `web` を宣言したチケットで実際に外部を見たかは結果報告と作業ログに残り、逆に宣言せずに使えば差分やログから気づける。レビューで拾える種類の逸脱に、フックの拒否は釣り合わない
- **止めた場合の害が大きい**: 調査タスクは公式ドキュメントの取得が本体なので、誤って止めると作業が進まない。issue #9 の調査ワークでは `curl` による取得（`Bash` 経由）も併用しており、`WebFetch` だけを止めても抜け道が残る（`Bash` の `curl` まで止めるのは過剰）

## 却下した案

- **`WebFetch` / `WebSearch` を登録して `web` 未宣言なら deny**: 上記のとおり判定モデルが合わず、止めた場合の害が守る利益を上回る。抜け道（`curl`）も残る
- **登録して deny ではなく通知（additionalContext）にする**: 「宣言していない外部問い合わせをした」という通知は、AI が自分で気づける情報でしかなく、コンテキストを消費するだけ。案内側フックを 1 本増やす価値が無い
- **`allow.ops` から `web` を削る**: 宣言が意図の記録として機能している（計画時に「外部を見る必要があるか」を考える契機になる）ので、消すと考える契機まで失われる

## 影響

- `10_spec/フック共通仕様.md` §8（強制しない理由）・§13（意図的な緩和の 1 行）
- `10_spec/hooks/20-PreToolUse/workflow-guard.md`（`ops` の判定に `web` を足さない。既存の記述に変更なし）
- **`10-task-*` の計画スキルへ**: `web` の宣言は引き続き求めるが、それが機械的に守られるものではないことを前提にする
