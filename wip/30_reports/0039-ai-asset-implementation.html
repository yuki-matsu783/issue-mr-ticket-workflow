  1. 1

    フェーズ 4c の実測（プローブ経由） ◎良 根拠: logs/hooks/probe-4c.jsonl・wip/tmp/p4c-headless.jsonl

    WORKFLOW_PROBE_4C=1 を settings.json の env に置いた専用セッションで、登録済みの本物のフックが受け取る stdin を記録した。値を落とすのは 7 フィールドだけで、それ以外はキーの名前と型のみ。TBD 6 件のうち 5 件は仕様どおりで、T9 だけが外れた。

    ID実測対比
    T2親子の session_id は同じ。子には agent_id / agent_type が付く一致（親子対応表は不要）
    T3ヘッドレスを示す入力フィールドは無い。source は対話と同じ startup一致
    T4agent_id / agent_type は実在、model は来ない。PreToolUse:Agent の tool_input.model も指定時のみ一致（補足 1 件）
    T5PowerShell の共通フィールドは Bash と同形一致
    T7終了コードのフィールドは存在しない。さらに exit≠0 では PostToolUse が 1 本も起動しない一致（「届いた = 成功」を裏付け）
    T9外れた。人間に通知は来ない（SDK メッセージには載る）不一致 → 16 行へ縮退
    根拠を見る（ヘッドレスのストリームに出た systemMessage） 
    {"type":"system","subtype":"informational",
 "content":"PreToolUse:Agent says: [プローブ] WORKFLOW_PROBE_4C=1 のため …",
 "level":"notice","session_id":"c59ef0ce-…"}

    結論

    T7 は負のコントロール（exit 3 / exit 7）で確かめた。tool_response.status は両分岐を観測（対話で省略 → async_launched で WF814 が発火 / ヘッドレスの false 明示 → completed）。

  2. 2

    T9 の縮退（17 行 → 16 行） △注意 根拠: 仕様 §12 の分岐・DDR i0009-54

    PreToolUse / matcher Agent の subagent-start-check を登録から外した。フック本体は消していない（SubagentStart の WF802 = 要点注入はそのまま生きる）。生成器 2 本（fixture.py / stages.py）を直して期待値 TSV と段階ファイル 6 本を再生成し、test_config_integrity.sh のハードコード 2 か所（総行数 17→16、実体と登録先が一致しない行 6→5）も合わせた。

    結論

    失うのは起動前の WF801（実行者の不一致）と WF803（background 起動）。受け皿は subagent-stop-check の縮退判定と WF814 で、WF814 は実測で実際に起動直後へ届いた。この行が無いとセッション内の印が常に書かれないので、縮退の側が必ず動く（DDR i0009-52 の設計どおり）。

  5. §12 の T2 / T3 / T4 / T5 / T7 を「実測で確認済み」に更新する。T2 の縮退（親子対応表）は不要と確定。副産物として「サブエージェント内のツール呼び出しには agent_id / agent_type が付く」を §2 に明記できる

想定と異なった点

計画時の見込み実際どう扱ったか
systemMessage はユーザーに表示される（公式の「Warning message shown to the user」）対話 UI では通知が来ない。ヘッドレスの SDK メッセージには level: notice で載っている「破棄される」ではなく「対話 UI が見せない」と記録し、§12 の縮退を発動（16 行）
実行者の比較は PreToolUse の tool_input.model で行える呼び出し側が指定しない限り来ない実装は既に「model が特定できない」へ倒していたので振る舞いの誤りは無い。仕様に追記（設計への反映 3）
失敗したツール呼び出しでも PostToolUse は動く1 本も起動しない（exit 3 / exit 7 で確認）「届いた = 成功」の正しさが裏づいた一方、WF601 が失敗時に効かない含意を仕様へ（設計への反映 4）
cd や一時スクリプトの実行は通るどちらも既定拒否（WF204）書き方を宣言の範囲に合わせて続行。tmp-script 分類の案を 0032 へ
HTML ビューはテンプレートを cp して作る（スキルの手順）cp が WF205 で止まるRead → Write で同じ内容を作った。スキルの手順とフックの規則の衝突として 0032 へ
