# 20-common-step-report-view — HTML はテンプレートを写して埋め、検査を通す

Markdown を正文とし、同じベース名の `.html` をテンプレートから作る。HTML にだけある情報を作らず、md を更新したら HTML も同じ変更で追随させる。全体計画書（`wip/00_overall_plan/`）には作らない。

- 要件: `.claude/docs/00_requirement/skills/20-common-step-report-view.md`
- 仕様（正。テンプレートの規約・検査 7 項目・エラー識別子 RV001〜008）: `.claude/docs/10_spec/skills/20-common-step-report-view.md`

## 手順

1. **対象を判定する**: `wip/30_reports/` の結果レポート・統括レポートと `wip/20_plans/` の計画書は必須。付録（`<連番>-<種類>-appendix-<記号>.md`）には作らない
2. **テンプレートを書き出す**: 用途に対応するテンプレート（レポート用 / 計画書用）を **Read で読み、同じベース名の HTML として Write で書き出す**。`cp` / `copy` のようなコマンドでの複製は使わない（コマンドによる書き込みは宣言の有無によらず WF205 で拒否されるので、`wip/20_plans/` のように書き込みを宣言したチケットでも通らない）
   - レポート: `assets/report.template.html` → `wip/30_reports/<ベース名>.html`
   - 計画書: `assets/plan.template.html` → `wip/20_plans/<ベース名>.html`
3. **Edit で埋める**: `{{名前}}` のプレースホルダ（要素の内容として置いてある）をすべて md の内容に置き換える。`data-required` 付きの必須節は削除せず、該当する内容が無いときも空にせず「無し」と 1 行書く（md 側も同じ）。空になる**任意**の節（`data-required` 無し）は節ごと削除してよく、目次からもその行を消す。それ以外の DOM 構造は変えない（構造の変更はテンプレートの改訂として AI アセットフェーズへ）
   - **どの節に収めるかは仕様の「OUT ひな形の節 → HTML の節」の対応表で決め、その場で判断しない**（判断がぶれると同じ種類のレポートでも節の位置が変わり、レビュアーが探す場所を覚えられない）。対象はサイドバーのメタ情報、結論の要約はサマリ、確かめられなかったことは同名の節、実施した内容と一覧の表は「実施した内容と結果」、後続への反映は「設計への反映」、逸脱は「想定と異なった点」、残課題・保留・対象なしの根拠は「残課題」。どれにも収まらない種類固有の節だけを必須節の後に足す
   - 視覚語彙: 結論の性質は 3 色 + 記号 + 文字（◎良 / △注意 / ✕問題）、レビューの重みは ◆特に見てほしい / ◇判断が欲しい / ・細かいレビュー不要。独自の色・記号を持ち込まない
   - レポートの章 ID は `f1, f2, …` の連番。目次・件数・未確認一覧・重点依頼から同じ ID を参照する
4. **検査する**: `bash .claude/skills/20-common-step-report-view/scripts/check-html.sh <file.html>`。失敗したら原因を直して再実行する（飛ばさない）。検査は全項目を実行して未充足を全件列挙する
5. **md と HTML の対応を自分で確かめる**: `check-html.sh` は HTML の構文と必須節の存在しか見ないので、**md にあって HTML に無い節・表・行は検出できない**。見出しの数・表の数・同じことを述べている数値を突き合わせ、食い違ったら HTML 側を直す
   - **同じ対象を指す 2 つの数**を並べて数える（結論の数なら md の `###` の見出し数と HTML の `<h3 id=` の数。`id` を持たない見出しはテンプレートの飾りなので数から外れる）。数え方をその都度決めない
   - **同じ数を 2 か所以上に書くときは内訳を必ず添える**（「27 件」ではなく「◎良 14 / △注意 12 / ✕問題 1 = 27 件」）。片方を更新し忘れると足し算が合わなくなって気づける
   - **累積の数（タスク全体の合計・テスト ID の総数など）は 1 か所にだけ置き、他の箇所はそこを指す**。複数の節に書くと、追記のたびに全部を直すことになり必ずどれかが古くなる
6. **記録する**: 検査結果（`OK: 検査 7 項目すべて通過（id N 件 / リンク M 件…）`）と 5 の突き合わせの結果を作業ログに残す
7. **同期する**: 以後 md を更新したら、同じ変更を HTML に反映して 4〜6 を繰り返す（追記だけで済ませない。md 側の差分が追加のみでなければ HTML も追加のみでは同期していない）

## 参照

- テンプレート: `assets/report.template.html`（レポート。`<body data-template="report">`）、`assets/plan.template.html`（計画書。`<body data-template="plan">`）。必須節の一覧はテンプレートの `data-required` だけが持つ
- 提供コマンド: `scripts/check-html.sh`
- md / html の対の存在検査: `20-common-step-commit-push`（push 前チェック項目 3）
- 検査結果の記録先: `20-common-step-ticket`（作業ログ）
- HTML ビューの対象と md 正文の原則: 要件書、DDR `i0001-05`

## エラー時の対処

| 状況 | 対処 |
|------|------|
| `RV001:` プレースホルダ残存 | 列挙された `{{名前}}` をすべて埋める（コメント内も数える。地の文で触れるときは表記を変える） |
| `RV002:` 外部リソース | `src` / `<link href>` / CSS `url()` / `@import` を除く。`<a href>` のハイパーリンクと `data:` URI は対象外なので、画像は data URI にする |
| `RV003:` id 重複 | 章をコピーしたら `f2, f3, …` に振り直す |
| `RV004:` 破断リンク | 目次・重点依頼・未確認一覧のリンク先 id を本文と揃える。任意節を削ったら目次の行も消す |
| `RV005:` `<style>` が 1 つでない | 追加した `<style>` を統合する（テンプレートの 1 つだけ） |
| `RV006:` 必須節が無い / テンプレートを特定できない | 削った必須節を戻す（無ければ「無し」と 1 行）。`<body data-template="report|plan">` を残す |
| `RV007:` id・リンク 0 件 | テンプレートから作っていない（白紙・スクリプト生成）。テンプレートを Read して Write するところからやり直す |
| `RV008:` 引数・ファイル不正（終了 2。検査には入っていない） | 存在する `.html` のパスを 1 つだけ渡す |
