この計画で何をするか

拡張の設計文書 7 ファイルをアプリルート配下へ移し、配置図・DDR の状態・仕様書の節名を揃え、移行のために残していた旧置き場の仕掛けを 1 回で外す。

決めたこと

  • docs/ の 7 ファイルを階層を変えずに apl/vscode-ticket-board/docs/ へ
  • 文書どうしの相互参照は docs/ 配下の相対なので解決先が変わらない
  • 旧置き場の片付けは 正史 → 設定 → テスト の順で 1 回にまとめる
  • F4 は F1 の後。先にやると未移動の docs/ を計画タスクが書けてしまう

F4 旧置き場の片付け§8 の段落・7 type の deny・テストのアサーション 4 件を 1 回で落とすai-asset-design → ai-asset-implementation

リスクと復旧

リスク影響対処・巻き戻し
F4 を F1 より先にやるまだ移動していない docs/ を計画・調査タスクが書けてしまう手順の順序を固定する（F1 → … → F4）
移動元の削除が判定順 (7) の ask WF202 に落ちる移動が止まる一度きりの移行としてこの ask を承認する（フック共通仕様 §8）
commit.sh が削除だけのコミットを作れないフェーズ 4 と同じ壁に当たる既知（B3）。手で検査を満たして git commit を使い、作業ログに記録する
F4 で deny を外しすぎる計画・調査タスクが apl/ を書けてしまう外すのは src/ と docs/ だけ。apl/ の deny は残し、テストで固定する
節名の変更が DDR i0013-02 と食い違う正史が 2 つになる新 DDR i0020-04 で置き換え、i0013-02 の frontmatter に置き換え先を書く
