# 10-task-design-exec の eval 定義

## 目的

`10-task-design-exec` の SKILL.md（実施タスクの共通手順 + 設計の固有手順）を読み込んだときに、要件を外部視点で書くこと・仕様にテスト ID を振ること・担当範囲を越えないこと・骨子どおりに書けないときの扱いが安定するかを確かめる。

## 評価シナリオ

各行は仕様書「テスト観点（eval）」の行と 1:1 に対応する（eval ID が対応の鍵）。

| eval ID | 入力プロンプトと状況 | 期待する振る舞い | 判定方法 | 添付ファイル |
|---------|--------------------|-----------------|---------|-------------|
| DGE-E01 | アプリの要件定義書（`apl/auth-gateway/docs/00_requirement/`）を書く | 受け入れ条件を EARS で書き、内部構造（クラス名・関数名・スキーマ）を仕様書へ回す | 要件書に内部構造が無いこと | 設計計画書 |
| DGE-E02 | アプリの仕様書（`apl/auth-gateway/docs/10_spec/`）を書く | 入出力・判定・エラー・テストシナリオを実装可能な粒度で書き、シナリオにテスト ID を振る | テスト ID の存在と、実装が推測なしに作れる粒度 | なし |
| DGE-E03 | 設計チケット 2 枚のうち 1 枚（認証まわり）を実施する | そのチケットが担う文書だけを書き、他のチケットの文書に手を出さない | 変更したファイルとチケットの担当範囲の一致 | なし |
| DGE-E04 | 骨子が前提にしていた既存インターフェースが実際には無いと分かった | 推測で骨子を変えず、書ける範囲を書いて「未解決事項」と代わりの案をレポートに残す | レポートの記載と、骨子との差分の扱い | なし |

## 比較条件

- with: Skill ツールで `10-task-design-exec` を読み込んだ状態で各シナリオのプロンプトを与える
- without: SKILL.md を読み込まず、`CLAUDE.md` と対象の要件書・仕様書だけを文脈に置いた状態で同じプロンプトを与える
- 実施回数: シナリオごとに with / without を各 3 回

## 効果ありの判定基準

- DGE-E01: with の 3 回すべてで要件書に内部構造が無く、without で 1 回以上混ざる
- DGE-E02: with の 3 回すべてでテスト ID が振られ、without で 1 回以上欠ける
- DGE-E03: with の 3 回すべてで担当範囲に収まり、without で 1 回以上他チケットの文書を触る
- DGE-E04: with の 3 回すべてで未解決事項として残り、without で 1 回以上骨子を書き換える
- 4 シナリオのうち 3 つ以上で上記を満たせば効果あり。差が出ないシナリオは SKILL.md の該当手順の文言を見直す対象として記録する
