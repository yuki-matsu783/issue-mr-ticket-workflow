# i0009-52. 通知しない場合も `skip` を記録し、縮退時は自分で判定する

## 背景

`i0009-31` は「WF801 の再掲は**縮退時の唯一の通知経路**であり、通常経路では出さない」と決め、仕様に「`decisions.jsonl` に `subagent-start-check` の WF801 の `notify` 記録が**無い**ときだけ再掲する」と書いた。

ワーク境界の 2 巡目レビューで、この条件が論理的に成立しないことが分かった。

- **記録が無いなら再掲する元が無い**。「再掲」は既にある記録を読み直して伝えることなので、記録が無い状態では実行できない
- 縮退時に通知するには `subagent-stop-check` が**自分で** `tool_input.model` とチケットの `executor` を比較する必要があるが、その手順が制御方式に 1 つも無く、入出力にも `decisions.jsonl` / `model-aliases.txt` / `tool_input.model` が挙がっていなかった
- さらに「記録が無い」は 2 つの状態を区別できない — (a) PreToolUse の経路が使えず**判定していない**（縮退）、(b) PreToolUse が判定したが**通知不要と決めた**（一致していた等）。(b) で再掲すると同じ不一致を 2 回通知するどころか、不一致でないものを通知することになる

## 決定

- **`subagent-start-check` は通知しなかった場合も `decisions.jsonl` に `skip` を記録する**（理由: 一致 / 対象チケット無し / `executor` の記載無し / `model` が特定できない / `subagent_type` が対象外 の 5 通り）
- **縮退の判定**: 同じ `tool_response.agentId` について `subagent-start-check` の記録が **1 件も無い**ときだけが縮退である（`notify` があれば通知済み、`skip` があれば通知不要と判定済み）
- **縮退時、`subagent-stop-check` は「再掲」ではなく自分で判定する**。`tool_input.subagent_type` が `task-executor` で、対象チケットの `executor` が `main` 以外で、`tool_input.model` が特定でき、`model-aliases.txt` で正規化して不一致なら WF801 を出す
- 制御方式にこの手順を置き、入出力に `tool_input`（`subagent_type` / `model`）・`decisions.jsonl`・`model-aliases.txt` を加える
- `SP-T08` で固定する（記録が無い → 出る / `skip` がある → 出ない / `notify` がある → 出ない）

## 理由

- **判定した事実を残さないと、判定したかどうかが分からない**。「記録の有無で縮退を見分ける」設計を採る以上、判定のすべての分岐が記録を残す必要がある。`skip` は `decisions.jsonl` の既存の値で、新しい仕組みを足さない
- **`skip` の記録は振り返りにも効く**。「なぜ通知されなかったのか」（`model` が省略されていた等）が後から分かる。`i0009-06` の限界 1（`model` 省略で比較できない）がどれくらい実際に起きるかを測れる
- **縮退時の判定は同じ入力でできる**。PostToolUse `Agent` は同じツール呼び出しなので `tool_input.model` が読める。新しい入力は要らない
- **「再掲」という言葉を残すと実装が迷う**。何を再掲するのかが存在しないので、実装者は記録を探し続けるか、勝手に判定を書くかのどちらかになる

## 却下した案

- **記録の有無ではなく、環境変数（`WORKFLOW_SUBAGENT_START_CHECK_ENFORCE=0`）で縮退を判定する**: 縮退の原因は停止だけでなく、登録漏れ・フックの起動失敗・matcher の不一致もある。記録の有無ならすべてを同じ形で拾える
- **`subagent-stop-check` が常に判定し、`subagent-start-check` の記録があれば黙る**: 判定のコストは小さいので実質同じだが、「誰が正か」が曖昧になる。正は `subagent-start-check` で、こちらは縮退時の代替という関係を保つ
- **`skip` を記録せず、`notify` の有無だけで判定する**: (b)（通知不要と判定済み）が縮退と区別できず、一致しているのに WF801 が出る
- **`subagent-start-check` の記録を `logs/sessions/<session_id>/subagent-<agent_id>.json` 側に持つ**: `decisions.jsonl` は全フックの判定の記録という位置づけ（§5）で、判定したことはそこに残るのが自然。ファイルを増やさない
