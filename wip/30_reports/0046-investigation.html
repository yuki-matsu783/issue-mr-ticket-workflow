shlex は cmdpos.sh の代わりにならない。供給できるのは語割りとクォート除去だけで、出力 10 項目のうち 7 項目は自前実装が丸ごと残る。50 件のコーパスで突き合わせると shlex 側に実行位置の見落としが 6 件、実行されない語の誤検知が 1 件出た。見落としは検査をすり抜ける方向の誤りで、フックの用途では致命的になる。一方 shlex は現行実装の既知の弱点を 6 件で正しく解いており、照合役として使えばバグを機械的に見つけられる筋は残る。

◆特に見てほしい

判断に困っている

  • 見落とし 6 件のうち 3 件（$(( )) 由来）は、punctuation_chars を切れば直るかもしれない。切ると区切り記号の語割りを自前でやることになるが、その道を試すべきか
  • 照合役案の価値を、差分 23 件のうち「shlex の方が正確」6 件だけで測ってよいか。表現差 10 件を除く設計が要る

◇承認が欲しい

方針は決めた

  • 本番置換は勧めない。置き換わるのは 429 行のうち正規化部 120 行程度で、代償に 7 件の判定誤りが入る

・細かいレビューは不要

ほぼ確実

  • リダイレクト演算子がサブコマンドに漏れる 4 件は試作の粗さで、shlex の欠陥ではない

確かめられなかったこと（この結果が言っていないこと）

  • shlex を本番に置いた場合の総合的な正しさ。試作は「段分割 + 実行体 + サブコマンド」に絞っており、CP_WRITE_TARGETS や CP_OPAQUE の再実装は行っていない
  • PowerShell 経路の網羅。最小入力 2 件を見ただけで、コーパスによる突き合わせは bash 経路のみ

実施条件（測った対象・環境）

  • Python 3.11.15（Linux コンテナ）。shlex は標準ライブラリ
  • 現行実装は .claude/hooks/lib/cmdpos.sh（429 行、コミット 6c87efb 時点）
  • コーパスは wip/tmp/corpus.json の 50 件。test_cmdpos.sh のテスト入力を土台に、ヒアドキュメントと算術展開の境界例を追加
  • 突き合わせの署名は「段の数 + 各段の実行体とサブコマンド」。bash wip/tmp/bench.sh dump-corpus と python3 wip/tmp/probe.py a3

実施した内容と結果

  1. 1

    A-1 出力 10 項目の切り分け △注意 根拠: cmdpos.sh:8-27 の公開 API 定義

    shlex が供給するのは CP_ARGS（全面）と CP_EXE・CP_REDIRECTS（部分）の 3 項目。残る 7 項目は外側に自前で書く。

    出力shlex が供給するか残る自前実装
    CP_EXE部分的basename 化・.exe 除去・小文字化・ラッパー 20 語の読み飛ばし・変数代入の読み飛ばし
    CP_ARGS供給する区切りバイトへの詰め直しのみ
    CP_SUBCMD供給しないgit のグローバルオプション表を持った走査
    CP_REDIRECTS部分的fd 番号（2>）の結合、fd 複製と &> の区別、/dev/null の除外
    CP_WRITE_TARGETS供給しない10 コマンドのオプション表と位置引数の解釈
    CP_OPAQUE供給しない実行系の語彙表と -c 併用の判定
    CP_PROVIDED供給しない提供コマンドのパス形の照合
    CP_DATA供給しない（むしろ壊す）ヒアドキュメントの追跡が無く、本文を実行位置の語として出す
    CP_GITLIKE供給しない縮退時の代替判定で shlex とは無関係
    CP_DEGRADED供給しないbash の版数と 4096 文字の縮退条件を Python 用に定義し直す

    結論

    429 行のうち shlex に置き換わるのは正規化部（_cp_normalize_to_reply とその補助、おおよそ 120 行）に留まる。

  2. 2

    A-2 扱えない構文 5 種 ✕問題 根拠: python3 wip/tmp/probe.py a2

    5 種のうちヒアドキュメント・コマンド置換 / バッククォート・算術展開の 3 種が判定を壊す。fd 複製と PowerShell は「自前実装が要る」で済む。

    根拠を見る（実行コマンドと出力） 
    $ python3 wip/tmp/probe.py a2
=== ヒアドキュメント本文 ===
  入力  : 'cat <<EOF\ngit commit\nEOF'
  語    : ['cat', '<<', 'EOF', 'git', 'commit', 'EOF']
=== サブシェル展開 $( ) ===
  入力  : 'echo "$(git commit -m x)"'
  語    : ['echo', '$(git commit -m x)']
=== バッククォート ===
  入力  : 'echo `git commit`'
  語    : ['echo', '`git', 'commit`']
=== fd 複製 2>&1 ===
  入力  : 'git push 2>&1 >/dev/null'
  語    : ['git', 'push', '2', '>&', '1', '>', '/dev/null']
=== 算術展開の << ===
  入力  : 'echo $((1<<2)); ls'
  語    : ['echo', '$', '((', '1', '<<', '2', '));', 'ls']
=== PowerShell 行継続 ===
  入力  : 'git `\n  push'
  語    : ['git', '`', 'push']

    結論

    算術展開では )); が 1 語になり、その中の ; が区切りとして働かない。後続の段が丸ごと消える。コメントには逆向きの罠もある。shlex の commenters は文字単位で語頭を見ないため、foo#bar git status を ['foo'] に切り詰め、git status を落とす。cmdpos.sh は直前の文字が語の切れ目かを見ている（cmdpos.sh:107-114）。

  3. 3

    A-3 現行実装との差分（コーパス 50 件） ✕問題 根拠: python3 wip/tmp/probe.py a3

    一致 27 件 / 差分 23 件。差分の性質は 4 つに分かれる。

    性質件数意味
    見落とし6実在するコマンドが shlex 側で見えない。検査をすり抜ける方向
    誤検知1bash が実行しないヒアドキュメント本文の語を実行位置として出す
    shlex の方が正確6現行実装が _ を返す入力で正しい値を復元する
    表現差・試作の粗さ10判定結果は変わらない
    根拠を見る（見落とし 6 件と誤検知 1 件） 
    --- c19 'echo "$(git commit -m x)"'
    cmdpos: n=2|echo:_;git:commit      shlex : n=1|echo:$(git commit -m x)
--- c20 'echo `git commit`'
    cmdpos: n=2|echo:;git:commit       shlex : n=1|echo:`git
--- c27 'echo $((1<<2)); ls'
    cmdpos: n=2|echo:_;ls:             shlex : n=1|echo:$
--- c28 'foo#bar git status'
    cmdpos: n=1|foo#bar:git            shlex : n=1|foo:
--- c45 'echo $((1<<2)); git commit'
    cmdpos: n=2|echo:_;git:commit      shlex : n=1|echo:$
--- c50 'cat <<EOF\nEOF\ngit push'
    cmdpos: n=2|cat:_;git:push         shlex : n=1|cat:<<
--- c46 'cat <<EOF\nfoo; git push\nEOF'   ← 誤検知
    cmdpos: n=1|cat:_                  shlex : n=2|cat:<<;git:push

一致 27 件 / 差分 23 件 / 合計 50 件

    結論

    c46 と c50 は同じ原因（ヒアドキュメントの追跡が無い）から誤検知と見落としの両方を生んでいる。一方 c31 git 'commit' は test_cmdpos.sh が「判定できない既知の制約」とコメント付きで固定している入力で、shlex は git commit と正しく復元した。照合役案の価値はここにある。

設計への反映

  1. 本番置換は勧められない。置き換えられるのは 429 行のうち正規化部 120 行程度で、代償に 7 件の判定誤りが入る。うち 6 件は検査をすり抜ける方向。同等の正しさを保つにはヒアドキュメント追跡・コマンド置換の再帰・算術展開の読み飛ばし・語頭を見るコメント判定を Python 側で書き直すことになり、shlex を使う利点がほとんど残らない
  2. 照合役としては筋がある。現行実装が _ を返す入力で shlex は正しい答えを出す。差を機械的に取れば取りこぼしを継続的に見つけられる。ただし差分の 10 件は判定に影響しない表現差なので、比較する項目を絞る設計が要る
  3. 照合役案を採るかどうかは 0043 の起動コスト（テスト実行時間への影響）を見てから決める

想定と異なった点

計画時の見込み実際どう扱ったか
コメントは shlex が扱えない構文commenters で扱える。ただし語頭を見ないため foo#bar を切り詰める想定と逆向きの見落としとして A-2 と A-3（c28）に記録した
ヒアドキュメントは本文を語として出す（誤検知）だけ区切り語の後に続く本物のコマンドを吸い込む見落とし（c50）も起きた両方向の誤りとして A-3 に分けて記録した
算術展開は観点に挙げていなかったpunctuation_chars=True が )); を 1 語にし、後続の段が消えるtest_cmdpos.sh の負のコントロールから拾い、コーパスに c45・c47 を足した

残課題

  • 試作の網羅範囲。CP_WRITE_TARGETS と CP_OPAQUE を shlex 版で再実装したときの差分は取っていない。本番置換を選ばないなら不要
  • PowerShell 経路のコーパス。bash 経路 50 件に対し PowerShell は最小入力 2 件のみ。照合役案を採る場合、対象にするかは設計で決める
  • shlex の版差。この環境は Python 3.11.15。punctuation_chars の挙動が古い版で異なるかは確認していない
