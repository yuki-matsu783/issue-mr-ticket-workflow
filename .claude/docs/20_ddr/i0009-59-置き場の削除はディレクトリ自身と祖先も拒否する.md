# i0009-59. 置き場の削除はディレクトリ自身と祖先も拒否する

## 背景

`i0009-30` は「作業中が 0 枚の切れ目では `workflow-guard` も判定しないので `rm wip/10_tickets/20_done/*.md` が誰にも止められない」という穴を塞ぎ、`workflow-state-guard` の制御方式 3 に「`rm` / `git rm` / `mv` / `git mv` の**元**が `wip/10_tickets/10_doing/**` → WF302、`20_done/**` → WF303」を足した。

ワーク境界の 2 巡目レビューで、この glob が**ディレクトリ自身を拾わない**ことが分かった。共通仕様 §8 の glob 規則は「`**` は 0 個以上のディレクトリに一致する」と定めるが、これは**パターンの位置より下**を指す。

| コマンド | `wip/10_tickets/20_done/**` に一致するか |
|---|---|
| `rm wip/10_tickets/20_done/0003.md` | する → WF303 |
| `rm -rf wip/10_tickets/20_done`（ディレクトリ自身） | **しない** |
| `rm -rf wip/10_tickets` | **しない** |
| `rm -rf wip` | **しない** |

作業中 0 枚の窓では `workflow-guard` も判定しない（制御方式 1）ため、**塞いだはずの穴が 1 段上のパスにそのまま残っていた**。`SG-T02` にもディレクトリ削除のケースが無かった。

## 決定

- 制御方式 3 の元判定を広げる: 元が `wip/10_tickets/10_doing/**` / `20_done/**` に一致するか、**それらのディレクトリ自身またはその祖先（`wip/10_tickets`・`wip`）である**とき → WF302 / WF303
  - 祖先の削除はどちらの置き場も消すので、識別子は **WF302**（作業中の置き場が消える方）に倒す
- `SG-T11` を新設して固定する: `rm -rf wip/10_tickets/20_done` が WF303、`rm -rf wip/10_tickets` と `rm -rf wip` が WF302、**`rm -rf wip/tmp` と `rm -rf logs` は通る**（負のコントロール）

## 理由

- **穴の大きさが 1 段上ほど大きい**。`rm -rf wip` は進行状態・チケット・計画書・結果報告をまとめて消す。ファイル単位の削除を塞いでディレクトリ単位を通すのは、塞いだことにならない
- **glob の意味を変えない**。`wip/10_tickets/20_done/**` が親に一致するように glob の規則を変えると、`.claude/**` が `.claude` の親（リポジトリルート）に一致するなど、他のすべての判定が壊れる。**この 1 か所で明示的に書く**のが安い
- **`wip/tmp` と `logs` は通す**必要がある。`wip/tmp/**` は作業用で消してよく、`logs/**` は `workflow-guard` の判定順 (1) で対象外。負のコントロールで固定する
- **祖先を WF302 に倒す**のは、作業中のチケットが消えることの方が回復しにくいため（完了済みは git 履歴から戻せるが、作業中の途中状態は戻せない）

## 却下した案

- **glob の規則を変えてパターン自身の親に一致させる**: 他のすべての判定が壊れる
- **`wip/**` を丸ごと保護対象にする**: `wip/tmp/**` への書き込み（作業用の一時ファイル）が止まる。`wip/20_plans/**` / `wip/30_reports/**` への書き込みも `common.allow` で許可されている
- **`rm -rf` の再帰オプションがあるときだけ拾う**: `rm -r` / `rm -rf` / `rm -fr` / `--recursive` の書き方を数える必要があり、しかも `rm wip/10_tickets/20_done`（空なら成功する）を取りこぼす
- **`workflow-guard` の側で拾う**: 作業中 0 枚では判定しない（制御方式 1）ので、この穴が開いた窓そのものを塞げない

## 影響

- `10_spec/hooks/20-PreToolUse/workflow-state-guard.md` 制御方式 3・`SG-T11`（新規）
- `20_ddr/i0009-30`（削除の遮断。ディレクトリ単位を含めることを追記する対象）
- **実装フェーズへ**: 祖先の判定は正規化した元パスの前方一致で足りる（`wip` / `wip/10_tickets` の 2 つを列挙する）
- 関連: `i0009-30`（削除の遮断）・`i0009-39`（`cmdpos_operands` で元を取る）
