# i0009-18. 提供コマンドは作業中チケット 1 枚を前提に動き、複数枚の検知はフックに委ねる

## 背景

issue #9 の申し送り G8 は「作業中チケットが 2 枚以上のときの扱い」を問うている。0012 は拒否側フックの側で `workflow-guard` の **WF207**（2 枚以上なら提供コマンド以外の書き込み・実行を deny）を確定し、DDR `i0009-02` で「2 枚以上の検知はフックの役割」と決めた。残るのは**提供コマンドの側**で、現状は次のように非対称になっている。

| 提供コマンド | 作業中チケットの見方 |
|---|---|
| `run-tests.sh` | `10_doing/*.md` の **1 枚目**の `allow.ops` を読む |
| `push.sh` の項目 2 | **1 枚目**の宣言を読む |
| `ticket.sh next` | **1 枚目**を `current` として返す |
| `ticket.sh start` | **件数**を見て、1 枚でもあれば TK002 で拒否する |
| `ticket.sh complete` / `cancel` | 番号を引数に取るので枚数に依存しない |

## 決定

- **提供コマンドの実体は直さない**。「作業中は 1 枚」を前提に動くことを 3 スキルの仕様に明記する
- 件数を見るのは **`ticket.sh start` だけ**とし、その位置づけを「2 枚目を作らせないための入口の防御」と書く
- 既に 2 枚以上ある状態の**検知と復旧の案内は `workflow-guard` の WF207** が担う（`i0009-02` の延長）
- `complete` / `cancel` は番号引数を取るので非対称ではない旨も書く
- 実体の修正が不要なので、**#10（3/3）への申し送りは出さない**

## 理由

- **同じ判定を 4 か所に置かない**。件数の検知を提供コマンド 3 本に足すと、判定が「フック 1 + コマンド 3」の 4 か所になり、メッセージと復旧の案内も 4 通りに分かれる。フック 1 か所なら回復の案内も 1 つ（`i0009-02` と同じ理由）
- **2 枚以上は機構の外でしか作れない**。`ticket.sh start` が入口を塞いでいるので、2 枚になるのは git 操作での復元・手動のファイル移動・機構の破損に限られる。その状態では WF207 が書き込みと実行を止めるため、提供コマンドが誤った 1 枚目を読んだとしてもできることはほとんど無い
- 残るリスクは「WF207 が提供コマンドを通す」ため `run-tests.sh` が誤ったチケットの `allow.ops` で判定し得ることだが、影響は**テストを走らせるかどうか**に閉じており、作業領域外への書き込みやリモート操作には及ばない
- 「1 枚目」の決め方（名前順 = チケット番号順）を仕様に書いておけば、万一 2 枚あっても挙動が決定的になる（実装ごとに変わらない）

## 却下した案

- **提供コマンド 3 本に件数検査を足す**: 判定が 4 か所に増える。しかも `push.sh` と `run-tests.sh` は「復旧のために動かしたい」場面（2 枚を 1 枚に戻す作業のあと）で止まると邪魔になる
- **`ticket.sh start` の件数検査もやめてフックに一本化する**: フックが停止している（`WORKFLOW_ENFORCE=0`）ときに 2 枚目が作れてしまう。作る側の入口だけは残すのが安い
- **2 枚以上を「1 枚目」ではなく「最後に着手したもの」で解決する**: `started_at` を全枚読む必要があり、ホットパスの `run-tests.sh` / `push.sh` に読み込みが増える。決定的でありさえすればよいので、名前順で足りる

## 影響

- `10_spec/skills/20-common-step-ticket.md`（`start` 1・`next` 1・`complete` 1）
- `10_spec/skills/20-common-step-commit-push.md`（push 前チェック 項目 2）
- `10_spec/skills/20-common-step-shell-script.md`（`run-tests.sh` 1・`TR-T05`）
- `10_spec/hooks/20-PreToolUse/workflow-guard.md` 制御方式 2（0012 で反映済み。ここでコマンド側と読み合わせた）
- 提供コマンドの実体（`ticket.sh` / `push.sh` / `run-tests.sh`）の修正は**不要**
