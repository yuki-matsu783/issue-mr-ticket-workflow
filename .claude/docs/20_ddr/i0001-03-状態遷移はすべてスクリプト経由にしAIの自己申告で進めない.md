# i0001-03. 状態遷移はすべてスクリプト経由にし AI の自己申告で進めない

## 背景

依頼では commit と push をスクリプト経由に限定し、それを使うスキルで挙動を標準化することが求められた。一方、参考実装 agent-workflow ではチケットの着手・完了（`git mv` + コミット）とレビュー状態（`request` / `complete`）が状態遷移の中心であり、これらがコミットを伴う。commit だけをスクリプトにしても、チケット移動を AI が手で `git mv` してからスクリプトでコミットする形になり、遷移の正しさ（WIP リミット・依存・境界）はスクリプトで保証できない。

## 決定

- 次の操作はすべて専用スクリプトのサブコマンド経由でのみ行う: コミット、push、チケットの着手・完了、レビュー依頼・レビュー完了・スレッド返信、マージ前作業（wip の片付け・衝突確認・issue 通知・draft 解除）
- `git` のコミット・push の直接実行、`10_doing/` へのファイル移動・直接書き込み、状態ファイル（JSON）の直接編集、`gh pr ready` の直接実行は PreToolUse フックが exit 2 で拒否する
- レビュー依頼・完了のスクリプトは MR への実操作（コメント投稿・レビュー取得）を自ら行い、その証跡（コメント ID・URL・HEAD の SHA・レビュー判定）を状態ファイルに記録する。AI が「依頼した」「確認した」と言うだけでは状態が進まない
- スクリプト間のコミットはすべてコミットスクリプトの規約（メッセージ形式・除外リスト）に従う

## 理由

- 遷移の前提条件（未コミット無し・push 済み・境界にいる・CHANGES_REQUESTED でない など）を 1 箇所で検証でき、フックはその経路以外を塞ぐだけでよい
- 証跡が Git 管理下に残るため、レビュアーは MR の差分で「いつ何が依頼され何が確認されたか」を追える
- 依頼の「挙動を標準化する」を、commit / push に限らずワークフローの全遷移に広げるのが一貫している

## 却下した案

- **commit / push だけをスクリプトにし、チケット移動は `git mv` を許す**: 依頼の文面には十分だが、WIP リミットや境界の検証がフック側の複雑な `mv` 解析に依存する
- **状態を AI に報告させ、人間が信じる**: 最も単純だが、compact やセッション再開で AI の認識が失われたときに状態も失われる
- **フックだけで直接実行を拒否し、スクリプトは作らない**: 拒否はできても、正しい経路を AI に示せず、都度ユーザーが手で操作することになる

## 影響

- 要件定義書 C・E・J 節
- スクリプトのサブコマンド一覧と状態ファイルのスキーマは仕様で定める
- 直接実行の検知は「コマンド位置」で判定し、地の文・ヒアドキュメント内の語で誤検知しない（縮退時の部分一致は仕様に明記）
