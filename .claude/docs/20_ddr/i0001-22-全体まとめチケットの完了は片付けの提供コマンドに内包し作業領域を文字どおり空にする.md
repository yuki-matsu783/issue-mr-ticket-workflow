# i0001-22. 全体まとめチケットの完了は片付けの提供コマンドに内包し、作業領域を文字どおり空にする

## 背景

敵対的レビューで、全体まとめの終盤の状態機械が未決着だと指摘された。従来の記述は「片付け → 全体まとめチケットを完了 → push → draft 解除」と読め、完了した全体まとめチケット自身が作業領域（完了の置き場）に残るため、「draft 解除時に作業領域が空」という要件と矛盾していた。機構の要件（J 節）は「片付け後はチケットが無い」前提で書かれており、完了と片付けのどちらが先でどちらが何を消すのかをどの文書も決めていなかった。あわせて、全体まとめが人間レビュー要とされた場合のレビュー依頼（push 済みが前提）の位置と、「main に残したい内容の `.claude/docs/` への書き写し」の実行主体（全体まとめは `.claude/docs/` を書けない）も未規定だった。

## 決定

- **片付けの提供コマンドが全体まとめチケットの完了を内包する**: コマンドは (1) 全体まとめチケットの完了検査（DoD・作業ログ）と完了時刻の記録を行い、(2) 通れば完了済みチケットを含む作業領域全体（全体計画書・チケット・計画書・レポート・ブランチ内の進行状態・一時ファイル）を空にする（機構がブランチ外に記録する進行状態 — MR・マージ前作業・前回 push の記録 — は消えない場所に残り、片付け後の継続判定を支える）。完了のスクリプトを単独で実行しない
- 片付け後は「チケットが無い状態」になり、push と draft 解除はその状態でも拒否されず、振り分けの再宣言も求められない（既存の J 節の規定がそのまま成り立つ）
- **レビュー要の場合の push 位置**: 全体計画で全体まとめチケットの人間レビューが「要」とされた場合は、HTML レポートの添付まで済ませた時点で push してレビューを依頼し、レビュー完了（未解決スレッドの確認を含む）後に片付け以降へ進む。push はこのチケットの宣言に含まれる
- **書き写しの主体**: 全体まとめが行う書き写しは MR 本文と添付に限る。`.claude/docs/` に残す内容は、それを書けるフェーズのタスクが自フェーズ内で済ませる。片付け前に未反映が見つかったら別 issue の起票に回す

## 理由

- 片付けが完了を内包すれば、片付けはチケットが作業中の状態で呼ばれるため、リモート書き込みの宣言体系（push・draft 解除の宣言は全体まとめチケットにある）と整合したまま、「作業領域が空」を文字どおり検査できる
- 完了と片付けを別ステップにすると、完了から片付けまでの間に「チケットはあるが作業中が無い」無宣言の隙間ができ、切れ目の統制の穴を 1 つ増やす
- 書き写しを全体まとめに担わせると「`.claude/` 配下を書けない」という宣言上限と矛盾する。各フェーズで済ませる方が、書ける者が書く原則にも合う

## 却下した案

- **完了 → 片付けの 2 ステップ**: 状態機械は成立するが、完了後の操作（片付け・push・draft 解除）が宣言の切れた状態で行われ、統制の例外を別途定義する必要がある
- **「作業領域が空」を「完了済みの全体まとめチケットのみ許容」に緩める**: 検査が複雑になり、「空」の意味が文書ごとにぶれる火種を残す
- **全体まとめに `.claude/docs/` への書き写し権限を追加する**: 書ける範囲が広がり、「まとめのタスクは成果物を作らない」という役割の輪郭が崩れる

## 影響

- `10-task-overall-summary.md`（メインフロー・代替フロー・書き写しの規定）
- `20-common-step-ticket.md`（全体まとめチケットの完了の例外）
- 自己改善ワークフロー機構.md C 節・J 節（片付けの規定・書き写しの主体）
- 片付けの提供コマンドの仕様（完了検査の内包。仕様書で定める）
