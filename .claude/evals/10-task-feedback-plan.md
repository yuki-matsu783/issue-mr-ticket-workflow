# 10-task-feedback-plan の eval 定義

## 目的

`10-task-feedback-plan` の SKILL.md（洗い出し → 分類 → 合意 → 別 issue → 後続の確定）を読み込んだときに、記憶ではなく記録から洗い出すこと・0 件でも根拠を残すこと・ヘッドレスで止まらないこと・別 issue だけは起票しないこと・2 軸で反映先を選ぶことが安定するかを確かめる。

## 評価シナリオ

各行は仕様書「テスト観点（eval）」の行と 1:1 に対応する（eval ID が対応の鍵）。

| eval ID | 入力プロンプトと状況 | 期待する振る舞い | 判定方法 | 添付ファイル |
|---------|--------------------|-----------------|---------|-------------|
| FBP-E01 | 完了したチケットが 12 枚ある状態でフィードバック計画に着手する | 全チケットの作業ログの固定見出しを機械的になぞって候補を洗い出す。記憶から書かない | 候補ごとの出どころ（チケット番号と見出し）の記載 | `assets/feedback-plan.template.md` |
| FBP-E02 | 全チケットの作業ログを見ても改善候補が 0 件だった | 0 件である根拠（確認した記録の範囲）を計画書に書き、後続フェーズを含めずに次のチケットを作る | 計画書の記載と、起票したチケット | なし |
| FBP-E03 | `WORKFLOW_HEADLESS=1` の実行で、候補 4 件の対応先の合意が取れない | 既定の提案（この MR で対応）どおりに決めて後続チケットの作成まで行い、決めた内容を MR に記録する。止まらない | 起票したチケットと MR の記録 | なし |
| FBP-E04 | 同じヘッドレス実行で、候補 1 件が「別 issue」と判断された | 起票せず、候補と理由を計画書と MR の記録に残す（取り消せない外部への副作用） | 起票の有無と記録 | なし |
| FBP-E05 | 「除外リストに拡張子が足りない」という候補の反映先を考える場面 | 「いつ効くか × 守らせ方」の 2 軸で選び、常時読み込まれるアセットを増やすコストを考える | 計画書の反映先の書き方 | なし |

## 比較条件

- with: Skill ツールで `10-task-feedback-plan` を読み込んだ状態で各シナリオのプロンプトを与える
- without: SKILL.md を読み込まず、`CLAUDE.md` と対象の要件書・仕様書だけを文脈に置いた状態で同じプロンプトを与える
- 実施回数: シナリオごとに with / without を各 3 回

## 効果ありの判定基準

- FBP-E01: with の 3 回すべてで候補に出どころが付き、without で 1 回以上出どころ無しの候補が混ざる
- FBP-E02: with の 3 回すべてで 0 件の根拠が書かれ、without で 1 回以上根拠なしに 0 件とする
- FBP-E03: with の 3 回すべてで後続チケットが作られ、without で 1 回以上合意が取れずに止まる
- FBP-E04: with の 3 回すべてで起票 0 件、without で 1 回以上無断で起票する
- FBP-E05: with の 3 回すべてで 2 軸の記載があり、without で 1 回以上「CLAUDE.md に書く」で済ませる
- 5 シナリオのうち 4 つ以上で上記を満たせば効果あり。差が出ないシナリオは SKILL.md の該当手順の文言を見直す対象として記録する
