# i0009-29. `workflow-state-guard` は設定が読めなくても既定値で判定を続ける

## 背景

`workflow-state-guard` の保護対象は 3 つで、うち 1 つだけが設定に由来する。

| 保護対象 | 由来 |
|---|---|
| 進行状態ファイル | `scope-limits.json` の `common.state_files` |
| 置き場（`wip/10_tickets/10_doing/**`・`20_done/**`） | 仕様に固定 |
| draft 解除コマンド | 仕様に固定 |

制御方式に「設定が読めない」分岐が無く、拒否側の原則（§3「判定できなければ拒否側に倒す」）どおりなら **WF309** に倒れる。

一方 `workflow-guard` は同じ状況を **WF210** とし、**復旧経路**を用意している: 提供コマンドの実行、`wip/10_tickets/**` への書き込み、そして **`scope-limits.json` 自身への ask（WF203）付きの書き込み**。

境界レビュー（付録 A の R13）の指摘: フックは**並列に走る**（`i0009-21`）ので deny はどれか 1 つでも出れば成立する。state-guard が WF309 に倒れると、workflow-guard がわざわざ用意した復旧経路が**潰される**。設定 1 ファイルの破損が完全なロックアウトになる。

## 決定

- `scope-limits.json` が読めない・解釈できないとき、`workflow-state-guard` は**拒否に倒さず**、`common.state_files` の**既定値**（`logs/mr.json` / `logs/review-state.json` / `logs/review-history.jsonl` / `logs/merge-state.json`）にフォールバックして判定を続ける
- フォールバックした旨を `notify` で記録する
- 置き場と draft 解除の判定は設定に依存しないので、そのまま働く
- 禁止事項「保護対象の一覧をコードに埋めること」に但し書きを足す（**設定が読めないときの既定値は例外**）
- テスト `SG-T10` に「設定が壊れていても拒否に倒れず、`scope-limits.json` 自身への Write がこのフックを通る」を置く

## 理由

- **拒否側に倒す原則は「守る対象に関わり得るのに判断できない」場合のもの**。ここで判断できないのは `state_files` の一覧だけで、しかもその既定値は仕様が知っている。判断できないのではなく、設定が壊れているだけ
- **復旧経路は 1 本でも塞がれば意味が無い**。並列実行なので、復旧経路を用意する側（workflow-guard）と塞ぐ側（state-guard）が別のフックでも結果は同じ。復旧経路の設計は**全フックの合意**で成立する
- 既定値をコードに持つことは禁止事項に触れるように見えるが、禁止の趣旨は「設定を読まずに埋め込む（設定を無視する）」ことで、**設定が読めないときのフォールバック**は別。但し書きで明示する
- 既定値が実際と食い違っていても害は小さい: 多く守りすぎれば復旧の書き込みが 1 つ止まるだけ（そのファイルは提供コマンド経由で触れる）、少なく守れば設定破損中の一瞬だけ保護が緩む

## 却下した案

- **原則どおり WF309 に倒す**: 上記のロックアウト
- **設定が読めないときは何も判定せず全部通す**: draft 解除の直接実行まで通る。守る対象のうち 2 つは設定に依存しないので、捨てる理由が無い
- **`workflow-guard` の復旧経路を state-guard にも複製する**: 復旧経路の定義が 2 か所になり、片方だけ更新される（`i0009-17` と同じ形の誤り）
- **既定値を別ファイル（`state-files.default`）に外出しする**: 設定が読めない状況で別の設定を読むことになり、同じ問題が 1 段深くなるだけ

## 影響

- `10_spec/hooks/20-PreToolUse/workflow-state-guard.md` 禁止事項・制御方式 0（新設）・`SG-T10`（新規）
- `10_spec/hooks/20-PreToolUse/workflow-guard.md` 判定順 3（WF210 の復旧経路。変更なし。ここで読み合わせた）
- **実装フェーズへ**: 既定の `state_files` は `workflow-state-guard` の中に定数として持つ（他のフックには複製しない）
