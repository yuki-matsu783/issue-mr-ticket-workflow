## 方針

基準は `.claude/rules/work-defaults.md`。**全種類で実行者を基準から外す**。理由は下記「機構の欠落」。人間レビューの要否は基準どおり、敵対的レビューだけ扱いを変える。

| type | 実行者 | 人間レビュー | 敵対的レビュー | 基準との差分 |
|---|---|---|---|---|
| overall-plan | メインエージェント | 要 | 不要 | 基準どおり |
| investigation-plan | メインエージェント | 不要 | 不要 | 実行者をサブエージェント（opus）から変更 |
| investigation | メインエージェント | 要 | 不要 | 実行者をサブエージェント（sonnet）から変更 |
| ai-asset-design-plan | メインエージェント | 不要 | 不要 | 実行者をサブエージェント（opus）から変更 |
| ai-asset-design | メインエージェント | 要 | 人間レビューに統合 | 実行者と敵対的レビューを変更 |
| ai-asset-implementation-plan | メインエージェント | 要 | 不要 | 実行者をサブエージェント（opus）から変更 |
| ai-asset-implementation | メインエージェント | 要 | 人間レビューに統合 | 実行者と敵対的レビューを変更 |
| feedback-plan | メインエージェント | 要 | 不要 | 基準どおり |
| overall-summary | メインエージェント | 要（最終確認） | 不要 | 基準どおり |

### 機構の欠落（差分の理由）

`work-defaults.md` の「提供コマンドが未完成でサブエージェントに状態遷移を任せられない等、プロジェクトの一時的な事情で全種類を一律に変える場合も、差分として明示する」に当たる。issue #10（実装 3/3）が未完了で、次が揃っていない。

- `10-task-*` スキル 15 本が未作成（`.claude/skills/` にあるのは `00-workflow-*` 2 本と `20-common-step-*` 7 本のみ）。サブエージェントに渡す手順書が無い
- 敵対的レビューエージェントが未作成（`.claude/agents/` が空）。敵対的レビューは人間レビューの観点に統合し、レビュー依頼の本文に「敵対的に見てほしい点」を明示して代替する
- `work-boundary.sh` / `merge-prep.sh` が未作成。ワーク境界の判定・レビュー依頼・レビュー完了の確認・マージ前作業は、メインエージェントが手順を代行する（レビュー状態ファイルは作らない）

代行の内訳:

| 本来の経路 | 本 PR での代行 |
|---|---|
| `work-boundary.sh status` | 作業領域のチケットの type を目視で確認する |
| `work-boundary.sh request --body-file` | `push.sh` の後、PR にレビュー依頼コメントを投稿し、チャットで報告して応答を終える |
| `work-boundary.sh complete` | 次のユーザー発言でレビュー結果を受け取り、指摘があれば同 type の追加チケットにする |
| `merge-prep.sh reset-wip` | `git rm` + `commit.sh`。ただし `wip/10_tickets/20_done` はフック WF303 が拒否するため人間の手が要る |
| `merge-prep.sh ready` | 人間が GitHub 上で draft を解除する（`gh pr ready` は WF015、MCP の `draft:false` は WF304 が拒否する） |

### やってよいこと

各チケットの `allow.write` / `allow.ops` は `.claude/hooks/config/scope-limits.json` の type ごとの既定に従う。追加の許可は次の 1 点だけ。

- `investigation` チケットで `python3` と `bash` の起動時間を測る。`scope-limits.json` の `commands.build-test` は npm の 6 コマンドしか列挙しておらず、計測コマンドが含まれない。計測は `wip/tmp/` 配下のスクリプトに閉じ、リポジトリの追跡ファイルには書き込まない

## 保留した点

| `shlex` の置き場（本番置換 / テストの照合役 / 採用しない） | フェーズ 5。フェーズ 3 の実測を材料にする |
