# i0001-21. 用語辞書は案内役でなく定義の正とし、文書は用語を定義し直さず辞書へリンクする

## 背景

当初は参考実装（agent-workflow）を踏襲し、「用語辞書は正典（requirements / spec）への案内役に徹し、辞書自身が用語を再定義しない」方式を要件にしていた。この方式で初期エントリを作ったところ、2 つの問題が表面化した。

1. **定義元リンクが不安定**: 用語の定義が要件書の Shall の中に散在しているため、辞書からのリンクは「暫定文書の C 節」のような節単位でしか張れない。要件書は分配・再編される予定で、作った直後から「分配時にリンク更新が必要」という引き継ぎ事項が発生した
2. **AI のコンテキスト効率が悪い**: 用語の意味を知るには辞書 → 正典の 2 ホップで、正典は長大な要件書。案内役方式の辞書は中身を持たないため、サブエージェントに渡しても概念体系が伝わらない

## 決定

- 用語の**定義（意味・目的・他の用語との関係）の正は用語辞書**に置く。エントリは定義（2〜4 行）・正典（その用語の振る舞いを定める requirements / spec）へのリンク・別名・禁止表記を持つ
- 辞書は**振る舞いの要件（When / Shall、判定基準・数値・手順）を持たない**。振る舞いの正は requirements / spec のまま
- requirements / spec は収録語を**定義し直さず**、初出箇所で辞書へリンクする

## 理由

- 辞書 1〜数ファイルで機構の概念体系が伝わり、サブエージェント（チケット実行者・レビューエージェント）の起動時入力にそのまま使える。コンテキスト消費が減る
- リンクの向きが「多数の文書 → 1 つの辞書」に揃い、定義は辞書に固定される。要件書の節をどう分配・改名しても定義の置き場が動かず、文書の再編に強い
- 文書側が用語説明を再掲しなくなり、重複が減る
- 「定義は辞書・振る舞いは requirements / spec」の線引きにより、正史の一意性は保たれる

## 却下した案

- **案内役方式（参考実装踏襲・当初案）**: 定義が要件書に散在して節単位リンクが再編で壊れ、辞書単体に情報量が無くサブエージェント入力に使えない
- **辞書に振る舞いの要件も書く**: 1 箇所で全部読めるが、requirements / spec と正史が二重化し、片方だけ直して食い違う事故が起きる
- **定義を要件書に残し辞書は生成物にする**: 手保守が消えるが、散在した Shall 文から定義を機械抽出するのは現実的でなく、生成の仕組みが先に必要になる

## 影響

- `00_requirements/rules/ai-asset-design-docs.md` / `design-docs.md` の「用語辞書」節（案内役 → 定義の正へ書き換え）
- `90_glossary/` の全ファイル（一言説明を定義に格上げ、「定義元」を「正典」リンクへ変更）
- 成果物ルールのレビュー観点（書式・可読性の観点章に「収録語を文書内で定義し直していないか」を置ける）
