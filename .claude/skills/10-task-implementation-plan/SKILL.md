# 10-task-implementation-plan — 検証できる単位にステップを割る

共通手順の禁止事項（計画書・チケット・`wip/tmp/` 以外に書き込まない、全体計画書と受け入れ条件を書き換えない、次の計画チケットを推測で作らない、計画書に結果や経過を書かない）に加えて、ソースコード・テストコードを書き始めない（実装は実装チケット）。設計文書を書き換えない（不備は設計差し戻しの提案として結果報告へ）。設計に無い機能・仕様に無い振る舞いをステップに入れない（別 issue 候補として結果報告へ）。**検証手段（テスト ID）の無いステップを起こさない**。

## 目的

仕様書のテストシナリオを軸に、1 ステップ = 1 テスト ID で合否が決まる形に実装を割り、許可範囲を必要最小限で提案する。

- 要件: `.claude/docs/00_requirement/skills/10-task-implementation-plan.md`
- 仕様（正。固有手順・OUT ひな形）: `.claude/docs/10_spec/skills/10-task-implementation-plan.md`
- 処理の共通手順（正）: `10-task-investigation-plan` の「計画タスクの共通手順（正）」

## 手順

共通手順（着手 → 入力の確認 → 計画書 → 実施チケット群 → 次の計画チケット → 完了 → 結果報告）は `10-task-investigation-plan` に従う。ここでは固有部分だけを示す。

- 設計書のテストシナリオに**テスト ID が無い**（または受け入れ条件に対応するシナリオが無い）ときは、実装チケットを起こさない。不足を根拠付きで結果報告に書き、設計（`design`）の追加チケットを起こす提案を返す。計画書は「設計差し戻し待ち」として残す
- ステップは**検証可能な単位**（1 ステップ = 対応するテスト ID で合否が決まる）に分け、依存順に並べる。1 チケット = 1〜2 ステップ
- **実装チケットの DoD の型**: 「{{対象}} が仕様書 {{節}} のとおりに動く」「テスト {{ID}} が失敗ケース（境界値・異常系）を含めて通る（実行方法: {{コマンド}}）」「既存のテストが通る」「仕様からの逸脱があれば作業ログに記録されている」
- **許可範囲案**（やってよいこと）はステップごとに書く場所（ディレクトリ・ファイル）を挙げ、必要最小限にする。テスト・ビルドの実行コマンドも含める
- テスト方針は TDD（テスト先行 → 失敗確認 → 実装）を既定とし、既存のテスト構成・コマンドに合わせる。`CLAUDE.md` の規約（可読性・単一責任・マジックナンバー禁止など）は参照するだけで再掲しない
- 人間レビュー要否の既定（方針が無い場合）: 実装計画チケットは「要」、実装チケットは `.claude/rules/work-defaults.md` に従う
- **見てほしい点の固定項目**: ステップ分割の妥当性（検証可能単位か・依存順か）/ テスト ID とステップの対応の網羅 / 許可範囲案の広さ / 設計不備の指摘の妥当性（該当時）

## OUT ひな形

`assets/implementation-plan.template.md`（共通の型は `20-common-step-report-view` の `assets/plan.template.md`）。

| 節 | 内容 |
|----|------|
| 対象 | issue・MR・根拠とする設計書 |
| 変更対象 | 追加・変更するファイルとその理由（仕様書の節） |
| 許可範囲案 | ステップごとの書き込み先・実行コマンド |
| テスト方針 | TDD の進め方、テスト ID × ステップの対応表、実行方法 |
| ステップ | 順序・依存・チケット |
| 検証方法 | 全ステップ完了時の確認（既存テスト含む） |
| リスク | 影響範囲・巻き戻し方 |
| 保留した点 / 対象なし / 設計差し戻し | 該当時 |

## エラー時の対処

| 状況 | 対処 |
|------|------|
| 設計書にテスト ID が無い | 実装チケットを起こさない。不足を結果報告に書き、設計の追加チケットを提案する |
| 設計に無い機能が要ると分かった | ステップに入れない。別 issue 候補として結果報告に書く |
| 設計文書の不備を直したくなった | 直さない。差し戻しの提案として結果報告へ |
| 許可範囲が広くなりすぎる | ステップを割り直して狭める。広いままなら理由を計画書に書き、見てほしい点に載せる |
| 共通手順で止まった（TK002 / TK005 / RV00x） | `10-task-investigation-plan` の「エラー時の対処」に従う |
