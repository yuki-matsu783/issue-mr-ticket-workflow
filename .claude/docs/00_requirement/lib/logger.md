# 共通 logger

## 概要

スキルのスクリプト（`scripts/*.sh`）とフック（`.claude/hooks/**/*.sh`）が共通で使う logger の要件を定義する。実行の記録を `logs/` 配下に残し、拒否・失敗・判定の追跡と振り返りに使えるようにする。

- **背景**: スクリプト・フックが各自の方式でログを書く（または書かない）と、拒否や失敗の原因調査で「何がいつ実行され、どこで止まったか」を辿れない。またフックは標準出力が応答チャネルのため、ログの出し方を誤ると機構自体を壊す。
- **目的**: すべてのスクリプト・フックが同じ形式・同じ場所・同じレベル制御でログを残し、通常はノイズなく（INFO）、調査時は環境変数 1 つで詳細（DEBUG）が得られる状態を作る。
- **スコープ**:
  - 含む: ログの出力先・形式・レベル・レベル制御・自動付与する情報・失敗時の振る舞い
  - 含まない: 何をログに書くか（各スクリプト・フックの仕様）、`logs/` の他の記録（進行状態・判定記録。機構の要件）、ログの閲覧・集計の仕組み

---

## ユーザーストーリー

**[As a]** 機構を保守する開発者として、

**[I want]** どのスクリプト・フックの実行も同じ形式のログで `logs/` に残り、必要なときだけ環境変数でデバッグ詳細を出したい。

**[So that]** 拒否・失敗・想定外の挙動の原因を、再現実験なしにログから特定できるため。

---

## 受け入れ基準（Acceptance Criteria）

### メインフロー

- When スクリプト・フックがログを書くとき、Shall 共通 logger を経由して `logs/` 配下に書き、各自の独自方式でログファイルを作ってはならない。
- When ログの行が書かれるとき、Shall タイムスタンプ・レベル・出どころ（スクリプト名）が logger によって自動で付与され、書き手が毎回指定してはならない。
- When レベルを指定せずに実行されたとき、Shall INFO 以上（INFO / WARN / ERROR）のログだけが出力されなければならない。
- When 環境変数でログレベルに DEBUG が指定されたとき、Shall DEBUG のログも出力されなければならない。

### 代替フロー

- If ログの出力先（`logs/`）が無い場合、Then logger はそれを作成して書き始めなければならない。

### 例外フロー

- If ログの書き込みに失敗した場合（権限・ディスク等）、Then logger は本体の処理を失敗させず、ログを黙って捨てなければならない（ログはあくまで補助。本体の動作を妨げない）。

### その他の細かい記述

- Shall not ログを標準出力・標準エラーに出してはならない（フックの応答チャネル・スクリプトの結果出力を汚さない）。
- Shall not ログに環境変数の値・トークン・クレデンシャル・個人情報を書いてはならない。
- When ログが `logs/` に置かれるとき、Shall コミットの対象外（`.gitignore`）であり、片付けの対象外であること（機構の記録と同じ扱い）。

---

## 前提条件

- `logs/` が `.gitignore` に含まれていること（機構の記録の要件で定義済み）
- スクリプト・フックが bash で書かれていること

---

## 制約条件

- **技術的制約**: bash から source して使える形で提供する
- **外部的制約**: ログの形式・出力先の詳細・レベルの値は仕様書が正

---

## 依存関係

- すべてのスキルのスクリプト・フック（利用者）
- `logs/` の規定（自己改善ワークフロー機構の要件・DDR i0001-28）

---

## 非機能要件

| 項目 | 説明 |
|------|------|
| 一貫性 | どのスクリプト・フックのログも同じ形式・同じレベル体系で読める |
| 安全性 | ログ機構の失敗が本体（コミット・push・フック判定）を止めない |
| 追跡性 | 行ごとに「いつ・どのレベルで・どこから」が機械的に読み取れる |
