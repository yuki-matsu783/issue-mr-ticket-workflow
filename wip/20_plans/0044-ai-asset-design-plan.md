# 0044 AI アセット設計の計画

## 対象

- 対象 issue: #15 https://github.com/yuki-matsu783/issue-mr-ticket-workflow/issues/15
- PR: #36 https://github.com/yuki-matsu783/issue-mr-ticket-workflow/pull/36
- 前提となる調査: `wip/30_reports/0046-investigation.md`（A 系）と `wip/30_reports/0043-investigation.md`（B 系）

## この計画で決めること

調査の結論は出そろっている。設計フェーズでやるのは「決定として正史に書き残す」ことだけで、新しい判断材料は要らない。

| 調査の結論 | 出どころ |
|---|---|
| `shlex` に置き換えると判定誤りが 7 件入る（見落とし 6・誤検知 1） | 0046 の A-3 |
| 置き換わるのは 429 行のうち正規化部 120 行程度 | 0046 の A-1 |
| ホットパスが 1 本 +20.7 ms、5 本で +103 ms 遅くなる | 0043 の B-1 |
| DDR i0009-22 が認める外部プロセスの予算（`jq` 1 回 = 3.85 ms）の 7.1 倍 | 0043 の B-1 |
| Python 不在の環境では検査が丸ごと落ちる。fail-open は塞げない | 0043 の B-2 |
| 解析そのものは `shlex` が 50 倍速い | 0043 の B-1 |
| 現行実装が `_` を返す入力（`git 'commit'`）を `shlex` は正しく解く | 0046 の A-3 |

## DDR の書き方

既存の DDR（`i0009-22`）の構成に合わせる: frontmatter（type / title / description / tags / keywords）→ 背景 → 決定 → 理由 → 却下した案 → 影響。

`i0015-01` の「却下した案」に置く 2 案と、それぞれに書く却下理由。

| 却下する案 | 却下理由（レポートの節） |
|---|---|
| 本番の `cmdpos.sh` を `shlex` に置き換える | 判定誤り 7 件（0046 A-3）／+103 ms（0043 B-1）／Python 不在時に検査が落ちる（0043 B-2）。どれか 1 つでも十分 |
| `shlex` をテストの照合役（差分テスト）として常設する | 照合役が信頼できない。`shlex` 側は「`shlex` + 自前の再実装」で、その再実装自体に 6 つの盲点がある（0046 A-2）。差分 23 件のうち 10 件は判定に影響しない表現差で、雑音比が高い。第 2 のパーサを保守する費用が、見つかる不具合（今回は既知の制約 1 件のみ）に見合わない |
