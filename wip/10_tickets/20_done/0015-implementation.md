### 仕様からの逸脱

1. **`FrontmatterDocument` に `body` を足した**。仕様「データの形」は `entries` だけを宣言しているが、仕様「処理フロー / チケットの解析」手順 5 の「**本文から**探す」を守るには終端の区切りの位置が要る。区切りの探索を `parseTicket` 側で重ねて書くより、既に切り出している `parseFrontmatter` が返すほうが二重実装にならない
2. **TB002 の文言に「（scalar でない）」を添える場合がある**。仕様の文言の型は `TB002: {キー名} が読み取れない` の 1 通りだが、キーが存在するのに形が違う場合は、欠落と区別が付かないと利用者が直せない
3. **コードフェンスの中の見出しを本文の見出しとして扱わない**。仕様手順 5 はフェンスに触れていない。作業ログにシェル片を貼るのは本ワークフローで日常的に起き、実際にレビューで踏んだため、仕様の意図（本文の見出し）に沿う側に倒した

上記 3 件はいずれも仕様書の追記が要る。書き込み許可が `src/**` と `wip/**` のため本チケットでは直せず、フィードバック計画（0012）へ送る。

### 判断と根拠

直さないと判断した指摘と理由:

- **M1（`RenderOptions.cspSource` が使われていない）**: 型を削るか仕様に「受け取るが使わない」と書くかの選択で、仕様書の変更が要る。書き込み許可の外なので 0012 へ送る。害は無い（未使用の引数が 1 つあるだけ）
- **M3（`workspaceFolders[0]` の変化に追随しない）**: 複数ルートやワークスペースの組み替えは要件・仕様が触れていない。挙動を決めるのは設計の仕事なので 0012 へ送る
- **M4（パネル由来の Disposable を `context.subscriptions` に積んでいない）**: 積むと開閉を繰り返すたびに配列が伸び続ける。`onDidDispose` で watcher を破棄しており、拡張ホストの終了時は VS Code 側が watcher を回収する。取り違えのリスクのほうが大きいと判断した
- **M5（YAML コメントを解釈しない）**: `ticket.sh` は値の後ろにコメントを書かない。解釈範囲を広げるのは DDR i0013-03 の「サブセットに限る」判断の変更にあたるため 0012 へ送る
- **M6（シンボリックリンク / `capabilities` の宣言）**: どちらも仕様に無い項目の追加で、`untrustedWorkspaces` の値は設計判断。0012 へ送る。読み取り専用でエディタに開くだけのため、当座の危険は小さい
- **M7・M8（`<meta name="viewport">` と「種類不明」「実行者不明」が仕様に無い）**: 実装が仕様より広い分は仕様の追記で埋めるべきで、実装から削ると表示が壊れる。0012 へ送る
- 一方、R1〜R5・M2・M9・M10 は「正しさ・追跡性・体感」に直接効き、いずれも `src/**` の変更だけで直せるため本チケットで直した

その他の判断:

- コードフェンスの検出は「行頭が ``` または ~~~ の 3 つ以上」でトグルする素朴な実装にした。開始と終了の記号や長さの一致までは見ない。チケットの作業ログで入れ子のフェンスを使う運びが無く、過剰な実装を避けたため
- 子のインデントは「最初に現れた子の幅」を基準にした。幅を 2 に固定すると `ticket.sh` 以外が書いたチケットで子を落としうるため
