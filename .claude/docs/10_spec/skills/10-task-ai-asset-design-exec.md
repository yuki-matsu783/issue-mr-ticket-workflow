# 10-task-ai-asset-design-exec スキル 仕様

## 概要・禁止事項

AI アセット設計実施タスクの内部仕様。対応する要件は [00_requirement/skills/10-task-ai-asset-design-exec.md](../../00_requirement/skills/10-task-ai-asset-design-exec.md)。処理フローの共通手順は `10_spec/skills/10-task-investigation-exec.md`「実施タスクの共通手順（正）」に従い、ここでは固有部分だけを書く。

禁止事項（共通手順の禁止事項に加えて）:

- アセット本体（`.claude/skills/`・`hooks/`・`rules/`・`agents/`・`settings.json`）への書き込み（書きたい内容は仕様書へ。実装は AI アセット実装フェーズ）
- 要件定義書への内部構造（スクリプト名・判定順・スキーマ）の記載（仕様書へ）
- 1:1:1 を崩す文書、正史への経緯の記載（経緯は DDR）
- テスト観点を機械テストか eval か区別せずに書くこと
- 設計計画書・調査結果レポートの書き換え

## 呼出条件

- `next` が AI アセット設計チケットを示したとき、全体計画で合意した実行者（サブエージェント）で読み込まれる

## IN / OUT

| IN | OUT |
|----|----|
| AI アセット設計計画書（文書一覧・骨子・横断整合・ヘッドレス方針）、調査結果レポート、既存の `.claude/docs/` | `.claude/docs/00_requirement/`・`10_spec/` の要件定義書・仕様書（新規 / 更新）、DDR、更新した横断文書・用語辞書、AI アセット設計結果レポート（md + HTML）、完了済みチケット群、結果報告 |

## IN / OUT サンプル

- 仕様書のテスト観点: 「WD-T06（機械テスト）: `wip/tmp/` 配下の書き込みは許可範囲外でも WF201 にならない」「AS-E01（eval）: 実装計画スキルが許可範囲案を最小にする（サブエージェント実行のログ評価）」
- 結果報告の見てほしい点: 「要件が外部視点（EARS）で書かれ内部構造が仕様へ分かれているか / テスト観点の ID と機械 / eval の区別 / ヘッドレス挙動の記載 / 横断文書・用語辞書との整合」

## 処理フロー

共通手順に加えて（3 の実施）:

- 書き方の正は `20-common-step-requirement`（要件: 外部視点・EARS・メイン → 代替 → 例外 → 細部）・`20-common-step-spec`（仕様: アセット種別ごとの節構成・テスト観点）・`20-common-step-ai-asset-creator`（置き場・命名・1:1:1）
- 要件定義書: 受け入れ条件を EARS の受け入れ基準に落とし、**ヘッドレス実行での帰結**を代替フローに書く
- 仕様書: 内部の挙動（判定順・入出力・エラー識別子・回復手順）と**テスト観点**を書き、テスト ID を振る。各観点に**機械テスト**（決定論的に検査できる）か **eval**（モデルの振る舞いをログ等で評価する）かを明記する。エラー識別子は既存の採番規則に従う
- 決定は根拠付きで正史に書き、採らなかった案と理由を DDR（`i<issue>-NN`）に残す。既存文書の更新は本文をその時点の正史に書き換える
- 計画書の横断整合に挙がった横断文書・用語辞書を更新する（用語の追加は別名も含めて辞書へ）
- 書き終えたらプレースホルダ 0 件・frontmatter（`type: requirement` / `spec`）・要件と仕様の相互参照・用語の整合を確認する
- 見てほしい点の固定項目: 外部視点と内部構造の分離 / テスト ID と機械・eval の区別 / ヘッドレス挙動 / 横断文書・用語辞書との整合

## OUT ひな形

AI アセット設計結果レポート（report-view のレポートテンプレート）に次を含める: 作成・更新した要件定義書・仕様書・DDR・横断文書の一覧（アセットとの 1:1:1 対応）/ 決定と根拠の要約 / 受け入れ条件 × テスト ID（機械 / eval）の対応表 / ヘッドレス挙動の一覧 / 想定と異なった点 / 残課題。
