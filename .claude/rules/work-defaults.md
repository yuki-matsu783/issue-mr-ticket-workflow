# work-defaults — タスク種別ごとの既定判断基準

全体計画タスクは、この表を基準に各チケットの実行者・人間レビュー要否・敵対的レビュー要否を提案する。issue の性質に応じた調整は「基準との差分」として理由付きで提案する（基準どおりの行は「基準どおり」と書けばよい）。基準は提案の既定であって強制ではなく、issue ごとの最終決定は全体計画でユーザーと合意する。

- タスクの種類の名称と担当（メインエージェント / サブエージェント）の正は `10_spec/skills/00-workflow-issue-mr-driven.md`「タスクの構成」（実体は `.claude/hooks/config/task-types.tsv`）。別名を作らない
- 既定の実行者は「サブエージェント（モデル名）」か「メインエージェント」のどちらかで書く。メインエージェント担当の 3 種はサブエージェント起動時のモデル検査の比較対象にしない
- 見直しの材料は、チケットに機械的に記録された着手・完了の時刻（`started_at` / `completed_at`）と作業ログ。見直しの結果はこの表の編集として反映する
- このファイルが無いプロジェクトでは、全体計画はスキルの既定（リスクの高いタスクは人間レビュー要）を使い、基準が無かった旨を全体計画書に書く

## 既定値

| type | 既定の実行者 | 人間レビュー | 敵対的レビュー | 理由 | 調整してよい条件 |
|---|---|---|---|---|---|
| overall-plan | メインエージェント | 要 | 不要 | フェーズ列・実行者・やってよいことの合意は人間が行う | なし（常に要） |
| investigation-plan | サブエージェント（opus） | 不要 | 不要 | 計画書は調査結果と一緒に見れば足りる | 問いが issue の受け入れ条件を超えて広がるなら要 |
| investigation | サブエージェント（sonnet） | 要 | 不要 | 結論が後続の計画を左右する | 読むだけの小さな調査（1 観点・1 チケット）は不要に下げてよい |
| design-plan | サブエージェント（opus） | 不要 | 不要 | 計画書は設計結果と一緒に見れば足りる | 対象なしの見込みなら省略してよい |
| design | サブエージェント（opus） | 要 | 要 | 正史（要件・仕様）の変更 | 差分が 1 文書・50 行未満なら敵対的レビューを省略してよい |
| implementation-plan | サブエージェント（opus） | 要 | 不要 | 許可範囲とロックアウト対策を実装前に見る | 中核（フック・settings.json）を含まなければ不要に下げてよい |
| implementation | サブエージェント（sonnet） | 要 | 要 | 振る舞いが変わる | 機械テストが全通過なら人間レビューを「approve のみ」に軽くしてよい |
| feedback-plan | メインエージェント | 要 | 不要 | 後続フェーズの要否は人間の判断 | なし |
| design-feedback-plan | サブエージェント（opus） | 不要 | 不要 | 計画書は反映結果と一緒に見れば足りる | 反映対象が複数文書にまたがるなら要 |
| design-feedback | サブエージェント（opus） | 要 | 要 | 正史（要件・仕様）の変更 | 差分が 1 文書・50 行未満なら敵対的レビューを省略してよい |
| ai-asset-design-plan | サブエージェント（opus） | 不要 | 不要 | 計画書は設計結果と一緒に見れば足りる | 対象なしの見込みなら省略してよい |
| ai-asset-design | サブエージェント（opus） | 要 | 要 | 正史（`.claude/docs/`）の変更 | 差分が 1 文書・50 行未満なら敵対的レビューを省略してよい |
| ai-asset-implementation-plan | サブエージェント（opus） | 要 | 不要 | 許可範囲とロックアウト対策を実装前に見る | 中核（フック・settings.json）を含まなければ不要に下げてよい |
| ai-asset-implementation | サブエージェント（opus） | 要 | 要 | 中核の変更は機構自身を止め得る | 中核を含まず機械テストが全通過なら実行者を sonnet に、人間レビューを「approve のみ」に軽くしてよい |
| overall-summary | メインエージェント | 要（最終確認） | 不要 | 片付け・draft 解除の前の最終確認 | なし |

## 調整の書き方（全体計画書「方針」）

- 基準どおりの種類は「基準どおり」と書く
- 基準から外す種類は、行ごとに「何を（実行者 / 人間レビュー / 敵対的レビュー）・どちらへ・なぜ」を 1〜2 行で書く。上の「調整してよい条件」に当たる場合はその条件を引用する
- 提供コマンドが未完成でサブエージェントに状態遷移を任せられない等、プロジェクトの一時的な事情で全種類を一律に変える場合も、差分として明示する
