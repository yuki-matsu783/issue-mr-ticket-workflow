# 10-task-design-feedback-plan スキル 仕様

## 概要・禁止事項

設計反映計画タスクの内部仕様。対応する要件は [00_requirement/skills/10-task-design-feedback-plan.md](../../00_requirement/skills/10-task-design-feedback-plan.md)。処理フローの共通手順は `10_spec/skills/10-task-investigation-plan.md`「計画タスクの共通手順（正）」に従い、ここでは固有部分だけを書く。

禁止事項（共通手順の禁止事項に加えて）:

- 設計書・コードの書き換え（突き合わせは読み取りだけ。書き戻しは設計反映チケット、実装の追加は別途）
- 実装漏れを「設計書を実装に合わせる」ことで解消する計画（設計書は正のまま、実装追加を提案）
- 別 issue 候補（受け入れ条件外の変更）をチケット化すること
- 差分の判断を保留したまま分類済みとして扱うこと（保留は「保留した点」へ）

## 呼出条件

- `next` が設計反映計画チケットを示したとき、全体計画で合意した実行者（サブエージェント）で読み込まれる

## IN / OUT

| IN | OUT |
|----|----|
| 設計書（要件定義書・仕様書・DDR）、実装結果レポート（逸脱一覧・計画外の変更）、ソースコードとテスト（読むだけ）、issue の受け入れ条件 | 設計反映計画書（`wip/20_plans/`、md + HTML）、設計反映チケット群、次の計画チケット 1 枚、結果報告 |

## IN / OUT サンプル

- 差分一覧の行: 「仕様書 §4 エラーメッセージ | 実装: UI 文言集の文言 | 分類: 設計書が古い | 方針: §4 を書き戻し、経緯を DDR」「仕様書 §5 ロック回数 | 実装: 未実装 | 分類: 実装漏れ | 方針: 書き戻さず実装追加を提案」
- 結果報告の見てほしい点: 「分類の妥当性（特に実装漏れと設計書が古いの線引き）/ 書き戻し方針が実装の実態と合っているか / 実装漏れの扱い（受け入れ条件との関係）/ 次の計画チケット」

## 処理フロー

共通手順に加えて:

- 計画書の**差分一覧**は、実装結果レポートの逸脱一覧・計画外の変更を起点に、設計書の節とコード・テストを読み取りだけで突き合わせて作る。行ごとに次の 4 分類のどれかを付ける
  - **一致**: 対応不要
  - **設計書が古い**: 実装が正しく設計書が追いついていない → 書き戻す（経緯は DDR）
  - **実装漏れ**: 設計書が正しく実装が足りない → 書き戻さず、実装の追加を結果報告で提案する（受け入れ条件に関わるなら実装の追加チケットの提案、そうでなければ残課題）
  - **設計に無い決定**: 実装中に決めたことが設計書に無い → 設計書に追記し、経緯を DDR に残す
- 1 チケット = 関連する設計書のまとまり（機能単位）。設計反映チケットの DoD の型: 「差分一覧の {{行}} が設計書 {{節}} に反映され、行が『一致』に消し込まれている」「経緯が DDR に残っている」「テスト ID が実装のテストと対応している」
- 差分が 0 件（すべて一致）なら「対象なし」として次の計画チケット（全体まとめ）だけを作る
- 人間レビュー要否の既定（方針が無い場合）: 設計反映計画チケット「要」
- 見てほしい点の固定項目: 分類の妥当性 / 書き戻し方針と実装の実態の整合 / 実装漏れの扱い / 次の計画チケット

## OUT ひな形

`assets/design-feedback-plan.template.md`:

| 節 | 内容 |
|----|------|
| 対象 | issue・MR・突き合わせた設計書とレポート |
| 差分一覧 | 設計書の節 × 実装の実態 × 分類 × 方針（表） |
| 書き戻し方針 | 設計書ごとの直し方・DDR の要否 |
| 実装漏れ一覧 | 提案（実装追加チケット / 残課題 / 別 issue 候補） |
| 受け入れ条件の確認 | 条件ごとに設計書と実装の双方で満たされているか |
| 設計反映チケット | まとまりごとのチケットと依存 |
| 保留した点 / 対象なし | 該当時 |

## テスト観点（eval）

| eval ID | 入力（プロンプトと状況） | 期待する振る舞い | 判定方法 |
|---------|------------------------|-----------------|---------|
| DFP-E01 | 実装で判明した仕様との食い違いが 5 件ある | 書き戻す文書と箇所を一覧にし、食い違いごとにどちらを正とするかを計画の段階で決める | 計画書の一覧と、正の決定の記載 |
| DFP-E02 | 書き戻す対象が無いと分かった | 「対象なし」と根拠を書き、設計反映チケットを起こさず次の計画チケットだけを作る | 起票したチケットの枚数 |
| DFP-E03 | 実装が仕様より正しいと判断する場面 | 実装を正とする理由を書き、仕様側を直す方針を計画書に残す。実装を仕様に合わせて壊さない | 計画書の理由の記載 |
