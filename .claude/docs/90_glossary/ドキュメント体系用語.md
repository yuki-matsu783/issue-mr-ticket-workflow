# ドキュメント体系用語

### 正史

その時点で有効な要件・仕様の記述。requirements / spec は正史だけを持ち、検討の経緯・却下案・過去の版は [DDR](#ddr) と git の履歴が持つ。

### DDR

設計上の決定の記録（背景・決定・理由・却下案・影響）。issue 番号ベースの識別子で命名され、マージ後は本文を変えず frontmatter の状態だけで無効化を表す。

### 用語辞書

機構固有語の定義（意味・目的・他の用語との関係）の正を集約した文書群。振る舞いの正は requirements / spec が持ち、各文書は収録語を定義し直さず初出でここへリンクする。参照の向きは常に設計書 → 辞書。

### 横断文書

特定のアセットに紐づかない要件・仕様の文書。要件・仕様それぞれの置き場の直下に置かれ、アセットに紐づく文書はアセットの種類ごとのサブディレクトリに置かれる。

### 成果物ルール

`.claude/rules/` のルールの 2 分類の一方。リポジトリに残りレビュー対象になる成果物の書き方を定め、[章スキーマ](#章スキーマ)に従い、観点別レビューの抽出対象になる。

### 行動ルール

`.claude/rules/` のルールの 2 分類のもう一方。作業の進め方・その場限りの操作の規約を定める。章スキーマの対象外で、観点別抽出の対象にならない。

### 章スキーマ

[成果物ルール](#成果物ルール)が持つ固定 7 章（適用範囲 / 構造・配置 / 書式・可読性 / セキュリティ / 堅牢性 / パフォーマンス / テスト・機械的検査）の構成の型。見出し文言と順序が全ルールで揃う。

### 観点章

[章スキーマ](#章スキーマ)のうちレビュー観点に対応する個々の章。観点別レビューエージェントは、対象ファイルに効く全ルールから担当の観点章だけを抽出して横並びレビューの入力にする。

### レポート

実施タスクと[全体まとめ](./ワークフロー用語.md#全体まとめ)の結果を書く Markdown 文書。同じ名前の [HTML ビュー](#html-ビュー)が併存し、Markdown が正文。[作業領域](./ワークフロー用語.md#作業領域)に置かれる。

### 計画書

「これから何をするか」だけを書く文書。実施した結果は[レポート](#レポート)に分離される。全体計画書と各計画タスクの計画書がある。

### HTML ビュー

レポート・計画書の視覚化。[テンプレート](#テンプレート)のコピーと Edit で作られ、ネットワーク接続なしで表示でき、ライト / ダーク両テーマで読める自己完結の HTML。全体計画書には作らない。

### テンプレート

コピーして使う雛形ファイル。`<名前>.template.md` / `.template.html` / `.template.sh` の命名で機械的に判別され、完成形として正しい frontmatter `type` を含む。
